## 阅读前置卡

### 一句话核心
这篇文章提供了一套针对 MLO（MyLifeOrganized）的顶层大纲分流原则与 TODO/大纲/日历三通道分工方法，核心目标是解决任务管理工具中 TODO 列表膨胀和冗余紊乱的问题。

### 核心洞见
- 顶层大纲按“主干任务 / 分支任务 / 临时任务 / 循环任务 / 也许/将来”五大块划分，其中主干与分支不是父子包含关系，而是按核心程度划分的并列区域。
- 核心原则是“被催促、有时限 → TODO；被看见、无时限 → 大纲；固定时间块 → 日历”，三类通道各司其职，避免 TODO 被污染。
- 大量任务其实不需要进入 TODO，只要在大纲中可见即可管理；默认全部进入 TODO 是冗余熵增的根源。
- 临时任务应阶段性处理、处理完即归档或转移，不应长期混入主干，以保护主线判断的清晰度。
- 固定周内重复事项（如作息、固定学习时段）应放日历而非 MLO，避免工具内重复制造待办。

在一个大纲没有很好的分流，也会造成这种紊乱的问题，这篇文试图解决。TODO 的膨胀问题和大纲，的分流问题。

## MLO 大纲顶层结构原则

-   顶层建议分为五大块：

-   主干任务
-   分支任务
-   临时任务
-   循环任务
-   也许/将来

-   这里的“主干任务”和“分支任务”不是父子包含关系，而是按核心程度划分的并列区域。

### 主干任务

-   当前人生/事业最核心、最能改变命运曲线的任务。

### 分支任务

-   非核心但仍有价值、需要阶段性推进或保留的任务。

### 临时任务

-   临时出现、阶段性处理、处理完即可归档、删除，或转入主干/分支。
-   不应长期混入主干，避免干扰主线判断。
-   可以是对主干、分支的临时细分辅助。

### 循环任务

-   这部分一般都是需要到期时显示在TODO中的
-   周期性维护事项。
-   例如：缴费、家庭事务、数据备份维护。
-   主要依赖开始日期、提醒、循环规则，到期再出现。

### 也许/将来

-   当前不承诺执行，但未来可能考虑的事项。
-   只在周回顾/月回顾中查看，不进入日常 TODO。

## MLO / TODO / 日历分流原则

-   🔴 无时限催促的场景任务用大纲管理+页签就很好，你会发现其实很多任务都用不到 TODO去管理，这节是一个很重要的技巧，如果全都默认进入TODO会对TODO产生很严重的冗余熵增问题，所以我总结了以下的原则，和具体的办法。
-   `TODO` 只放需要被催促、需要完成确认的行动；`大纲`放需要被看见但无需完成的方向（这部分对 TODO 隐藏）；`日历`放固定发生的时间块（一般不进入 MLO）。

### 【被催促，有时限】→ 进入 TODO

-   比如

-   需要到期提醒
-   需要完成确认
-   需要打勾闭环
-   定时完成的任务
-   循环完成的任务

-   如果不显示在 TODO 中，容易忘记或延误的任务

### 【被看见，无时限】→ 大纲 + 页签 / 视图管理

-   比如

-   方向
-   提示
-   长期计划
-   当前学习对象
-   日历的辅助项目

-   不需要完成、只是需要保留和定期看到的事项
-   这类项目一般不进入 TODO，否则会污染当前行动列表（TODO）使TODO过分的杂乱膨胀。

### 【周内固定日历事项】→ 放日历，一般不进 MLO

-   固定周内重复的内容，不要放入MLO，更应该放入日历，这样不会导致MLO异常的杂乱膨胀。
-   比如

-   睡觉
-   起床洗漱
-   工作时间段
-   固定英语学习时段
-   固定散步时段
-   固定吃饭 / 休息

-   这些主要由日历负责触发，不需要在 MLO 里重复制造待办。
-   但如果固定日程下有具体行动、检查清单或复盘任务，可以在 MLO 中单独管理具体行动。
