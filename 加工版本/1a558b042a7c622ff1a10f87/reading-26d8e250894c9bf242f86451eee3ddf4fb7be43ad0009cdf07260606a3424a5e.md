## 正文

很少有哪种技能像 coding 这样让人望而却步。电视里的描绘让 writing computer code 看起来像是天才才能从事的活动：古怪的 symbols 在屏幕上飞速掠过，背景里 techno music 震耳欲聋。

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/coding-perception-vs-reality.png)

但事实是，coding 其实相当容易。

我这么说，并不是要贬低才华横溢的 programmers 的工作。一项技能完全可能既容易掌握 basics，又很难精通。人人都学习写作，但很少有人学会写好。因此，说 basic literacy 是一项“容易”获得的技能（因为我们绝大多数人都能做到），与肯定优秀作家的努力并不矛盾。

我这么说，也不是要嘲笑那些正在努力学习 programming、却感到沮丧的人。

恰恰相反，我说 coding 容易，是因为我相信，几乎所有人，即使不觉得自己特别聪明，也有能力学会 write simple programs。他们没有学会，主要是因为一些 structural barriers，而不是这项技能本身有什么 intrinsic difficulty。

## 我的 Coding 经历

收听本文

我 writing programs 的时间已经超过了自己人生的一半。我上过几门大学课程，甚至完整学过[在线 CS degree 的 content](https://www.scotthyoung.com/blog/myprojects/mit-challenge-2/)（顺便说一句，如果你想学 code，这完全没有必要）。

从某些方面看，我的背景似乎让我没有资格谈论 coding 有多容易。不过，我可以毫不犹豫地说，engineering、accounting、physics 和 law 这些学科都比 programming 更难。你在高中学的大部分 math 也更难，只不过你通常在 algebra 上得到的 practice 比 code 多得多得多，这往往会让人误判哪一个更难。

## 为什么 Coding 让人觉得难

学习 code 很难，有这么几个原因：

1.  **Installing 新的 languages 特别令人沮丧**。这是一个准 programmer 要做的第一件事，而且直到今天，它依然是 programming 中最让我讨厌的事。这会让人误以为 programming 真的很难，因为新手会把 getting set up 的困难 extrapolate 到之后的每一刻。
2.  **languages、tools、libraries 和 plug-ins 实在太多太多了。** 刚开始 programming 时，人很容易不知所措，因为要学的东西有一大堆，而你根本不知道从哪里开始。
3.  **入门 classes 里往往有很多之前已经自学过 programming 的人。** 因此，不公平的比较可能让你觉得自己不够聪明，做不了 program。（我曾认识一位取得 civil engineering 硕士学位的女性，这比 intro coding 难得多，但她告诉我，第一堂课让她觉得自己不够聪明，学不了 code。这简直_荒唐_，可人们就是会信以为真，因为某个痴迷技术的孩子在开课前就已经有了差不多十年的经验。）

programming 刚开始的那段时间最难。Getting set up 难得令人恼火，而且往往在你 write 哪怕一 line 的 code 之前，就要求你学习一种与 computers 打交道的新方式。

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/difficulty-of-coding.png)

想想 installing 大多数 languages 的 instructions。Open 那个 terminal 或 command prompt。Type in 一组 case-sensitive、exact 的 instructions，来 download 并 install 那个 language。Use GitHub。还有 Homebrew。Versions 也很重要。你 running 的是 32 还是 64 bit？因为如果你不确定，它就会 crash，给出一条 cryptic error message，让你觉得自己像个白痴。

这些 tools 和其他东西一样，都能学会，但它们强化了电视给人的印象：coding 主要就是 using 晦涩难懂的 tools，而这些 tools 有着古怪、不友好的 user interfaces。人们看到 coding，就会想象自己在 parsing《黑客帝国》中绿色流动的字母；但实际情况更像是照着食谱一步一步做。

## 你怎样才能渡过最初的困难？

有几种办法可以做到。我最喜欢的办法，就是买一本书，明确告诉你如何一步一步 set up 一个 language。书店里的大多数此类书都会教你 installation process，只要你能一丝不苟地照着做，通常就能成功。

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/oreilly.png)

或者，你也可以一头扎进 internet tutorials，但要意识到，它们有时面向的是已经熟练的 programmers：这些人知道 Homebrew 和 GitHub 是什么，也能熟练地往 Terminal 里 writing commands。如果你碰到这样的 tutorial，可以试着跟着做，但如果搞砸了，也别难过。这确实令人沮丧，但并不意味着所有 coding 都会如此。

另一个选择是完全避开 setup。直接使用某个 coding tutorial website，它们无需任何 installation 就能教你 code。我也喜欢这种方式，但有时你没法用这些 apps 真正 build 出你想 build 的东西。不过，如果你讨厌 setup，我会建议从这里开始。

不过，最重要的是记住我告诉你的这一点。当你尝试学习 code 时，get set up 会让人沮丧，接受这只是需要付出的一点小代价就好。很快，一切就会容易起来，你也能做出很酷的东西。别因为卡在这里就觉得自己笨，我也仍然会卡住，而我 writing code 已经很多年了。

## 你应该从什么 Language/Tool 开始？

这看起来是个值得问的好问题，但我认为，实际上这是思考如何学习 programming 的错误方式。

首先，尽管 programmers 经常吹嘘自己懂多少种 languages，你还是要认识到，大多数 languages 只是 superficially different。是的，language design 那些事我都知道，所以别跟我讲 scripting 与 compiling 相比有什么重要性，也别跟我讲一个 language 是 strongly 还是 weakly typed。这些确实重要，但它们都是 details。

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/programming-similarity.png)

几乎所有 languages 和 tools 的 basics 都是一样的。Variables。Loops。Functions。Pointers。Stack。Trees。Hashing。Recursion。这些 concepts 在大多数 languages 中都 exist。如果你选择一个 mainstream language，你学习这些内容的方式大体相同，所以选择 Ruby、Python、C++、Java 还是 PHP 并不重要。

languages _确实_重要的地方，在于你想用它们来_做什么_。想 write iPhone apps？Swift 或 Objective C 是首选的 languages。需要 create web pages？JavaScript 会派上用场。没错，只要你愿意 tinker，并找到合适的 plug-ins，几乎任何 language 都能用于任何 task。不过，要着手某些 types 的 projects，有些 languages 会比另一些更容易。

因此，首先要问的不是：我应该学哪种 language，而是：我应该从哪个 project 开始？

## 你的第一个 Project 应该是什么？

我建议，在开始你的 programming 之旅时，甚至在你 write 哪怕一行 code 之前，就先决定一个你想 create 的具体 programming project。

这样做有几个目的：

1.  **它会大大缩小 language/tool 的选择范围**。一旦你知道自己要 building 一个 website，你就已经倾向于那些为这个目标而 designed 的 tools 了。
2.  **你学到的一切都与一个目的地相连**。正如我[在书中详尽说明的](https://www.scotthyoung.com/blog/ultralearning/)，transfer of learning 是出了名地困难。直接学习，比学了某些东西后只是希望它将来能帮上忙更有效。
3.  **你可以做自己觉得很酷的东西**。如果你觉得 make 一个 interactive website 很酷，那就去做。如果你更喜欢 game，那就去做。如果你更想 automate 自己的 accounting work，让自己只用同事一半的时间就能完成，那就改做这个。做自己觉得很酷的事情，你就会有动力坚持下去。

一般来说，projects 越小越好。决定从 making 下一个 Google 开始很有雄心，但很可能在你取得多少进展之前，就让你陷入细枝末节、难以前行。

如果你真正的抱负很大，通常最好先做一个 toy project。许多 experienced programmers 在进入 programming 的新领域时，仍然会这样做。Toy projects 采用 programming 的 essential ideas，却把它变成你几天或几周就能完成的东西，而不是需要几年。

好的 projects 的 Examples 包括：

-   **一个 basic text-adventure game。**不需要 graphics，但仍然需要学习 loops、variables、input-output processing 等 concepts。
-   **一个 simple website。**先从仅仅 displaying 一个 static page 开始。随着你学得更多，也许可以 add in comments、users、photos 或 interactive elements。
-   **一个 simple app。**你希望自己的手机上有什么极其简单的东西？刚开始时它可以很傻，不必担心。
-   **一个用于 automating 某项烦琐 task 的 script。**

一般来说，不涉及 multimedia content 的 programs 更容易（websites 算是个小小的例外），所以，例如你正在 making 一个 game，那么 text game 往往比带有 graphics 的 game 更容易，哪怕仅仅是因为 making 所有 graphics 也需要时间。

同样，不同的 core activities 有不同的难度。反复进行的 Arithmetic 和 simple calculations 最容易。为 exact patterns 而进行的 Processing text 稍难一些。为 vague patterns 而进行的 Processing text 则更难。Processing、speech、photos 和 video 就更难了。

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/difficult-programs-to-make.png)

如果你最终选择的第一个 project 事实证明特别困难，缩小规模也没关系。“Make 一个 calculates 我的 mortgage payments 的 application”比“Make 一个能从 photo 中告诉你某人发型是什么的 application”容易得多得多。刚开始时，这种差别往往并不明显，所以，如果你不小心选了一个“难”的 problem 作为起点，不必担心，之后可以把它调整得更容易一些。

## 你应该使用哪些 Resources？

一旦选定了 project，下一步就是找一些 resources 来帮忙。许多人会为这一步无休止地纠结，但和 language 的选择一样，它远没有你想象的那么重要（而且更多地取决于你的目标）。

我不会列举具体的 resources，因为好的 resources 太多，我的建议难免遗漏其中一些最好的。相反，下面是寻找好 resources 的三个策略：

1.  **找一本教授你所需的 language + project 的书**。你当地的书店或图书馆应该有 computer 专区，你可以直接从中任选一本。我喜欢 [O’Reilly](http://shop.oreilly.com/)，但好书还有很多。（如果你还没确定用哪种 language，就 Google 一下你的 project 类型，找找建议。）
2.  **参加一门 MOOC**。[Coursera](https://www.coursera.org/learn/python?)、[edX](https://www.edx.org/learn/computer-programming)、[MIT](https://ocw.mit.edu/courses/electrical-engineering-and-computer-science/6-00sc-introduction-to-computer-science-and-programming-spring-2011/)、[Harvard](https://online-learning.harvard.edu/course/cs50-introduction-computer-science)、[Stanford](https://online.stanford.edu/courses) 等都在网上教授 computer programming。再强调一次，最重要的不是具体哪门课，而是它是否教授你关心的 language/project domain。
3.  **学习一个 tutorial program/website**。同样，这类资源有很多。我第一次想学 Python 时，用的是 [Google 的 Python 教程](https://developers.google.com/edu/python/)。

为挑选哪本书或哪门课而焦虑，实在是操错了心。最主要的是利用书或课程，学到足以开始在你的 project 上 tinkering 的知识，而不是单独去 master programming。在尚未准备好时就开始自己的 project——你完全应该带着这样的感觉去做。

## 像真正的 Programmers 那样做，去 Ask Google

一旦真正开始 writing code，你就会遇到很多很多这样的情况：你要么不知道某件事该怎么做，要么以前学过，却已经忘了。

在这些情况下，你应该像真正的 programmers 那样做：**去 ask Google**。这并不丢人，而是真正的 programming 的一部分。我已经 coding 多年，却总会忘记一些琐碎的 syntactical 东西，所以我发现自己一遍又一遍地 googling regular expressions。这没什么不好，它只是这个过程的一部分。

一旦你完成了 installation，通过书本学了一些内容、了解了 basics，并开始做自己的第一个 project，你就会通过 googling 和不断充实自己的 programming 知识库来学习其余内容。Computer science theories、对你所用 language 的 detailed understandings，或 advanced design patterns，都可以等到你完成几个真正的 projects、觉得自己能够 code 一些东西之后再学。

#### 注意事项 #1：不要 Copy-and-Paste

关于这一步，第一条建议是永远不要 copy-and-paste。Copy-and-pasting 不好，因为你没有试着理解自己正在 copying 的 code。相比之下，如果你必须 transcribe，就会自然地问自己：“为什么是这个？为什么不是别的？”即使你无法马上给出很好的答案，亲自 typing 也会让你开始思考答案，而 copy-and-pasting 则会让思考停下来。

#### 注意事项 #2：在寻找 Solution 之前，先自己试一试

第二条建议是，在查找别人如何做之前，总要先试着自己 solve。大多数 problems 都有非常多可以被 solved 的方式。难点在于，expert programmers 往往知道一种特别 concise、clever 的方式，但那往往不是“obvious”的方式。这可能让你陷入一个误区：看到一个 employs tricky syntax 的 clever solution，就觉得自己 _不可能_ 想到那个 solution，进而相信自己不可能独立 solved 它。这通常并不属实，却是在尝试寻找自己的 solutions 之前就查找 solutions 所带来的不幸副作用。

## 你该花精力 Learning Computer Science 吗？

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/comp-sci-vs-coding.png)

Computer science 往往被 equated with programming，但在实践中，两者往往相当不同。Comp sci 更多涉及 discrete math、complicated algorithms 和 computation 的 fundamental issues。Programming 则要 practical、hands on 得多。

例如，许多 computer science professors 并不是出色的 programmers。这听起来可能像是职业上的失败，除非你意识到，他们的工作主要是用铅笔和纸、借助 math 来 prove，而不是 write usable code。

我做过[一个完整的 project 来 learn computer science](https://www.scotthyoung.com/blog/myprojects/mit-challenge-2/)，所以我确实很喜欢它。不过，如果你的目标主要是 practical，我不会在一开始就花很多时间在这上面。如果你已经做了一阵子 programming，并且完成了一些真正的 projects，那么深入 advanced algorithms、theories of computation 和 discrete math topics 可能会非常令人着迷。但如果你从这些内容开始，就很容易感到不知所措。

## 建议总结

这篇文章比较长，所以在结束之前，让我再重申一下最后这些要点：

1.  学习 code 远比大多数 non-coders 想象的容易，至少在制作简单东西时是如此。
2.  它之所以看起来困难，主要是因为：
    1.  Setting up 令人沮丧。
    2.  开始时的选择太多。
    3.  入门课程里有很多 self-taught 的神童，让你觉得自己很笨。
3.  要自学，你应该：
    1.  先决定自己想 make 什么类型的东西（website、app、game、script 等），再挑选最适合你想 make 的东西的 language。
    2.  立即从一个具体的 project 开始，build 一个小东西。书籍、课程和 tutorials 应该帮助你走到这一步。
    3.  遇到困难时，像其他所有人一样 ask Google
        1.  但不要 copy-and-paste 答案。
        2.  而且先试着自己 solve 它。
4.  只有在自己 making 了一些东西之后，再学习 computer science 课程。

只要能熬过最初的挫败感，建立一点信心，任何人都能学会 code。更重要的是，这是一项你终身都能使用的技能，即使你从未成为 full-time programmer。

## 原文

Few skills scare people away like coding. Television portrayals make it seem like writing computer code is a genius-level activity, as weird symbols race across the screen and techno music blares in the background.

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/coding-perception-vs-reality.png)

But the truth is that coding is actually pretty easy.

I’m not saying this to dismiss the work of brilliant programmers. A skill can simultaneously be fairly easy to get the basics in, while also being really difficult to master. Everyone learns to write, few people learn to write well. There’s no contradiction, therefore, in saying that basic literacy is an “easy” skill to acquire (in that the vast majority of us are able to do it), without dismissing the efforts of talented writers.

Nor am I saying this to mock people who are trying to learn programming and find it frustrating.

Rather, I say coding is easy because I believe that almost all people, even if they don’t see themselves as particularly smart, have the ability to learn to write simple programs. That they don’t is mostly due to some structural barriers than any intrinsic difficulty with the skill itself.

## My Experience Coding

Listen to this article  

I’ve been writing programs for over half my life. I’ve taken a couple university classes. I even worked through the [content of a CS degree online](https://www.scotthyoung.com/blog/myprojects/mit-challenge-2/) (which is totally unnecessary if you want to learn to code, by the way).

In some ways, my background may seem to disqualify me about making statements on the ease of coding. However, I can say, without a doubt, that subjects like engineering, accounting, physics and law are more difficult than programming. Most math you learn in high-school is more difficult too, although you usually get waaay more practice with algebra than code, which often leads to a misperception as to which is more difficult.

## Why Coding Feels Hard

Learning to code is hard for a couple reasons:

1.  **Installing new languages is super frustrating**. This is the first activity for a would-be programmer and, to this day, the thing I hate most about programming. This can create the misperception that programming is really hard because newbies extrapolate the difficulty of getting set up to how it will be every moment after.
2.  **There are waay too many languages, tools, libraries and plug-ins.** Starting programming is super overwhelming because there are a bajillion things to learn and you have no idea where to start.
3.  **Early classes tend to be populated with people who have taught themselves programming before.** Thus, you may think you’re not smart enough to program because of an unfair comparison. (I once knew a woman who got a masters in civil engineering, which is much harder than intro coding, and she told me she wasn’t smart enough to code because of her first class. This is _bananas_, and yet people fall for it because some nerdy kid has like ten years of experience before the class starts.)

The first moments of programming are the hardest. Getting set up is annoyingly difficult and often requires learning a new way of working with computers even before you write a single line of code.

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/difficulty-of-coding.png)

Consider the instructions for installing most languages. Open the terminal or command prompt. Type in a case-sensitive exact set of instructions to download and install the language. Use GitHub. Homebrew. Versions matter too. Are you running 32 or 64 bit? ‘Cause if you’re not sure it will crash with a cryptic error message and you’ll feel like an idiot.

These tools are learnable, like everything else, but they reinforce the impression given by television that coding is mostly using esoteric tools with weird, unfriendly user interfaces. When people see coding they imagine parsing the green-streaming letters of the Matrix, whereas the truth is a lot more like following a recipe along step-by-step.

## How Do You Get Over the Initial Difficulties?

There’s a few ways you can do this. My favorite is to just buy a book that will tell you exactly how to set up a language step-by-step. Most ones from the bookstore will teach you the installation process, and if you can be meticulous at following them you’ll usually be successful.

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/oreilly.png)

Alternatively, you can dive into internet tutorials, but recognize that sometimes they are aimed at already-proficient programmers, who know what Homebrew and GitHub are, and are fluent with writing commands into Terminal. If you get one of these, you can try to follow it, but don’t feel bad if you screw it up. It’s frustrating and it doesn’t mean all coding will be like this.

Another option is to avoid setup at all. Just use some coding tutorial website that teach you to code without needing any installation. I like this too, but sometimes you can’t actually build the thing you want to build with these apps. However, if you hate the setup, that’s where I’d start.

Most important, however, is to remember that I told you this. When you try to learn to code, it will be frustrating to get set up, and just accept that this is a small price to pay. Soon it will be easier and you’ll do stuff that is cool. Don’t feel dumb because you get stuck here, I still do and I’ve been writing code for years.

## What Language/Tool Should You Start With?

This seems like a good question to ask, but, I’d argue, it’s actually the wrong way to think about learning programming.

First, despite the fact that programmers often boast about how many languages they know, recognize that most languages are only superficially different. Yes, I know all about language design, so don’t tell me about the importance of scripting versus compiling, or whether a language is strongly or weakly typed. Those things matter, but they’re details.

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/programming-similarity.png)

The basics of nearly all languages and tools are the same. Variables. Loops. Functions. Pointers. Stack. Trees. Hashing. Recursion. These concepts exist in most languages. If you pick a mainstream language, you’ll learn these in mostly the same way, so it doesn’t matter if you pick Ruby, Python, C++, Java or PHP.

The place languages _do_ matter is _what_ you want to use them for. Want to write iPhone apps? Swift or Objective C are the languages of choice. Need to create web pages? JavaScript is going to come in handy. Yes, you can use almost any language for any task if you tinker with it and get the right plug-ins. However, some languages are easier to get started with certain types of projects than others.

Therefore, the first question to ask is not: which language should I learn, but, which project should I start with?

## What Should Be Your First Project?

I recommend starting your programming adventure, even before you write a single line of code, with a decision about a concrete programming project you’d like to create.

This serves a couple purposes:

1.  **It narrows down the language/tool choices considerably**. Once you know you’re building a website, you’re already leaning towards tools that were designed with that goal in mind.
2.  **Everything you learn is connected to a destination**. As I document [extensively in my book](https://www.scotthyoung.com/blog/ultralearning/), transfer of learning is notoriously difficult. Learning directly works better than learning something and just hoping it will help you later.
3.  **You can work on something you think is cool**. If you think it would be cool to make an interactive website, do that. If you’d prefer a game, do that. If you’d prefer to automate your accounting work so you’re done in half the time as your colleagues, do that instead. Do what you feel is cool and you’ll be motivated to stick to it.

In general, smaller is better when it comes to projects. Deciding to start with making the next Google is ambitious, but probably will get you stuck in the weeds before you make much progress.

If your true ambitious are huge, it’s often best to work on a toy project first. Many experienced programmers still do this when they are entering a new territory of programming. Toy projects take the essential ideas of programming, but turn it into something you can do in a few days or weeks, instead of years.

Examples of good projects include:

-   **A basic text-adventure game.** No graphics, but still requires learning concepts like loops, variables, input-output processing.
-   **A simple website.** Start with just displaying a static page. Maybe add in comments, users, photos or interactive elements as you learn more.
-   **A simple app.** What’s something dead-simple you’d like to have on your phone? It can be stupid to start, don’t worry.
-   **A script for automating a tedious task.**

In general, programs are easier when they involve no multimedia content (websites are a bit of an exception), so if you’re making a game, for instance, a text game tends to be easier than one with graphics, if only because making all the graphics can take time.

Similarly, different core activities have different difficulties. Arithmetic and simple calculations done repeatedly are easiest. Processing text for exact patterns is a bit harder. Processing text for vague patterns is harder still. Processing, speech, photos and video is even harder.

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/difficult-programs-to-make.png)

If you do end up picking an initial project that turns out to be super difficult, it’s okay to scale back. “Make an application that calculates my mortgage payments” is much, much easier than “Make an application that can tell you what someone’s hairstyle is from a photo.” It’s often not obvious that this is the case in the beginning, so don’t worry if you accidentally pick a “hard” problem to start with, you can adjust it later to something easier.

## Which Resources Should You Use?

Once you’ve picked a project, the next step is to get some resources to help. This is a step many people worry over endlessly, but like the language choice, it’s a lot less important (and depends more on your goals) than you think.

I won’t list specific resources, because there are so many good ones that my suggestions are going to leave out some of the best. Instead, here’s three strategies for finding good resources:

1.  **Get a book that teaches you the language + project you want**. There should be a computer section in your local bookstore or library, you can just pick any of those. I like [O’Reilly](http://shop.oreilly.com/), but there are lots of good ones. (If you haven’t figured out which language yet, just Google your type of project and look for suggestions.)
2.  **Attend a MOOC**. [Coursera](https://www.coursera.org/learn/python?), [edX](https://www.edx.org/learn/computer-programming), [MIT](https://ocw.mit.edu/courses/electrical-engineering-and-computer-science/6-00sc-introduction-to-computer-science-and-programming-spring-2011/), [Harvard](https://online-learning.harvard.edu/course/cs50-introduction-computer-science), [Stanford](https://online.stanford.edu/courses) and others all teach computer programming online. Once again, the thing that matters most isn’t the exact class, but whether it teaches the language/project domain you care about.
3.  **Take a tutorial program/website**. Again, there are tons of these. I used [Google’s for Python](https://developers.google.com/edu/python/) the first time I wanted to learn Python.

Stressing over which book or course to pick is the wrong thing to worry about. The main thing to do is to use the book or course to learn enough to start tinkering on your project, not to master programming on its own. Starting your project before your ready is definitely the way you should feel about it.

## Do What Real Programmers Do and Ask Google

Once you actually get started writing code, you’re going to encounter many, many situations where you either don’t know how to do something, or you learned how to do it before and you’ve forgotten.

In these situations, you should do what real programmers do: **ask Google**. This isn’t a shameful activity, but a part of real programming. I’ve been coding for years, but I always forget silly syntactical things and so I find myself googling regular expressions over and over again. It’s not bad, it’s just part of the process.

Once you’ve gotten yourself installed, you’ve learned a bit with your book to know the basics and have started working on your first project, you’ll learn the rest by googling and adding to your library of programming knowledge. Computer science theories, detailed understandings of the language you’re working with or advanced design patterns can wait until you’ve finished a few real projects and feel like you can code something.

#### Caveat #1: Don’t Copy-and-Paste

A first piece of advice when it comes to this step is to never copy-and-paste. Copy-and-pasting is bad because you don’t try to understand the code you’re copying. If you have to transcribe, in contrast, you naturally ask yourself, “why this? why not something else?” Even if you don’t have a great answer immediately, typing things for yourself will open your mind up to the answer whereas copy-and-pasting shuts down thinking.

#### Caveat #2: Try it Yourself Before Looking for a Solution

A second piece of advice is to always try to solve something yourself before looking up how someone else does it. Most problems have many, many ways they can be solved. The challenge is that expert programmers often know a particularly concise, clever way, but that often isn’t the “obvious” way. This can lead to a trap where you see a clever solution that employs tricky syntax, think that there was _no_ way you would have guessed that solution, and believe you couldn’t have solved it on your own. That’s usually not true, yet it’s an unfortunate side effect of looking up solutions before trying to find your own.

## Should You Bother Learning Computer Science?

![](https://www.scotthyoung.com/blog/wp-content/uploads/2019/07/comp-sci-vs-coding.png)

Computer science tends to be equated with programming, but in practice the two tend to be rather different. Comp sci tends to be a lot more discrete math, complicated algorithms and fundamental issues of computation. Programming is a lot more practical and hands on.

A lot of computer science professors, for instance, aren’t great programmers. This may sound like a professional failure, unless you realize that their job is mostly to prove things with a pencil and paper using math, rather than write usable code.

I did [a whole project to learn computer science](https://www.scotthyoung.com/blog/myprojects/mit-challenge-2/), so I happen to really like it. However, if your goal is mostly practical, I would not spend much time with it in the beginning. If you have done programming for a little while, and finished some real projects, then diving into advanced algorithms, theories of computation and discrete math topics can be really fascinating. But if you start with these, it can be easy to get overwhelmed.

## Summary of Advice

This has been a longer post, so let me reiterate the final points before I go:

1.  Learning to code is much easier than most non-coders think, at least to make simple stuff.
2.  The main reason it seems hard is because:
    1.  Setting up is frustrating.
    2.  There are too many options to start.
    3.  Early classes are populated with self-taught whiz-kids who make you feel dumb.
3.  To teach yourself you should:
    1.  Decide what kind of thing you want to make (website, app, game, script, etc.) first, pick the language that fits best with what you want to make.
    2.  Start immediately with a concrete project to build something small. Books, courses and tutorials should help you get to that point.
    3.  When you get stuck, do what everyone else does and ask Google
        1.  But don’t copy-and-paste the answers.
        2.  And try to solve it for yourself first.
4.  Learn computer science classes only after making some things on your own.

If you can get through the initial frustration and build a little confidence, anyone can learn to code. What’s more, it’s a skill you can use throughout your life, even if you never become a full-time programmer.
