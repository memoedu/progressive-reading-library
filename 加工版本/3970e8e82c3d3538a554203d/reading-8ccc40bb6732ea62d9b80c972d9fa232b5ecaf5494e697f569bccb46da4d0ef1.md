## Codex 科研编程常用术语速查：计算数学与 PDE 数值模拟篇

在使用 Codex 等 AI Coding Agent 开展计算数学研究时，经常会遇到一些来自软件工程、算法实验和自动化测试的术语。下面通过一个统一的数值模拟项目，解释 15 个常用术语及其在实际开发中的作用。

## 一、统一案例：开发一个高阶 PDE 数值求解器

假设我们正在研究一维 Euler 方程：

$$
\boldsymbol U_t+\boldsymbol F(\boldsymbol U)_x=0,
$$

目标是开发一个基于五阶 WENO 空间重构与三阶 SSP-RK 时间积分的有限体积求解器，并在已有算法基础上引入一种新的激波检测与数值耗散控制机制，以改善激波附近的计算结果。

整个科研开发流程包括：

1.  实现已有数值方法，建立参考版本。
2.  引入新的激波检测和数值耗散机制。
3.  验证各个数值模块的正确性。
4.  开展精度测试、激波算例和消融实验。
5.  优化性能，执行正式大规模计算。
6.  保存代码、实验配置和结果，保证可复现性。

下面的 15 个术语都围绕这个项目展开。

## 二、15 个核心术语

### 1\. 基线（Baseline）

定义： 用于与新算法比较的固定参考方法或程序版本。

项目中的应用： 将原始 WENO5 有限体积求解器作为 Baseline，记录其误差、收敛阶、激波分辨率和 CPU 时间。之后开发的新格式都与这个版本比较，以判断改进是否有效。

关键词： 参考标准、固定版本、公平比较。

### 2\. 消融（Ablation）

定义： 通过移除、关闭或替换算法中的某个模块，评估该模块对最终结果的贡献。

项目中的应用： 新算法包含激波检测器和自适应数值耗散两个模块。分别关闭检测机制或替换耗散策略，比较激波误差和数值振荡，从而判断性能改善来自哪个模块。各消融版本必须有合理的数学定义。

关键词： 控制变量、模块贡献、机制验证。

### 3\. Oracle（预言机）

定义： 在测试中向算法提供真实答案或理想辅助信息，用于隔离某个模块的误差。

项目中的应用： 测试激波检测器时，Oracle 模式直接提供已知的激波位置，而 Non-Oracle 模式由程序自动识别。比较两者结果，可以判断自动检测过程带来了多少误差。

关键词： 理想信息、误差隔离、性能上限参考。

### 4\. 冻结（Freeze）

定义： 在指定开发或实验阶段保持某些代码、参数、数据或算法状态不变。

项目中的应用： 为研究新数值耗散机制，冻结 WENO5 重构、SSP-RK3 时间积分、网格和 CFL，只修改耗散模块，避免其他变化干扰实验结论。

关键词： 固定参数、限制修改、控制变量。

### 5\. 烟测（Smoke Test）

定义： 对程序进行快速、基础的运行检查，确认没有明显故障。

项目中的应用： Codex 修改求解器后，先在 50 个网格单元上运行 10 个时间步，检查程序能否启动、正常结束，以及是否出现 NaN、数组越界等异常。

关键词： 快速检查、基本运行、初步排错。

### 6\. 单元测试（Unit Test）

定义： 独立验证程序中某个函数或最小功能模块是否满足预期。

项目中的应用： 单独测试 WENO5 重构函数，检查常数数据的重构是否保持常数，以及光滑函数的界面重构是否达到预期精度，而不需要运行整个 Euler 求解器。

关键词： 局部模块、独立验证、函数正确性。

### 7\. 集成测试（Integration Test）

定义： 检查多个独立模块组合起来之后能否正确协作。

项目中的应用： 将 WENO5 重构、数值通量、边界条件和 SSP-RK3 时间积分组合，运行一个简单的周期边界算例，检查模块接口、数据传递和时间推进是否正确。

关键词： 模块组合、接口检查、协同运行。

### 8\. 回归测试（Regression Test）

定义： 在程序修改之后，重新检查已验证的功能，确保新修改没有引入错误或性能退化。

项目中的应用： 修改数值耗散模块后，重新运行原有的常数解保持、光滑解收敛阶和经典 Riemann 算例，确保新算法没有破坏原来的正确性质。

关键词： 防止退化、历史测试、修改后复查。

### 9\. E2E（End-to-End Test，端到端测试）

定义： 从程序实际使用入口开始，验证整个工作流程能否正确完成。

项目中的应用： 从读取 Euler 算例配置文件开始，依次执行网格初始化、数值计算、结果保存、误差统计和绘图，确认最终能够生成正确的实验数据与图片。

关键词： 完整流程、输入到输出、系统级验证。

### 10\. 最小复现（MRE，Minimal Reproducible Example）

定义： 将复杂错误简化为能够稳定重现问题的最小独立案例，以便定位根因。

项目中的应用： 如果 Euler 求解器在复杂激波算例中出现 NaN，可以逐步减少网格数、简化初始条件和关闭无关模块，直到找到一个仍然触发错误的最小算例。

关键词： 简化问题、稳定复现、根因定位。

### 11\. 静态检查（Static Analysis）

定义： 不运行被检查的程序，通过分析源代码发现潜在错误、类型问题和不规范实现。

项目中的应用： 每次 Codex 修改 Python 求解器后，使用 Ruff、Mypy 等工具检查未使用变量、类型不匹配和潜在代码问题，再执行实际数值测试。

关键词： 不运行程序、自动检查、代码质量。

### 12\. 哈希（Hash / SHA-256）

定义： 哈希通过特定算法为数据生成固定长度的指纹，用于标识版本或检查内容是否发生变化。SHA-256 是常见的加密哈希算法。

项目中的应用： 开展数值实验时，使用 Git Commit Hash 记录求解器的代码版本，并用 SHA-256 记录参考解、网格文件和重要输入数据的内容指纹。

这样可以确认不同实验是否使用了相同的数据，并检查参考解是否被 Codex 意外覆盖。

需要区分：

-   Git Commit Hash： 标识特定 Git 提交；仅记录它不能反映未提交的工作区修改。
-   文件 SHA-256： 检查任意文件的字节内容是否与记录时一致。

例如，在 Windows PowerShell 中：

```text
git rev-parse HEAD
git status --short
Get-FileHash .\reference.csv -Algorithm SHA256
```

为什么经常检查？ 因为科研数值实验不仅要求程序能运行，还要求代码版本、输入数据和参考解都能够追溯。不过无需每次修改都计算整个项目的 SHA-256，通常只需对重要文件和关键实验进行检查。

关键词： 文件完整性、版本追溯、数据一致性、实验复现。

### 13\. 生产（Production）

定义： 指软件进入正式、稳定的实际使用阶段；在科学计算中也常指 Production Run，即正式数值计算。

项目中的应用： WENO5 求解器通过精度、稳定性和回归测试后，使用高分辨率网格开展正式 Euler 激波模拟，生成用于论文分析的数据，而不再只是运行小规模调试算例。

关键词： 正式计算、稳定版本、生产就绪。

### 14\. 掩码（Mask）

定义： 用布尔数组或其他标记结构，选择哪些数据或网格区域参与特定计算。

项目中的应用： 新算法使用 Shock Mask 标记激波附近的网格单元，仅在这些单元启用额外的数值耗散；光滑区域保持原始高阶方法。

举例：激波检测掩码（Shock Mask） 在求解 Euler 方程时，高阶数值方法可能需要在激波附近启用限制器，而在光滑区域尽量避免额外的数值耗散。

假设某个激波检测指标为 $S_j$，设置阈值 $\varepsilon$：

$$
M_j= \begin{cases} 1,&S_j>\varepsilon,\\ 0,&S_j\leq\varepsilon. \end{cases}
$$

这里 $M_j$ 就是一个 Shock Mask。

-   $M_j=1$：该网格单元被标记为需要限制器处理。
-   $M_j=0$：该网格单元不需要启用这项额外处理。 一维激波检测掩码示意

![](https://pic2.zhimg.com/v2-be52642c6e1ea055517a130a0fb243d3_1440w.jpg)

对应代码可以写为：

```text
shock_mask = sensor > threshold

# 只对检测到的单元施加限制器
u_new[shock_mask] = limiter(u_new[shock_mask])
```

这是示意性写法。实际有限体积或 DG 限制器往往还需要邻近单元、守恒变量及多项式系数，而不只是简单地修改被选中的数组元素。

关键词： 区域选择、条件激活、数据筛选。

### 15\. 门禁（Gate / Quality Gate）

定义： 一组必须通过的自动或人工检查条件，用来决定某个代码版本能否进入下一开发阶段。

项目中的应用： 为 Euler 求解器设置质量门禁：新算法必须通过静态检查、单元测试、守恒性检查、精度测试和回归测试，才能合并到稳定分支或进入正式数值实验。

与普通测试的区别是：测试负责发现问题，门禁决定是否放行。

关键词： 质量控制、自动验收、禁止带错进入下一阶段。
