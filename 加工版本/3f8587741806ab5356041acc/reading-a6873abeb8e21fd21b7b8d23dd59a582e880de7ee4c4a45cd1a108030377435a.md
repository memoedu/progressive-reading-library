## 核心洞察

一、OpenCode Go订阅性价比分析：文章指出，OpenCode Go订阅制相比API付费更便宜，10美元月费（新账号5美元）即可获得5小时12美元、每周30美元、每月60美元的使用额度。按汇率折算，GLM-5.2输入约1.58元/百万token，输出约4.97元，但DeepSeek V4 Pro和MiMo V2.5 Pro按原价计算，实际折扣为66折而非16折，作者对此表示不解。
[[#^pr-29bfc6716886|正文跳转]]

二、多账号管理的痛点：OpenCode Go账号月限额仅60美元，且存在5小时和周限额，导致单个账号不耐用。订阅多个账号时，需要管理多份Key，并关注每个Key的额度使用情况和冷却时间，操作繁琐，这是OCG Manager工具要解决的核心问题。
[[#^pr-fa123ae16e51|正文跳转]]

三、OCG Manager核心功能：OCG Manager是OpenCode Go专用的多账号管理器，支持本地托盘运行和服务器部署。它作为网关，默认监听127.0.0.1:9042，上游固定为opencode.ai/zen/go，支持chat/completions、responses、messages和models等端点，并能在客户端协议与模型原生协议不一致时自动转换请求和响应。
[[#^pr-2a8142371b9d|正文跳转]]

四、智能熔断与冷却机制：与一般网关不同，OCG Manager只处理401、403、429错误（即账号错误或限额不足），出现错误时自动熔断当前Key，并根据OpenCode Go反馈的具体时间对Key进行冷却。账号设置可手动与OpenCode Go同步作为预设，但仅供参考，不用于实际熔断判定。
[[#^pr-5d2a8a70e28a|正文跳转]]

五、简单路由策略与缓存考量：OCG Manager目前没有负载均衡或其他路由逻辑，采用从上到下依次路由，跳过已熔断或冷却的Key。作者根据个人实测（New API随机/轮询模式）推测OpenCode Go的缓存（如GLM-5.2）是根据Key配置的，但也可能是New API的BUG，因此未做进一步猜测。
[[#^pr-cb53cf2ce24a|正文跳转]]

六、额度显示仅供参考：由于OpenCode Go官方未开放Usage接口，OCG Manager显示的额度是根据流经网关的流量计算的，不代表实际额度，仅供参考。可能出现额度显示已打满但实际仍能运行的情况，用户需注意这一限制。
[[#^pr-a3a47acdbcf4|正文跳转]]

七、使用方式与配置：在Windows上安装后，有托盘即表示系统已启动，用户只需将URL和Key粘贴到原来填写OpenCode KEY和URL的位置即可，例如在CC-Switch中。软件还内置了常用应用的配置文件，但默认配置是作者随意填写的，仅供参考。每次请求的日志会显示命中的账号和消费情况。
[[#^pr-4dcf0ea85367|正文跳转]]

八、服务器模式与CLI管理：OCG Manager支持CLI启动和Docker两种服务器模式，目前只推荐CLI启动。本机使用但不想安装托盘时也可用CLI启动。用户可通过CLI直接管理网关，例如添加Key、列出Key、测试连通性、查看状态和启动服务。Docker支持正在开发中。

## 功能简述

这是一个 OpenCode Go 专用的多账号管理器，支持本地托盘运行和服务器部署。

^pr-2a8142371b9d

![](https://pic4.zhimg.com/v2-a218b712d976251f4843c134772f01d7_1440w.jpg)

在本机运行的时候，默认 URL 为 [http://127.0.0.1:9042/v1](https://link.zhihu.com/?target=http%3A//127.0.0.1%3A9042/v1)。

上游默认为 [https://opencode.ai/zen/go](https://link.zhihu.com/?target=https%3A//opencode.ai/zen/go) （这个应该没有人想去改它吧）。

网关支持接收以下 EndPoint：

-   `POST /v1/chat/completions`
-   `POST /v1/responses`
-   `POST /v1/messages`
-   `GET /v1/models`

客户端协议和模型的原生协议不一致时，会自动转换请求，再把上游响应转回客户端需要的格式。

和一般的网关不同的是，OCG Mgr 只会处理 401、403、429 错误，也就是 OpenCode Go 的账号错误/限额不足。

^pr-5d2a8a70e28a

当出现错误以后，会自动熔断当前 Key，根据 OpenCode Go 反馈的具体时间，对对应的 Key 进入冷却。

账号支持手动和 OpenCode Go 进行同步设置，作为新增账号时候的预设，但是这个数值仍然仅供参考，并不作为实际熔断的判定。

![](https://pic4.zhimg.com/v2-ef1fb071ac832d03498ca2638d9fac3b_1440w.jpg)

目前没有任何负载均衡、或者其他路由逻辑，采用的是简单的从上到下依次路由，跳过其中已经熔断/进入冷却的 KEY。

^pr-cb53cf2ce24a

因为根据我个人实测（New API 随机/轮询模式），OpenCode Go 的缓存是根据 Key 来配置的（指 GLM-5.2）。也有可能是 New API 自己的 BUG，这里我不多做猜测。

![](https://pic3.zhimg.com/v2-a2c099de1bb71541407aa53ca6267172_1440w.jpg)

因为 OpenCode Go 官方并没有开放 Usage 接口，所以上面的额度都是根据流经网关的流量计算的，并不代表实际额度。只能仅供参考，会出现额度看起来被打满了但是实际仍能运行的情况。

^pr-a3a47acdbcf4

## 服务器模式

支持 Cli 启动和 Docker 两种模式。目前只推荐 Cli 启动。

^pr-c9fb5e7a43bb

PS：如果你本机使用，但是不想安装托盘，也可以 Cli 启动。

![](https://pica.zhimg.com/v2-27f9c2f58b5b6f53a300ec67c3ff7bc4_1440w.jpg)

同时你可以直接用 Cli 对网关进行直接的管理。

```
ocg-manager-cli key add main sk-...
ocg-manager-cli key list
ocg-manager-cli key ping
ocg-manager-cli status
ocg-manager-cli serve --port 9042
```
