## 核心洞察

一、WSL2满足本科CS学生低成本Linux需求：对于预算有限且不想使用双系统的CS本科学生，WSL2能以最低成本满足绝大部分开发需求。它无需额外硬件投入，安装简单，开箱即用，且能直接访问Windows文件系统，适合作为日常开发环境。
[[#^pr-699d70544bf2|正文跳转]]

二、WSL安装简单开箱即用：WSL的安装过程非常简单，只需两条命令即可完成：`wsl --list --online` 查询可用分发版，`wsl --install Ubuntu-22.04` 安装指定版本。这种低门槛使得初学者也能快速上手，无需复杂配置。
[[#^pr-fc413155ffbf|正文跳转]]

三、WSL可访问Windows文件系统并支持符号链接：WSL默认将Windows文件系统挂载在`/mnt`下，用户可以将工作目录放在Windows侧，再通过`ln -s`符号链接到WSL中访问。这样既可以利用Windows的GUI工具进行文件操作，又能在WSL中随意实验，即使系统崩溃也能快速恢复。
[[#^pr-27f2d73f3302|正文跳转]]

四、WSL2支持GPU直通可跑深度学习：WSL2支持显卡直通，用户可以在WSL内搭配miniconda运行深度学习任务，甚至进行轻量级LLM推理，例如llama3.2-3B全精度推理。这为本地AI开发提供了便利。
[[#^pr-bc894eb61aaf|正文跳转]]

五、VSCode原生适配WSL：VSCode对WSL有良好适配，在WSL终端中执行`code .`即可一键启动VSCode并远程连接到当前目录，实现无缝的跨环境开发体验，无需额外配置。
[[#^pr-608232041574|正文跳转]]

六、WSL原生支持GUI应用：WSL原生支持x11和wayland的GUI方案，无需配置即可运行图形界面应用，且分辨率调整也有文档和教程可循，提升了可用性。
[[#^pr-8e4016211836|正文跳转]]

七、WSL常见吐槽源于使用不当：部分对WSL的吐槽源于错误的使用方式，例如WSL可以迁移到任意位置而不必占用C盘空间，且支持NAT模式，可通过设置`http_proxy`和`https_proxy`代理上网。正确配置可避免这些问题。
[[#^pr-1f0ee616b73d|正文跳转]]

八、WSL2存在高阶功能限制：WSL2不支持从`/boot`拷贝initramfs等脚本操作，USB映射也是麻烦事，这些高阶功能缺失使其无法完全替代传统Linux环境，但对本科阶段开发需求而言，其低成本优势仍具吸引力。
[[#^pr-f8315f685f4d|正文跳转]]

## 正文

从 CS 本科学生的角度答一下。

因为我没有足够预算去配置一台性能足够的 Linux 设备，且我不想使用双系统，而 WSL2 能够满足我的绝大部分需要。

^pr-699d70544bf2

1.  WSL 的安装没有难度，开箱即用；一行 wsl --list --online 查询分发，一行 wsl --install Ubuntu-22.04 安装成功

^pr-fc413155ffbf

2\. WSL 可以直接访问 Windows 的文件目录，默认挂在在 /mnt 下。这诞生了一种我推荐的玩法：工作目录本体全放在 Windows 文件系统里，把所有会用到的目录 ln -s 到 WSL 里访问即可——这有两个优点：

^pr-27f2d73f3302

-   其一，可以用 Windows 的 GUI 访问目录，方便打包/发送；
-   其二，可以放开顾虑在 WSL 里敞开随便乱玩，炸了直接一锅端，反正我重新链接一下就回来了

虽然这确实会因为跨文件系统导致读写速度降低，但仍在我的可接受范围内。

![](https://picx.zhimg.com/50/v2-59c9ab61be3f043faee63ac412b22e57_720w.jpg?source=2c26e567)

3. WSL2 直通显卡，我可以搭配 miniconda 在本地跑一些深度学习任务，甚至是轻量化 LLM 推理：

4\. VSCode 适配了 WSL，在 WSL 中 code . 可以一键在当前目录启动VSCode远程连接

![](https://picx.zhimg.com/50/v2-f66a54b75f77d0114369d7370adaa07b_720w.jpg?source=2c26e567)

5. WSL 原生支持 x11 和 wayland 的 GUI 方案，不需要任何配置开箱即用；如果要调分辨率也能找到文档和教程。

6. Win11 的标签页式终端虽然依旧难用，但跟 win10 的那一堆垃圾比起来至少能用了。

![](https://picx.zhimg.com/50/v2-1dba7bf2d66a4ee31fbe1fdc10cd3657_720w.jpg?source=2c26e567)

我看到一小部分对 WSL 的吐槽来源于对 WSL 的不正确使用方式，例如：WSL 是可以迁移到任何地方的，不必占用C盘空间（见[Migrate\_WSL2](https://link.zhihu.com/?target=https%3A//github.com/damienvanrobaeys/Migrate_WSL2)）；WSL 可以走 NAT，依此打个 http\_proxy 和 https\_proxy 挂上梯子。

^pr-1f0ee616b73d

以上这些只是说明 WSL 是适合本科阶段 CS 学生的工具，稍微高阶一点的玩法 WSL 不支持的多了去了。有一些脚本会从 /boot 里拷贝一份 initramfs，但是 WSL2 直接把这部分砍了；包括 USB 映射也是个大麻烦……但不妨碍它以最低的成本满足了我现阶段的开发需求。
