# 中国的高校计算机教育存在哪些问题？ - 锦恢 的回答

## 阅读前置卡

- 价值判断：高。围绕高校计算机教育提出具体的工程实践问题，覆盖课程衔接、考核、实习和课设，并给出可操作的教学设计；论据主要是个人经历与观察，缺少系统调查。
- 信息密度判断：高。多数条目同时包含问题、后果、技术实例或改进方案，具体信息集中；夹有情绪化评价、重复批评和少量生活插话。
- 是否继续阅读：3 全文。值得全文阅读以理解各门课程的具体问题与实践方案，尤其是实习安排和需求变更课设；内容以经验性批评为主，无须逐句精读。

## 核心洞察

一、讨论限于部分学校的工程教学：这些问题仅涉及部分学校的部分现状，建议更偏向工程应用和代码实践。在粗浅看过评论区网友推荐的 scip 后，认为它对学习编程语言大有裨益，值得推荐。
[[#^pr-336e747e8e2e|正文跳转]]

二、编译与构建不能被IDE掩盖：C语言基础课不讲 gcc、clang 的编译参数，直接用 Dev-C++ 或 VS 入门，完全掩盖了底层执行；C++课不教用 g++ 链接动态库和静态库，导致大量毕业生不会调用矩阵库或 OpenCV。应让学生先完成复杂的 C++ 第三方库项目，等编译命令超过100行后再教 make 和 cmake，让他们深切体会工具的价值。
[[#^pr-a1accedfcccf|正文跳转]]

三、编程课应上机考核：部分学校用笔试考核 C、Python 等编程语言课，滋养了无数小镇做题家。正确方式应是类似 ACM 赛制的上机编程考核；数据结构和算法设计也应如此，先把算法用代码实现出来，而不是只看分数。
[[#^pr-a1accedfcccf|正文跳转]]

四、先建立应用图景再学习课程：缺少工程应用导论、课程设置割裂，使学生无法建立自上而下的认知：学完 C语言后再学数据结构和操作系统，很多学生仍不懂数据结构的意义和用途，学习兴致不高。大一就应介绍 Python、C++、Java、js 的应用场景，以及计算机组成原理、深度学习、图形学、web全栈开发等领域的概况，让学生按需求选课。算法教学也必须交代日常软件中的具体应用，否则学生进入社会后会瞬间价值观崩塌，觉得高校所学算法没有用。
[[#^pr-a1accedfcccf|正文跳转]]

五、大二实习能改变学习动机：公司实习对技术和市场认知的改变非常大；有无实习的学生之间的差距，比985与二本学生之间的差距还大，已有童子功者除外。部分学院专门留出半年或一年实习，不实习不发毕业证，值得肯定。实习应放在刚学完基础的大二，让学生真正认识操作系统和数据结构在工程实践中的重要性，进而选择转专业或认真学习这些课程，强逼学生学习没有用。
[[#^pr-a1accedfcccf|正文跳转]]

六、科班Python不能止于调包：非计算机专业能调用库就算合格，但计算机科班不应连 CPython 解释器原理、基于双向循环链表的 GC 回收机制，以及大部分 Python 计算库是 C语言写成的动态库都不知道。Python课不讲这些内容，实在丢人。
[[#^pr-a1accedfcccf|正文跳转]]

七、网络课必须现场组网：计算机网络课把大部分时间花在几乎没什么用的物理层、数据链路层上，实用性最强的应用层协议，特别是历代 HTTP 协议，却基本一两节课就讲完。好几个遇到过的顶级985毕业生不会实验室组网、分不清 socket 与 websocket、不会把服务器和嵌入式设备接入同一内网，并称已忘记 DHCP 和 A类内网 IP；还有不少人不知道主板上的以太网口在哪里。光讲协议没有用，应拿交换机和以太网双绞线现场演示组网与协议接入。
[[#^pr-a1accedfcccf|正文跳转]]

八、机组实验填空化且抄袭严重：计算机组成原理抄袭严重，大部分人没有能力独立完成 CPU 软核设计与 RTL 开发。部分985计算机强校为避免被学生“爆破”，把实验变成 Verilog 或 scala 填空，导致抄袭严重，部分学校的实验形同虚设，毕业生面对五级流水线、flush、中断向量表等问题也答不上来。
[[#^pr-a1accedfcccf|正文跳转]]

九、编译原理要落到解析器实践：编译原理过于理论化，部分文法缺少实际应用举例。应讲清相关文法、常用的左推自动机框架及技术栈，并让学生编程实现 JSON 流式增量解析器；后续还应讲 antrl 和 LLVM，让学生实现小型 AST parser 或支持简单标记的正则表达式引擎。写报告本身并不令人反感，但应让学生选择喜欢的标记语言，查阅相应的 IEEE 标准手册，理解其中的 BNF。
[[#^pr-a1accedfcccf|正文跳转]]

十、网络课被戏称为“计算机文科”：计算机网络课偏重协议讲授、缺少实际组网训练，甚至出现毕业生不会实验室组网的情况，因此在很多学校被历届学生戏称为“计算机文科”。
[[#^pr-a1accedfcccf|正文跳转]]

十一、软件工程课设至少变更三次需求：软件工程非常重要，同时面向架构师和产品经理；技术学得足够通透后，会发现打磨产品时管理和认知与技术一样重要，不能以只想做普通程序员为由忽视它。很多学校却没有让需求建模、开发迭代、开发管理、设计模式等内容跟进实际应用。较好的课设应从第一节课组队，分别承担产品经理和开发角色，由老师提出需求并开始设计开发简单产品，课程中至少进行3次需求变更，让学生体会需求和软件永远不可能一步到位，必须用科学管理方法迭代升级。这些方法可在 Software Engineering A Practitioners Approach 中学到。
[[#^pr-d00d5a4659b4|正文跳转]]

十二、图形学教学偏离应用需求：图形学与编译原理有相似困境：教学过于理论化、数学化，方向像是让学生编写 GPU 和图形驱动，而学生想学的是使用 OpenGL 和游戏引擎所需的数学知识。缺少编程实践，使大部分学生结课后只是复习了小学数学，写 shader、做抗锯齿时只能求助 ChatGPT，得到抽象油画般的结果，对他们自行实现体素渲染引擎已不抱期待。即便米哈游的引擎岗也不是招人写 GPU 驱动，没有必要连一条线段的光栅化都自己实现。
[[#^pr-d00d5a4659b4|正文跳转]]

十三、机器学习课程应先补足基础：很多学校把机器学习安排在大一，课时安排错乱。西瓜书面向拥有一定机器学习基础的中阶入门者，而非新手；数学和编程知识不足的学生为追赶潮流贸然学习，往往完全看不懂或只能理解一部分。正确的学习顺序应是高等数学→线性代数→概率论→最优化原理→矩阵微分与求导原理（或读完西瓜书附录第一章）→机器学习。
[[#^pr-8815af5ccf62|正文跳转]]

十四、AI科班不能只会调用框架：大部分学校的深度学习教学难以由浅入深。其他专业只会调用框架、写 torch 胶水尚情有可原，但人工智能专业学生连框架基本原理、正向图与反向图、反向传播在计算图中的递归实现，以及 CNN 的 img2col 的 GEMM 优化都不懂，太离谱。
[[#^pr-8815af5ccf62|正文跳转]]

十五、数据处理能力缺少课程训练：深度学习应用开发中，写 torch 胶水的时间大概只占整个训练过程的 10%—30% 不到，大模型开发中的占比更低。因此，快速完成数据下载、标准化、归一化、数据增强，并实现 IO 和内存高效的 dataloader，是非常重要的能力。这些能力通常在 data mining 相关课程中磨练，但很多学校不开设，学生只能在深度学习类课程的截止期限压力下与 ChatGPT 一起练习。
[[#^pr-8815af5ccf62|正文跳转]]

十六、初学实践应多做任务而非刷点：学校缺少常用 CV、NLP 任务模型的代码实践课。一周内使用规模小于 10 万的数据集快速实现共 10 个任务，包括目标分类、检测、分割、语义分类和单词生成，曾让这段学习经历中的编程能力和深度学习理解显著加深。初学时不必揪着少数性能点不放，先做到 loss 下降、测试集准确率不错即可；只顾刷点的做法令人厌恶。很多学校一学期只做一两个模型，学生的大部分时间精力反而花在报告和调参上。
[[#^pr-8815af5ccf62|正文跳转]]

十七、独立训练大模型离不开HPC：学校缺少 HPC 和 infra 课程。AI 学生应学习高性能计算、基本分布式通信协议以及 DP、PP、MP；不会这些，就永远无法独立完成大模型或较大 CV 模型的训练、优化和部署。这些内容可以在《高性能计算原理》一类课程中学到。
[[#^pr-8815af5ccf62|正文跳转]]

十八、调参依赖底层理解与梯度排查：调参困难、NaN 和运行结果不一致，涉及 Python、PyTorch 的基本特性及深度学习框架底层原理；不好好学习这些底层知识，自然不知道如何调参。运行结果不同，可能因为未设置全局 manual_seed、种子设置不全、未关闭 dataloader 的 shuffle、使用了默认无序的 Python set，或使用了第三方库内建的随机数种子。loss 降不下去时，通常先训练三轮，从计算图根节点向上层次遍历，打印 node grad dict 的资源视图，定位梯度从哪里开始爆炸；有经验的人一般会先看 exp 等含指数的运算节点。实习 mentor 曾抱怨，面试的 10 多名 C9 高校研究生没有一人懂计算图原理，也不知道通过打印节点梯度来调参。
[[#^pr-8815af5ccf62|正文跳转]]

十九、用软件开发视角理解深度学习：很多 AI 专业学生因为天天看 CVPR、NIPS 等会议，把模块设计得厉害、指标刷得高视为成功，却没有结合软件开发理解深度学习。现实数据不断变化，算法好不好不仅要看测试集表现，还要看能否适应新数据，CDD 就是一个例子。开发机器人意图识别模块时，起初并不知道用户会咨询、表达情绪还是上传数据；真正开发有用的模型，会自然提出 multi label、hierarchy label 等问题，因为它们来自实际部署。解决这些问题能让自己早点下班，而不是编讲自己也不理解的故事。
[[#^pr-8815af5ccf62|正文跳转]]

二十、AI工作大概走向理论与工程：只卷模块的垃圾文章越来越难发表，未来 AI 工作大概会分为数学理论创新和纯 infra 两个方向。理论方向包括融合因果推断方法、创造新的非相关性计算 op，以及对抗与可信计算中的验证、几何深度学习等，数学知识有很多用武之地。纯 infra 方向以大模型和 SAM 为最好的代表：它们没有理论创新，做 SAM 还得会一些 C++ 和前端。
[[#^pr-1e6ec7ee2550|正文跳转]]

二十一、工程能力与部署约束不可绕过：大模型入门门槛高，除了需要很多显卡，还因为目前 AI 专业毕业生大部分不具备很强的纯 infra、即工程能力，包括数据处理、标准化、TB 级 IO、分布式训练、可持久化训练、量化与计算图剪枝、模型部署和异构优化。在业界做终端和机器人的那批算法工程师看来，高校做的东西就是玩具。不考虑运行时内存、耗电量和推理延迟的深度学习模型永远上不了板子，以“有 5G”为由回应这些约束也不成立。
[[#^pr-1e6ec7ee2550|正文跳转]]

二十二、强烈推荐的框架实践书：强烈推荐《python实现深度学习框架》。
[[#^pr-cb6f4aac15b5|正文跳转]]

二十三、书架上的《智能计算系统》：书架上的《智能计算系统》由陈云霁老师赠送，是国内最早讲 AI 芯片架构的书。

以下仅为部分学校的部分现状，有则改之无则加勉。（本文的建议更加偏向工程应用和代码实践，这里推荐一下评论区网友推荐的 scip，我粗浅看了一下，对于学习编程语言大有裨益）

1.  C语言基础不讲gcc或者clang的编译参数，而是直接用的devc++或者VS这样的集成开发环境上手，完全掩盖底层执行。
2.  C++不讲如何使用g++连接动态库和静态库，导致计算机毕业生不会使用C++调用矩阵库或opencv的一抓一大把。
3.  指导学生写一个复杂C++第三方库项目，然后在学生的编译命令超过100行后教给学生make和cmake，让学生感激涕零。
4.  部分学校竟然用笔试考试作为C和Python这类编程语言课的期末考核方式，滋养了无数小镇做题家。正确的做法应该是使用上机打代码类似ACM赛制的方式进行考核。数据结构和算法设计同理，先别想着怎么设计算法，你先给我用代码撸出来再说，score is cheap, show me the code.
5.  缺少面向工程应用的导论课，学生有权利在大一时认识到，Python，C++，Java，js等常规编程语言的应用场景，知道计算机组成原理，深度学习，计算机图形学，web全栈开发等领域的概况，然后根据自己的需求选课。
6.  课程设置割裂，无法让学生建立自上而下的认知。比如大一学完C语言基础，再教数据结构和操作系统，很多学生根本呢就不知道学数据结构的意义是什么，有什么用，导致学习兴致不高。
7.  部分学校没有实习课。公司实习对计算机学生的改变非常大，无论是技术还是市场认知上。有没有实习的计算机学生差距比985和二本的差距还大（童子功除外！）。此处点名表扬部分学校，它们的计算机学院会专门空出一年或者半年让学生去实习，不实习不给毕业证。建议把这个实习放在大二，刚学完基础后，再去实习，当学生真正意识到操作系统和数据结构在工程实践中的重要性后，他们会选择转专业或者认真学习操作系统和数据结构等课。你逼学生学没用的。
8.  教Python不讲CPython解释器原理。非计算机也就算了，他们当个调包侠就算合格，计算的科班学个Python连CPython，基于双向循环链表的GC回收机制，大部分Python计算库都是C语言写成的动态库都不知道，也太丢人了。
9.  讲算法时不讲具体的应用场景，导致学生学了某个算法根本不知道我们日常生活中的软件中哪里用了这个算法，导致进社会后瞬间价值观崩塌，觉得高校学的算法没有用。
10.  计算机网络把大部分时间都花在了几乎没啥用的物理层，数据链路层等方面。计算机网络实用性最强的应用层协议，特别是http历代协议基本一两节课讲完。我已经tm遇到了好几个顶级985计算机毕业生连实验室组网都不会，socket和websocket傻傻分不清，如何用路由器把服务器和嵌入式设备接入一个内网不会，一讲DHCP和A类内网IP他们说全部忘记了。。。所以，计算机网络在很多学校被历届学生戏称为“计算机文科”。你光讲各类协议没用呀，你得上课拿交换机和以太网双绞线现场演示组网和协议接入。哦，对了，不少人连以太网口在主板上的哪里都不知道，也是个神人了。也难怪小林大佬要写那本书了。
11.  计算机组成原理抄袭严重！大部分人都没有能力独立完成CPU软核的设计与rtl开发，导致部分985CS强校为了避免被学生爆破，把计算机组成原理出成了Verilog或者scala的完型填空，也是群神人了。导致抄袭严重，部分学校的机组实验出和没出一样。问毕业生五级流水线，flush，中断向量表等等直接阿巴阿巴。
12.  编译原理教得太理论了，课上教的部分文法没有实际应用举例，比如你讲完上下文无关文法就应该讲什么玩意儿是上下文无法文法，常用的左推自动机框架有哪些，技术栈是什么，如何编程实现一个json流式增量解析器。后续讲完后，antrl和llvm总要讲的吧？总要让学生自己实现一个小AST parser或者支持简单标记正则表达式引擎的吧。我本人不反感写报告，那你总要让学生选择一个自己喜欢的标记语言，然后翻看对应的IEEE标准手册，理解其中的BNF的吧？

1.  软件工程是非常重要的一门学问，但是很多学校把这门课讲得稀巴烂，完全没有实际应用跟进，比如需求建模，开发迭代模式，开发管理，设计模式等等，别tm跟我说你只想做个普通的程序员，等到你的技术学得相当通透后，你会发现管理和认知对于打磨一个产品来说和技术一样重要。软件工程就是同时给架构师和产品经理开的一门课，非常重要。一个比较良性的软工课设应该是从第一节课开始进行组队，一个人当产品经理，一个人做开发，老师从课程开始提出需求，开始设计开发简单产品，然后整个课过程中，老师至少进行3次需求变更，让学生体会到，他们设计的需求和软件永远不可能一步到位，软件的开发需要科学的管理方法进行迭代升级，这些科学方法就藏在软件工程的那本 Software Engineering A Practitioners Approach 里面（这本书可以在google里面搜到免费的原稿pdf，不要走错了！这也是我本科期间最精美的一本教材）。
2.  计算机图形学是一个巨坑，一时半会儿讲不清。它的困境和编译原理差不多，老师教得太理论了，讲得过于数学化，老师教的是让你去写GPU驱动和图形驱动，但是你只是想要学会 opengl 和游戏引擎的使用层面的数学知识。缺少编程实践，大部分学生结课后，小学数学复习得差不多了，但是你让TA写个 shader，做个抗锯齿化，他只能打开chatgpt，然后生成一堆毕加索的抽象油画。我已经不奢望他们会自己去实现体素渲染引擎了。。。就算是米哈游的引擎岗也不是招你进去写GPU驱动的，难不成，你连一条线段的光栅化都要自己实现？

计算机相关的基本就这么多了。

作为计算机辅修人工智能的萌新，而且我看到评论区不少朋友也在吐槽人工智能的教育，我就简单写一写人工智能上面的一些教学槽点吧。

1.  课时安排错乱。很多学校的《机器学习》这门课是开在大一的，但是事实上，周老师的那本西瓜书的受众不是机器学习新手，而是“拥有一定机器学习基础的中阶入门者”。很多学生在没有足够数学和编程知识的情况下就贸然学习这本书，想要附庸风雅，追赶潮流，但是发现自己完全看不懂，或者只能看个一只半截。正确的科技树应该是：高等数学->线性代数->概率论->最优化原理->矩阵微分与求导原理（或者西瓜书的附录第一章看完）->机器学习。
2.  深度学习讲得太烂了。大部分学校讲深度学习很难由浅入深地讲，别的专业的人做个掉包侠，写写torch胶水情有可原，你tm作为人工智能专业的同学，连深度学习框架的基本原理，啥是正向图啥是反向图，反向传播在计算图中的递归实现是什么，CNN的img2col的GEMM优化怎么做的都不知道，也太离谱了。
3.  缺少 data mining 相关的课程。实际进行深度学习应用开发时，你写torch胶水的时间大概只占整个训练过程的 10% - 30% 不到，如果是大模型开发，这个过程的时间占比更低。因此，是否能在短时间内完成数据的下载，标准化，归一化，数据增强，快速实现一个IO高效、内存高效的 dataloader 就是一个非常重要的能力，一般在 data mining 相关的课程中会磨练这项能力，但是很多学校并不开设这门课，导致学生只能在类深度学习的课程的ddl中和chatgpt一起磨练这项能力。
4.  缺少常用CV，NLP任务的分类器模型的代码实践课。我之前学习深度学习时，代码与模型理解能力突破的一次重大事件就是在一周内，以刷题的气势完成了CV，NLP里面总共10个任务（目标分类，检测，分割，语义分类，单词生成）的快速实现，因为都是用的数量小于10万的数据集跑的，所以可以在短时间内快速完成某个任务的开发和实现。这一周的深度学习刷题磨练让我的编程和深度学习理解能力瞬间加深了很多。刚开始时不必揪着那几个点不放，只需要能让loss下降，测试集的准确率不错就行。我很讨厌那些刷点的小镇做题家。很多学校的做法是一个学期只让学生做一两个模型，学生把大部分时间精力全花在写报告和调参上面了。
5.  缺少HPC和infra方面的课程。在大模型火之前，我其实就建议过要让AIer去学习HPC，基本的分布式通信协议，如何进行DP，PP，MP呀，你这些不会，就永远也无法独立完成一个大模型（或者比较大的CV模型）的训练、优化和部署。这些课可以在《高性能计算原理》这类课程中学到。
6.  基础不牢，地动山摇。很多人一直和我抱怨深度学习调参怎么调，为啥一直NaN，为啥每次运行结果都不一样。这些涉及到python和pytorch的基本特性，深度学习框架的底层原理，你自己不去好好学这些底层，当然不知道怎么调参了。比如每次运行结果不一样，可能是全局随机数种子没有manual\_seed，可能 manual\_seed 的不全，可能dataloder的shuffle没有关，可能用了python的set（默认set是无序的），可能用了第三方库内建的随机数种子。loss降不下去，我们一般怎么调参？先训练三轮，从计算图根节点往上层次遍历，打印一下 node grad dict 的资源视图，看一下，从哪里开始爆炸的。有点经验的老玩家一般都会从 exp 呀这样的含指数的 operation node 看。只能说，你问我有什么课能学调参，你这个问题让我怎么回答。。。之前实习时的mentor还和我抱怨说，之前面试了10多个C9的研究生，一个人都不懂计算图原理，问他们怎么调参的，他们居然不知道去打印节点梯度，也是群神人了。
7.  不去结合软件开发与深度学习。很多AI专业的小朋友会学魔怔，他们会觉得说我一个模型模块设计得很nb，点刷得很高，我就很成功了，为啥，因为这群小朋友天天看CVPR，NIPS这样的会议，所以也不能怪他们。如果你以软件开发的角度去看待深度学习，你会获得新的 big picture。在现实生活中，数据是在不断变化的，所以一个深度学习算法是否好，不仅要看它的测试集表现如何，还要能支持适应新的数据（一个例子就是 [CDD](https://link.zhihu.com/?target=https%3A//rasa.com/docs/rasa/conversation-driven-development)）。比如你开发一个机器人的意图识别模块，你一开始是不知道用户真正的意图有哪些的，可能有咨询问题的可能有输出情绪的，可能有做数据上传的。总之，你要是能真的去做一件有用的深度学习模型后，你就会自然而然地提出那些multi label，hierarchy label，因为它们就是实际部署过程中遇到的问题，你去解决它们就能让自己早点下班，而不是去讲一个自己都不知道是什么的故事。这也太不自洽了，不是吗？

最后给AIer一个小小的忠告，光卷模块的垃圾文章越来越难发了，未来的AI工作大概会分为两个方向：

-   数学理论上的创新，比如把causal inference的方法融合进来，创造新的非相关性计算op；比如做对抗和可信计算中的验证、几何深度学习等，也有很多数学知识的用武之地。 ^pr-1e6ec7ee2550
-   纯 infra 工作，大模型和SAM就是最好的代表（搞SAM还得会一些C++和前端），你说它有什么理论创新吗？没有。那为什么入门大模型的门槛这么高呢？除了需要一堆卡之外，那就是因为**目前AI专业的毕业生，大部分人并不具有很强的纯infra能力，也就是工程能力**。数据处理，标准化，TB级IO，分布式训练，可持久化训练，量化和计算图剪枝，模型部署和异构优化等等。真的，在业界，比如做终端和机器人的那批算法工程师看来，高校做的东西就是玩具。不考虑运行时内存，耗电量，推理延迟的深度学习模型永远上不了板子。什么？你说有5G？哥们，你太幽默了。
