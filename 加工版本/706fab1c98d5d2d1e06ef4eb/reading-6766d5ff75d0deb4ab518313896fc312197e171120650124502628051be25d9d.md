在程序语言理论中，**形式化**是把语言的结构、运行规则与类型规则写成精确定义，再对这些定义证明性质的方法．

不少程序语言爱好者都想过设计一门自己中意的语言．你可能熟悉代数数据类型、所有权、代数作用，也能在项目里熟练使用它们；真到动手设计时，脑袋里却常常只剩一堆零散的偏好：“我想要这个特性”“我不喜欢那种写法”．**会用**一个概念，与**决定它在新语言中怎样工作**，是两项不同的任务：设计时还要说明它解决什么问题、在什么条件下可用、与其他特性相遇时会发生什么．

研究程序语言时，关心的问题往往很朴素：这段程序会算出什么？它会不会在运行时崩溃？编译器声称它“没有类型错误”，这句话有多可靠？要对**所有**程序给出可核对的保证，就得先规定程序的结构与运行规则，同时界定“类型错误”和“出错”各自的含义．

下面用一门只有布尔值和自然数的小语言，串联起这套形式化工作．全文先区分**对象语言**与**元语言**，说明为何不用自然语言编写规格；接着通过 **BNF** 与满足封闭条件的**最小集合**定义语法，并导出**结构归纳法**．在此基础上，用推导规则建立**小步操作语义**，利用**规则归纳法**证明**确定性**；随后区分**值**与**受阻**状态，给出**语法导向**的类型规则以证明**反演**与**类型唯一**，再结合**典范形式**、**进展**与**保型**定理完成“良类型程序不会受阻”的证明．最后将数学规则对应到 Rust 代码，验证检查器相对类型规则的**算法可靠性**与**完备性**．

### 对象语言与元语言

日常交流里，自然语言足够好用，含糊的地方可以靠语境补上．编写程序语言的**规格**时，却不能把关键设计留给读者或编译器作者自行脑补．

比如算数里的“先乘除，后加减”能把 `2 + 3 * 4` 分组为 `2 + (3 * 4)`，却没规定 `f() + g()` 先调用哪一边．规格只写“返回结果”而漏掉边界与异常情况的话，就会留下隐患；C 语言标准用英文写成，几十年来围绕某些条款具体允许什么的争论一直没停，后来还促成了 Cerberus 这类专门将 C 语义精确化的研究项目．自然语言的量词范围也常惹麻烦：“所有提交的程序都没有接受”，既可理解为“每个程序都遭拒绝”，也可理解为“并非所有程序都得到接受”；此外，若不区分“被研究的程序”与“用来谈论程序的语言”，就会像 Berry 悖论（“不能用少于二十个汉字命名的最小正整数”）那样，把外部描述偷偷地混作内部表达式．至于证明，“通过类型检查的程序都不会出错”谈论的是无穷多个程序，测试只能覆盖有限样本，纸面推导若拿一句“其余情形显然同理”带过，往往正是错误藏身的地方．

为此需要先做一条基本区分：被研究的程序语言称为**对象语言**，用来定义、讨论和证明对象语言性质的语言称为**元语言**．例如“$\operatorname{succ}\ 0$ 是值”是元语言里的判断，对象语言本身并没有“值”这个词．在 Rust 里把对象语言的语法树写成枚举 `Term` 时，Rust 扮演的也是元语言的角色．

### 语法：BNF、最小集合与结构归纳

从字符串到树的解析本文不讨论．直接开始讲**抽象语法**．对象语言中的程序称为**词项**（简称“项”），用元变量 $t$ 表示．这门算术语言的抽象语法用 **BNF**（Backus–Naur 表示法）写作：

$$
t ::= \operatorname{true} \mid \operatorname{false} \mid \operatorname{if}\ t\ \operatorname{then}\ t\ \operatorname{else}\ t \mid 0 \mid \operatorname{succ}\ t \mid \operatorname{pred}\ t \mid \operatorname{iszero}\ t
$$

这里 $\operatorname{succ}\ t$ 表示后继（加一），$\operatorname{pred}\ t$ 表示前驱（减一），$\operatorname{iszero}\ t$ 判断是否为零．

BNF 只是一种记号，它的严格含义由集合论中的归纳定义给出：**词项集合** $\mathcal{T}$ 是满足下列**封闭条件**的**最小**集合：

1.  $\{\operatorname{true}, \operatorname{false}, 0\} \subset \mathcal{T}$（本文用 $\subset$ 表示允许相等的包含）；
2.  若 $t_1 \in \mathcal{T}$，则 $\operatorname{succ}\ t_1, \operatorname{pred}\ t_1, \operatorname{iszero}\ t_1 \in \mathcal{T}$；
3.  若 $t_1, t_2, t_3 \in \mathcal{T}$，则 $\operatorname{if}\ t_1\ \operatorname{then}\ t_2\ \operatorname{else}\ t_3 \in \mathcal{T}$．

“封闭”保证用生成规则造不出集合外的东西；“最小”（**最小性子句**）保证集合里**只有**用这三条规则在有限步内搭出来的树，不会混入额外叶子（不属于最小集合的元素例如 `null` ）或无限深的树．

在 Rust 中，这个最小集合可以自然地表示为代数数据类型：

```rust
#[derive(Clone, Debug, PartialEq, Eq, Hash)]
pub enum Term {
    True, False,
    If(Box<Term>, Box<Term>, Box<Term>),
    Zero,
    Succ(Box<Term>), Pred(Box<Term>), IsZero(Box<Term>),
}
```

“最小”除了排除额外元素，还直接给出**结构归纳法**：设 $P$ 是词项上的性质，若 $P$ 对三个常量成立（基准情况），且在直接子项满足 $P$ 时对每个构造子构成的复合项也成立（归纳情况），那么满足 $P$ 的词项集合也符合同样的封闭条件．由于 $\mathcal{T}$ 是这类集合中最小的，$\mathcal{T}$ 的每个词项自然都满足 $P$．在集合论背景下，结构归纳法无需作为独立公理额外引入，它直接来自“最小”这一限定．

但是，语法只规定形状，不保证项满足类型规则．$\operatorname{succ}\ \operatorname{true}$ 和 $\operatorname{if}\ 0\ \operatorname{then}\ 0\ \operatorname{else}\ \operatorname{true}$ 都是合法的词项；它们怎样规约、是否良类型的话，还得再定义规则．

我们先来讲规约．

### 求值：小步操作语义、规则归纳与确定性

有了语法树，接下来定义**语义**．本文采用**小步操作语义**，用词项之间的一步转移描述程序如何一步步运行．

先划出已经算完的合法结果，称为**值**（元变量 $v$），其中自然数的结果称为**数值**（元变量 $\mathit{nv}$）：

$$
\begin{aligned} \mathit{nv} &::= 0 \mid \operatorname{succ}\ \mathit{nv} \\ v &::= \operatorname{true} \mid \operatorname{false} \mid \mathit{nv} \end{aligned}
$$

例如 $\operatorname{true}$、$0$、$\operatorname{succ}\ (\operatorname{succ}\ 0)$ 是值；$\operatorname{succ}\ \operatorname{true}$ 是词项但不是值，因为 $\operatorname{succ}$ 后面不是数值；$\operatorname{pred}\ 0$ 也不是值，它还能继续规约．

**一步规约关系** $t \longrightarrow t'$ 是对下列十条**推导规则**封闭的最小二元关系．横线上是前提，横线下是结论；没有前提的规则称为**公理**：

$$
\frac{}{\operatorname{if}\ \operatorname{true}\ \operatorname{then}\ t_2\ \operatorname{else}\ t_3 \longrightarrow t_2}\ \text{(E-IfTrue)} \qquad \frac{}{\operatorname{if}\ \operatorname{false}\ \operatorname{then}\ t_2\ \operatorname{else}\ t_3 \longrightarrow t_3}\ \text{(E-IfFalse)}
$$

$$
\frac{t_1 \longrightarrow t'_1}{\operatorname{if}\ t_1\ \operatorname{then}\ t_2\ \operatorname{else}\ t_3 \longrightarrow \operatorname{if}\ t'_1\ \operatorname{then}\ t_2\ \operatorname{else}\ t_3}\ \text{(E-If)}
$$

$$
\frac{t_1 \longrightarrow t'_1}{\operatorname{succ}\ t_1 \longrightarrow \operatorname{succ}\ t'_1}\ \text{(E-Succ)} \qquad \frac{}{\operatorname{pred}\ 0 \longrightarrow 0}\ \text{(E-PredZero)}
$$

$$
\frac{}{\operatorname{pred}\ (\operatorname{succ}\ \mathit{nv}) \longrightarrow \mathit{nv}}\ \text{(E-PredSucc)} \qquad \frac{t_1 \longrightarrow t'_1}{\operatorname{pred}\ t_1 \longrightarrow \operatorname{pred}\ t'_1}\ \text{(E-Pred)}
$$

$$
\frac{}{\operatorname{iszero}\ 0 \longrightarrow \operatorname{true}}\ \text{(E-IsZeroZero)} \qquad \frac{}{\operatorname{iszero}\ (\operatorname{succ}\ \mathit{nv}) \longrightarrow \operatorname{false}}\ \text{(E-IsZeroSucc)}
$$

$$
\frac{t_1 \longrightarrow t'_1}{\operatorname{iszero}\ t_1 \longrightarrow \operatorname{iszero}\ t'_1}\ \text{(E-IsZero)}
$$

其中 E-IfTrue、E-IfFalse、E-PredZero、E-PredSucc、E-IsZeroZero、E-IsZeroSucc 是**基本规约规则**，直接规定基本运算如何化简；E-If、E-Succ、E-Pred、E-IsZero 则是**结构规则**（或称**同余规则**），规定当外层尚不能直接化简时，允许在哪个子项位置向内推进．

规则的细节体现了语言的设计取舍．例如 E-If 只允许规约条件 $t_1$，不允许提前在未选中的分支 $t_2, t_3$ 里规约；E-PredSucc 要求内部已经是数值 $\mathit{nv}$ 才能消去 $\operatorname{pred}\ (\operatorname{succ}\ \mathit{nv})$．如果把 E-PredSucc 放宽为任意词项 $t$，那么 $\operatorname{pred}\ (\operatorname{succ}\ (\operatorname{iszero}\ 0))$ 既可以直接消去外层变成 $\operatorname{iszero}\ 0$，又可以先用结构规则在内部算一步变成 $\operatorname{pred}\ (\operatorname{succ}\ \operatorname{true})$，一步规约就失去了唯一后继．

由于 $\longrightarrow$ 也是满足规则的**最小**关系，这里同样可以使用**规则归纳法**（对推导树作归纳）：要证明某性质对所有 $t \longrightarrow t'$ 成立，只需证明它在六条公理规则上成立，且能从四条同余规则的前提传到结论．由此可以先证**值不可规约**（对任意值 $v$ 不存在 $t'$ 使 $v \longrightarrow t'$），再证**一步规约的确定性**：

> **定理（确定性）．** 若 $t \longrightarrow t'$ 且 $t \longrightarrow t''$，则 $t' = t''$．

有了确定性定理，下面这个只返回单个 `Option<Term>` 的 Rust 函数 `step`，就不会因 `match` 分支的书写顺序而漏掉其他合法的规约路线：

```rust
pub fn is_nv(t: &Term) -> bool {
    match t { Term::Zero => true, Term::Succ(t) => is_nv(t), _ => false }
}

pub fn is_value(t: &Term) -> bool {
    matches!(t, Term::True | Term::False) || is_nv(t)
}

pub fn step(t: &Term) -> Option<Term> {
    use Term::*;
    match t {
        If(c, a, b) => match &**c {
            True => Some((**a).clone()),
            False => Some((**b).clone()),
            c => Some(If(Box::new(step(c)?), a.clone(), b.clone())),
        },
        Succ(t1) => Some(Succ(Box::new(step(t1)?))),
        Pred(t1) => match &**t1 {
            Zero => Some(Zero),
            Succ(n) if is_nv(n) => Some((**n).clone()),
            t1 => Some(Pred(Box::new(step(t1)?))),
        },
        IsZero(t1) => match &**t1 {
            Zero => Some(True),
            Succ(n) if is_nv(n) => Some(False),
            t1 => Some(IsZero(Box::new(step(t1)?))),
        },
        True | False | Zero => None,
    }
}
```

### 正规形式、受阻与多步规约

相对于规约关系 $\longrightarrow$，不能再向前规约一步的词项称为**正规形式**．在这门语言里，正规形式包含两类：一类是作为合法计算终点的**值**，如 $\operatorname{true}$、$\operatorname{succ}\ 0$；另一类是既非值、又没有一步后继的词项，称为**受阻的项**（stuck term），如 $\operatorname{succ}\ \operatorname{true}$、$\operatorname{if}\ 0\ \operatorname{then}\ \operatorname{true}\ \operatorname{else}\ \operatorname{false}$．

这里用**受阻**来刻画“程序走到规则无法继续处理的运行时类型错误”．把零步或有限多步规约连接起来，就得到一步规约的自反传递闭包，即**多步规约** $t \longrightarrow^* t'$：

$$
\frac{}{t \longrightarrow^* t}\ \text{(M-Refl)} \qquad \frac{t \longrightarrow t_1 \quad t_1 \longrightarrow^* t'}{t \longrightarrow^* t'}\ \text{(M-Step)}
$$

在这门小语言中，每一步规约都会让语法树的节点总数严格减少，即 $\operatorname{size}(t') < \operatorname{size}(t)$，因此每条规约链都会在有限步内停在某个正规形式上．接下来需要关心的是，**我们要怎么确定**规约最终会停在**值**上，还是停在**受阻**状态上．

### 类型系统与类型安全：典范形式、进展与保型

为了在**不运行程序**的前提下排除受阻状态，我们引入类型系统．类型的语法只有两个构造子：

$$
T ::= \operatorname{Bool} \mid \operatorname{Nat}
$$

**类型判断**写作 $\vdash t : T$（由于这门语言没有变量，类型环境为空，下文简记为 $t : T$），由下列七条**类型规则**归纳定义：

$$
\frac{}{ \operatorname{true} : \operatorname{Bool} }\ \text{(T-True)} \qquad \frac{}{ \operatorname{false} : \operatorname{Bool} }\ \text{(T-False)} \qquad \frac{}{ 0 : \operatorname{Nat} }\ \text{(T-Zero)}
$$

$$
\frac{t_1 : \operatorname{Bool} \quad t_2 : T \quad t_3 : T}{\operatorname{if}\ t_1\ \operatorname{then}\ t_2\ \operatorname{else}\ t_3 : T}\ \text{(T-If)}
$$

$$
\frac{t_1 : \operatorname{Nat}}{\operatorname{succ}\ t_1 : \operatorname{Nat}}\ \text{(T-Succ)} \qquad \frac{t_1 : \operatorname{Nat}}{\operatorname{pred}\ t_1 : \operatorname{Nat}}\ \text{(T-Pred)} \qquad \frac{t_1 : \operatorname{Nat}}{\operatorname{iszero}\ t_1 : \operatorname{Bool}}\ \text{(T-IsZero)}
$$

若存在某个 $T$ 使 $t : T$ 可推导，则称 $t$ **良类型**．

观察结论左侧的词项形状：每种语法构造恰好对应唯一一条候选类型规则．这种性质称为**语法导向**（syntax-directed）．语法导向让我们能从结论倒推前提，即**类型反演引理**（例如若 $\operatorname{succ}\ t_1 : T$，则必有 $T = \operatorname{Nat}$ 且 $t_1 : \operatorname{Nat}$），并由此证明**类型唯一性**（若 $t : T_1$ 且 $t : T_2$，则 $T_1 = T_2$）．

但要注意，这套静态类型规则是**保守**的：$\operatorname{if}\ \operatorname{true}\ \operatorname{then}\ 0\ \operatorname{else}\ \operatorname{false}$ 一步就能规约到值 $0$，不会受阻；可 T-If 要求两个分支具有同一类型 $T$，因此拒绝了它．类型安全只承诺“通过检查的程序不会受阻”，不承诺“凡是不会受阻的程序都能通过检查”．

Robin Milner 在 1978 年提出口号“良类型的程序不会出错”（well-typed programs cannot go wrong）．在本文的模型下，这句话写成精确命题就是**类型安全性**（也称**类型健全性**）：

> **推论（类型安全）．** 若 $t : T$ 且 $t \longrightarrow^* t'$，则 $t'$ 没有受阻．

Andrew K. Wright 与 Matthias Felleisen 在 1994 年给出了一条标准的语法证明路线，把任意多步的 $\longrightarrow^*$ 拆成两条只涉及一步的定理，并用**典范形式引理**衔接：

> **引理（典范形式）．** 若 $v$ 是值且 $v : \operatorname{Bool}$，则 $v$ 是 $\operatorname{true}$ 或 $\operatorname{false}$；若 $v$ 是值且 $v : \operatorname{Nat}$，则 $v$ 是数值 $\mathit{nv}$．
> **定理（进展，Progress）．** 若 $t : T$，则 $t$ 是值，或存在 $t'$ 使 $t \longrightarrow t'$．
> **定理（保型，Preservation）．** 若 $t : T$ 且 $t \longrightarrow t'$，则 $t' : T$．

首先，典范形式引理把编译期的类型信息还原为求值规则所需的具体值形状．在此基础上，进展定理对 $t : T$ 作规则归纳，保证良类型项在当前这一步不会受阻；保型定理对 $t \longrightarrow t'$ 作规则归纳并配合反演引理，保证词项向外规约一步之后仍然保持原类型，使进展定理能在后续步骤继续适用．这两条定理缺一不可：只有进展没有保型，程序走一步后可能失去类型并在第二步受阻；只有保型没有进展，一开始就受阻的项根本没有下一步可走，保型的前提也无从触发．将二者结合，再对多步规约作归纳，便完成了类型安全的证明．

### 规则与算法：从逻辑规范到 Rust 实现

逻辑规则定义了哪些 $(t, T)$ 属于类型关系，我们现在要实现这些规则．对本文的语法导向规则，我们可以写出 Rust 的类型推理函数 `type_of`：

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Type { Bool, Nat }

pub fn type_of(t: &Term) -> Option<Type> {
    use Term::*;
    match t {
        True | False => Some(Type::Bool),
        Zero => Some(Type::Nat),
        Succ(t1) | Pred(t1) => {
            (type_of(t1)? == Type::Nat).then_some(Type::Nat)
        }
        IsZero(t1) => {
            (type_of(t1)? == Type::Nat).then_some(Type::Bool)
        }
        If(c, a, b) => {
            let ta = type_of(a)?;
            (type_of(c)? == Type::Bool && type_of(b)? == ta).then_some(ta)
        }
    }
}
```

代码与数学规则之间仍然需要建立对应关系．要确认检查器的实现无误，需分别验证两个方向的性质（注意区分检查器的**算法可靠性**与语言本身的**类型健全性**）：

**算法可靠性**要求若 `type_of(t) == Some(T)` 则 $\vdash t : T$，用来排除假阳性，保证检查器不会放行坏程序；

**算法完备性**要求若 $\vdash t : T$ 则 `type_of(t) == Some(T)`，用来排除假阴性，保证检查器不会漏掉规则认可的程序（否则一个永远返回 `None` 的检查器没有卵用）．

把这里的**算法可靠性**与前文的**类型安全**结合起来，就得到了完整的保证：**若 `type_of(t) == Some(T)`，则从 $t$ 出发的求值永远不会受阻．**

### 术语对照

全文术语优先遵循[香蕉空间](https://link.zhihu.com/?target=https%3A//bananaspace.org/)的译名，其余参考延伸阅读中的中文译文；完整术语表见 [https://glomzzz.com/how/terms/](https://link.zhihu.com/?target=https%3A//glomzzz.com/how/terms)．

-   **词项**（term）：对象语言中的表达式．
-   **抽象语法**（abstract syntax）：只关心分好组的树形结构、不关心字符排布的语法．
-   **封闭条件**（closure conditions）与**最小性子句**（extremal clause）：定义归纳集合时的生成规则与“最小”限制．
-   **结构归纳法**（structural induction）：沿着词项语法树的构造过程证明性质的方法．
-   **小步操作语义**（small-step operational semantics）：通过一步步的状态转移关系定义程序执行的语义．
-   **规约**（reduction）与**推导规则**（inference rule）：按规则改写词项的过程，以及规定判断如何得出的横线规则．
-   **规则归纳法** / **推导上的归纳**（rule induction / induction on derivations）：沿着推导树的结构证明性质的方法．
-   **正规形式**（normal form）与**受阻**（stuck）：无法再规约一步的词项；其中不是值的正规形式称为受阻．
-   **类型判断**（typing judgment）与**语法导向**（syntax-directed）：形如 $\vdash t : T$ 的陈述，以及由词项最外层语法形状唯一决定候选规则的性质．
-   **反演**（inversion）与**典范形式**（canonical form）：从结论倒推前提的引理，以及由值的类型反推值具体形状的引理．
-   **进展**（progress）与**保型**（preservation / subject reduction）：良类型项要么是值要么能规约一步；良类型项规约一步后类型不变．
-   **类型安全性** / **类型健全性**（type safety / type soundness）：良类型词项在多步规约下不会进入受阻状态．
-   **算法可靠性**（algorithm soundness）与**完备性**（completeness）：检查算法返回的类型判断都能由规则推出（可靠），且规则可推出的判断算法都能返回（完备）．
