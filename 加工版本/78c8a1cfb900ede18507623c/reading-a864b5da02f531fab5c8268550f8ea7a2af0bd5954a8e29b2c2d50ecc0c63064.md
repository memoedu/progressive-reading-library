## 正文

![PL troll：一种没有 type declarations 的 statically typed language。Types 完全使用 Hungarian notation 来 determined](https://danluu.com/images/pl-troll/davidalbert-pl-troll.webp)

Troll？人们就是这样 write Verilog 的[1](https://danluu.com/pl-troll/#fn:1)。在我以前的公司，我们有一个由 formal methods PhD's 组成的团队，他们写了一个 linter，依据我们的 naming convention 来 typechecked 我们的 code。对于我们的 chip（作为 CPU 来说，它算小的），building 一个 model（compiling）大约需要五分钟，running 一次 single short test 需要十到十五分钟，而 long tests 则需要数个 CPU 月。一个能在数秒内 run 的 linter，其价值应该显而易见，更不用说，为了弄清某个 test 为什么 failed，可能需要花数小时 tracing through waveforms[2](https://danluu.com/pl-troll/#fn:2)。

让我们看看一些最常用的 naming conventions。

### Pipeline stage（流水线阶段）

当你对 hardware 进行 [pipeline](http://en.wikipedia.org/wiki/Pipeline_\(computing\)) 时，最终会得到同一个 signal 的许多 versions，这个 signal 所 traverses 的 pipeline 中，每个 stage 都对应一个。即使没有 static checks，你也会希望有某种简单的方法来 differentiate 它们，因此你可能把它们 name 为 `foo_s1`、`foo_s2` 和 `foo_s3`，分别表示它们 originate 于第一、第二和第三个 stages。在任何一个特定的 stage 中，一个 signal 最有可能与同一 stage 中的其他 signals interact；来自其他 stages 的 logic 被 accessed 时，往往就是出了错。确实有理由 access 其他 stages 的 signals，比如 bypass paths，以及会查看多个 stages 的 control logic；但 contained 在一个 stage 内的 logic 足够常见，因此在查看其他 stages 的 signals 时，进行一次“cast”，或加一条 disables 这项 check 的 comment，也不算太麻烦。

### Clock domain（时钟域）

在没有 synchronization 的情况下 Accessing 不同 clock domain 中的 signal，就像从多个 threads 中 accessing 一个 data structure 却没有 synchronization。算是吧。但更糟。糟得多。从 metastable state 来 Driving combinational logic（此时 signal 处于 0 与 1 之间）可能消耗大量 power[3](https://danluu.com/pl-troll/#fn:3)。这里，我说的不只是 inefficient。如果你拿来一块 90 年代末的 high-power chip，removed 它的 heat sink，即使在 normal operation 下，它也会把自己熔进 socket 里。如今的 chips，其可能达到的 maximum power possible power consumption 高得惊人，即使有 heat sink，只要你 disabled thermal regulation，这些 chips 也会自毁。处于 intermediate value、floating 的 Logic 不仅会 uses 大量 power，还会 bypasses chip 通常通过 slowing down clock 来 reduce power 的能力[4](https://danluu.com/pl-troll/#fn:4)。在没有 synchronization 的情况下 Using cross clock domain signals 不是个好主意，除非你喜欢 random errors、high power dissipation，以及偶尔真的发生的熔毁。

### Module / Region（模块 / 区域）

在 high speed designs 中，use 一个 sourced 自其他 module 的 signal，却没有先对它 registering，是一种 error。这会悄无声息地蒙混过 simulation；只有查看 timing report 时，你才会发现。在我上次参与的 chip 项目中，generate 一份 timing report 大约需要两天[0](https://danluu.com/pl-troll/#fn:and-you-couldn-t-concurrently-generate-a-new-one-for-each-build-due-to-the-license-costs-6)。如果你不小心 reference 了一个来自 distant module 的 signal，不仅无法 meet 那条 path 的 timing budget，synthesis tool 还会 allocate resources，试图让那条 path 变得 faster，从而 slow down 其他一切[5](https://danluu.com/pl-troll/#fn:7)，让整份 timing report 都变得毫无价值[6](https://danluu.com/pl-troll/#fn:9)。

### PL Trolling（编程语言圈的恶作剧）

在新工作中，没有任何 static checking 就 coding Verilog，让我一直觉得毫无遮蔽。我迟迟没有 writing 自己的 checker，因为 static analysis 是那种得有 PhD 才能做的吓人东西，对吧？而且，为 SystemVerilog writing 一个 parser，是一项大得离谱的任务[7](https://danluu.com/pl-troll/#fn:10)。不过，结果发现，并不需要多么完整的 parser，而且我谈到的所有事情都足够简单：开始半小时后，我就有了一个 tool，found 了七个 bugs，而 false positives 只有两个。我预计等我们完成时，code 会是现在的 4x，所以这就是半小时工作换来 28 个 bugs，更不用说其中两个 bugs 还在 heavily used macros 里。

我想今天就到这里，不过还有许多其他容易 check 的事情，肯定能 find bugs（例如，checking 那些已 declared 或 assigned、却没有 used 的 regs/logic）。每当我想挑战一个 self-contained 的难题时，也有许多不那么容易的事情可做（例如，checking 某些东西是否在应该 clock gated 或 power gated 时却没有这样做；以 statistically 的方式做这件事并不难，但以 statically 的方式做就 non-trivial 了）。

咦。也没那么糟嘛。我现在已经晋升为初级 PL troll 了。

## 原文

![PL troll: a statically typed language with no type declarations. Types are determined entirely using Hungarian notation](https://danluu.com/images/pl-troll/davidalbert-pl-troll.webp)

Troll? That's how people write Verilog[1](https://danluu.com/pl-troll/#fn:1). At my old company, we had a team of formal methods PhD's who wrote a linter that typechecked our code, based on our naming convention. For our chip (which was small for a CPU), building a model (compiling) took about five minutes, running a single short test took ten to fifteen minutes, and long tests took CPU months. The value of a linter that can run in seconds should be obvious, not even considering the fact that it can take hours of tracing through waveforms to find out why a test failed[2](https://danluu.com/pl-troll/#fn:2).

Lets look at some of the most commonly used naming conventions.

### Pipeline stage

When you [pipeline](http://en.wikipedia.org/wiki/Pipeline_\(computing\)) hardware, you end up with many versions of the same signal, one for each stage of the pipeline the signal traverses. Even without static checks, you'll want some simple way to differentiate between these, so you might name them `foo_s1`, `foo_s2`, and `foo_s3`, indicating that they originate in the first, second, and third stages, respectively. In any particular stage, a signal is most likely to interact with other signals in the same stage; it's often a mistake when logic from other stages is accessed. There are reasons to access signals from other stages, like bypass paths and control logic that looks at multiple stages, but logic that stays contained within a stage is common enough that it's not too tedious to either “cast” or add a comment that disables the check, when looking at signals from other stages.

### Clock domain

Accessing a signal in a different clock domain without synchronization is like accessing a data structure from multiple threads without synchronization. Sort of. But worse. Much worse. Driving combinational logic from a metastable state (where the signal is sitting between a 0 and 1) can burn a massive amount of power[3](https://danluu.com/pl-troll/#fn:3). Here, I'm not just talking about being inefficient. If you took a high-power chip from the late 90s and removed the heat sink, it would melt itself into the socket, even under normal operation. Modern chips have such a high maximum power possible power consumption that the chips would self destruct if you disabled the thermal regulation, even with the heat sink. Logic that's floating at an intermediate value not only uses a lot of power, it bypasses a chip's usual ability to reduce power by slowing down the clock[4](https://danluu.com/pl-troll/#fn:4). Using cross clock domain signals without synchronization is a bad idea, unless you like random errors, high power dissipation, and the occasional literal meltdown.

### Module / Region

In high speed designs, it's an error to use a signal that's sourced from another module without registering it first. This will insidiously sneak through simulation; you'll only notice when you look at the timing report. On the last chip I worked on, it took about two days to generate a timing report[0](https://danluu.com/pl-troll/#fn:and-you-couldn-t-concurrently-generate-a-new-one-for-each-build-due-to-the-license-costs-6). If you accidentally reference a signal from a distant module, not only will you not meet your timing budget for that path, the synthesis tool will allocate resources to try to make that path faster, which will slow down everything else[5](https://danluu.com/pl-troll/#fn:7), making the entire timing report worthless[6](https://danluu.com/pl-troll/#fn:9).

### PL Trolling

I'd been feeling naked at my new gig, coding Verilog without any sort of static checking. I put off writing my own checker, because static analysis is one of those scary things you need a PhD to do, right? And writing a parser for SystemVerilog is a ridiculously large task[7](https://danluu.com/pl-troll/#fn:10). But, it turns out that don't need much of a parser, and all the things I've talked about are simple enough that half an hour after starting, I had a tool that found seven bugs, with only two false positives. I expect we'll have 4x as much code by the time we're done, so that's 28 bugs from half an hour of work, not even considering the fact that two of the bugs were in heavily used macros.

I think I'm done for the day, but there are plenty of other easy things to check that will certainly find bugs (e.g, checking for regs/logic that are declared or assigned, but not used). Whenever I feel like tackling a self-contained challenge, there are plenty of not-so-easy things, too (e.g., checking if things aren't clock gated or power gated when they should be, which isn't hard to do statistically, but is non-trivial statically).

Huh. That wasn't so bad. I've now graduated to junior PL troll.
