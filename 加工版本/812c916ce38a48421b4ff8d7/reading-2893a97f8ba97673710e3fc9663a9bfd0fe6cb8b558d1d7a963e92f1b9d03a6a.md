# 中国的高校计算机教育存在哪些问题？ - 割风 的回答

## 阅读前置卡

- 价值判断：高。从数学基础、算法理论体系、系统项目实践和工具链四方面分析计算机教育，提供具体课程与学习经历作为例证，对理解课程短板有较高参考价值。
- 信息密度判断：中。有四项明确结论及相应解释，但穿插较多个人经历、情绪化评价和工具偏好，核心信息集中程度居中。
- 是否继续阅读：3 全文。值得阅读全文，理解各项教育问题的论证、实践项目的作用，以及理论教育不足并非国内外差距主要因素这一限定。

## 核心洞察

一、计算机知识大致分为四类：参考 CSRankings，计算机领域知识大致可以分为四类：理论计算机科学，包括算法、语义、密码学；系统，包括体系结构、操作系统、数据库、分布式系统；人工智能，包括视觉、自然语言处理、信息提取等；交叉领域，包括机器人、生物信息学、经济学、图形学。
[[#^pr-946e55ab7443|正文跳转]]

二、离散数学才是计算机的基础：我国本科数理教育将微积分（实分析）列为必学内容，它在传统工科中是不可不学的日常工具。但现代常见的计算机都是基于二进制的离散状态机，因此离散数学、组合数学和抽象代数才是计算机的基础。微积分当然有用，但更多是分析算法和概率模型的工具，学得再好也不能直接提高对计算机的认识水平。
[[#^pr-75ba1160f9af|正文跳转]]

三、基础课设置难奠定理论基础：大学里普遍有太多机械工业时代的老学究，擅长各种积分，其价值就是给大一学生念微积分课本、出考试难题。与此同时，很多计算机本科甚至没有在大一必修离散数学，抽象代数在几乎所有学校更是选修课；这直接导致本科计算机教育很难给学生奠定良好的理论基础。
[[#^pr-9406bb976ce4|正文跳转]]

四、课程只顾能教什么而非学生需要：很多学校的计算机系至今还要求学生在大二、大三必修两个学期的大学物理，如同大一数学分析的延续，不管对计算机有没有用都必须学。这种安排不在乎学生需要什么，只在乎教师能教什么。
[[#^pr-037cc1a377fd|正文跳转]]

五、数学教育重分析轻代数轻组合：代数和离散逻辑不仅是计算机的基础，更是整个数学大厦的基础。我国从中学到大学却花了太多时间在各种“解析”和“分析”上：一个能考上985的人，圆锥曲线算得很快、导数题做得很花，却连算术基本定理和代数基本定理都说不清楚。这种重分析、轻代数、轻组合的数学教育不能满足计算机科学的需要。
[[#^pr-8a204f4a68d4|正文跳转]]

六、算法课重具体算法轻理论体系：算法和数据结构是所有计算机系的必修核心课程，大部分学校也比较重视，但课程往往过于关注具体算法而忽视整个理论体系。期末考试要么上机写算法题，要么在纸面画二叉树，基本上都在考具体算法。认真上过这些课程的本科生，大都能说清楚几种O（nlogn）的排序算法，也能分析二叉搜索树为什么需要平衡。
[[#^pr-fc202eae0ca3|正文跳转]]

七、NP困难无意义论暴露理论欠缺：王垠以高次数多项式时间复杂度同样无法接受为由，断言把指数复杂度降为高次数多项式复杂度也毫无意义，进而认定NP困难问题本身无意义。这种判断展示了对算法理论体系认识的不足：不必研究复杂度理论，但凡认真读过CLRS，也不至于说出这样的话。
[[#^pr-40025a032ae0|正文跳转]]

八、其他理论选修课不在讨论重点：密码学、数理逻辑等其他理论计算机课程在国外也普遍是选修课，对一般计算机专业学生没有太多讨论价值，因此不在此展开。
[[#^pr-271916c36819|正文跳转]]

九、算法课重具体算法而轻体系：我国大学的算法数据结构课程过于关注具体算法，没有帮助学生认识整个算法理论体系。认真上过这些课程的本科生，用形式语言或伪代码系统讲解一个算法仍很困难，要讲清楚什么是NP困难问题以及为什么研究它，更是不可能。
[[#^pr-0d9b9e891c5e|正文跳转]]

十、理论不足并非国内外差距主因：我国计算机理论教育虽有很多不足，但由于高考的存在，名牌大学本科生的数理能力普遍碾压同档次欧美大学本科生，加上算法竞赛和数学竞赛在我国普及得非常好，理论教育不足并不是拉开国内外差距的主要因素；系统知识教育问题才是关键。
[[#^pr-af43212bdced|正文跳转]]

十一、系统知识连接模型与应用：计算机系统知识，是用人类普遍掌握的物理层面的工程方法，具体实现一个计算机模型，并在上面运行各种应用所需要的知识。
[[#^pr-76c6c5592d86|正文跳转]]

十二、体系结构解决速度与成本问题：现阶段实现计算机模型的工程方法是集成电路。用集成电路实现一个图灵机没有多复杂，但要实现快速、低成本的图灵机，就需要存储系统分层、流水线架构、多核心架构等复杂系统知识；这些知识大致构成计算机体系结构的主要内容。
[[#^pr-9c8337109ee7|正文跳转]]

十三、操作系统承接多应用多用户需求：快速高效的图灵机可以快速高效地运行一个程序，但现实中还需要一台计算机运行各种复杂应用、在不同应用间切换，甚至供多个用户使用，这些就是操作系统的功能。
[[#^pr-b9ad10259495|正文跳转]]

十四、系统知识回应现实需求：单台机器的算力总是有限，不同机器上的不同用户又有通信需求，因此产生了分布式系统和计算机网络。程序员总是希望拥有更好用、更高效的编程语言，因此编译器被发明了。
[[#^pr-602d3d054535|正文跳转]]

十五、系统知识必须大量动手实践：系统知识教授如何用简单元件实现复杂功能，是面向现实问题的工程知识，必须动手进行大量实践。国外一流大学的计算机科学课程中，体系结构课程肯定要实现一个CPU，操作系统课程要动手写操作系统，计算机网络课程要写路由器，编译原理课程要写编译器。
[[#^pr-ee3f78d6cc93|正文跳转]]

十六、课程大项目缺乏奖励却招投诉：课程大项目往往需要任课教师投入大量时间设计和维护，但我国大学向来不会因为教师设计了好的课程项目而给予奖励；让大家压力都很大的项目反而会在教务处招致大量投诉。这种投诉态度受到批评：即使写不了代码，也必须拿到计算机学位，并以自身能力弱为理由要求迁就。
[[#^pr-aae6f5fd4fcf|正文跳转]]

十七、有的系统课只考概念就能过：在自己不能设计项目的情况下，有的教师为了省事，把系统课程当文科教。例如操作系统课程只要求回答线程、进程和内存管理是什么，答得差不多就能通过，连教材也使用翻译本。
[[#^pr-ae41b48ecd09|正文跳转]]

十八、原样照搬项目让学生抄答案过关：有的教师不加任何修改地照搬国外一流大学的课程项目，因为修改也需要花大量时间研究项目本身。网上已有的题目也有现成答案，学生把程序抄来，看一看、改一改，就又混过一门课。
[[#^pr-ac07bf28f1da|正文跳转]]

十九、实践不足使毕业生难进复杂项目：我国大学计算机系统类课程的项目实践严重不足，导致毕业生对计算机系统没有深入认识，也缺少开发经验，作为程序员很难直接进入复杂项目。
[[#^pr-5a601c81762c|正文跳转]]

二十、LaTeX 与 Overleaf 用于书面作业：欧美大学至少在计算机系，基本上从本科阶段开始，大部分书面作业就使用 LaTeX。大部分人会直接在 Overleaf 上开设项目，支持多人共同编辑同一项目，对小组项目更加方便。
[[#^pr-c32844c23a01|正文跳转]]

二十一、报告与代码工具习惯存在差距：欧美大学的代码作业基本上在 GitHub 上维护。其他大学的情况不清楚，但在自己的本科学习中，大部分同学直到快毕业，都没有养成用 LaTeX 写报告、用 GitHub 维护代码的习惯。
[[#^pr-373fdef2e3a5|正文跳转]]

二十二、默认 Windows 导致 shell 不熟：国外导师对系统课编程项目基本默认在 Linux 上完成，顺便支持 macOS，选择性支持 Windows。国内大部分老师则默认在 Windows 上完成，这种习惯很不好，导致包括自己在内的很多同学本科毕业时仍不甚熟悉 Unix shell。
[[#^pr-9cabbf371709|正文跳转]]

二十三、欧洲同学动手能力强的亲身感受：在欧洲学习的亲身感受是，那边的同学动手能力真的很强。特别佩服的一位德国队友，笔记本只装 Linux，不用 Google，而使用一个已记不起名称、无广告且由非营利机构提供的搜索引擎；这样的工具选择还带来了对共产主义理论为什么先在德国产生的切身体会。
[[#^pr-24eef951d428|正文跳转]]

二十四、学计算机必须抛弃百度系产品：进入计算机系学习的同学，不管怎么样，都一定要抛弃百度系的任何产品：世界上没有比百度更糟糕的搜索引擎，哪怕使用 Bing 也好得多。
[[#^pr-b73422eab02e|正文跳转]]

25、按经济条件选择工具环境：有钱就直接使用 Mac，购买稳定的付费梯子；没钱就使用 Linux，自己蹭 AWS 服务器搭梯子。
[[#^pr-48d389a35be0|正文跳转]]

26、英文教材的使用体验与差异：教材是所有人都需要的工具。本科母校的数学和算法课程基本使用英文影印版教材，读起来舒服，还顺便提高了英语水平；系统类课程却都使用翻译本，令人感到可惜。原因并不明白，大概是因为理论课老师都是海归博士，而系统课老师都是本土出身。

[[#^pr-474efd856c0b|正文跳转]]

28、工具链落后使学习效率低下：由于系统性的问题，国内大学的计算机系普遍存在不同程度的工具链（教材）落后问题，使得学生学习效率低下。

## 正文

答主中上游985本，欧盟top硕，专业都是cs。 参加过noi，ccpc，在大厂混过，也算是能写代码，略懂算法的人。站在个人经历之上谈谈我国cs教育体系存在的不足。

谈到计算机领域的知识，参考[csranking](https://link.zhihu.com/?target=http%3A//csrankings.org/), 大致可以分为四类：

^pr-946e55ab7443

1.理论计算机科学（算法，语义，密码学）

2.系统（体系结构，操作系统，数据库，分布式系统）

3.AI（视觉，自然语言处理，信息提取等）

4.交叉领域（机器人，生物信息学，经济学，图形学）

就以上四个划分，答主逐一谈谈。

一. 理论知识

我国的本科教育，在数理层面，微积分（实分析）是必学的，这部分知识在传统工科中就是日常工具，不学不可。

但是现代常见的计算机都是基于二进制的（离散)状态机，因而，离散数学，组合数学，抽象代数才是计算机的基础。微积分有没有用呢？当然有，但对于计算机来说，微积分更多是分析算法和概率模型的一个工具，微积分学的再好也不能直接提高你对计算机的认识水平。

^pr-75ba1160f9af

遗憾的是，我们大学里普遍有太多机械工业时代的老学究，他们擅长各种积分，他们的价值就是给大一学生念微积分课本，出考试难题。关于离散数学，很多计算机本科甚至都没有在大一必修，抽象代数更是几乎所有学校都是选修的。这就直接导致我们的本科计算机教育很难给学生奠定良好的理论基础。

^pr-9406bb976ce4

遑论很多学校的计算机系至今还要在大二大三必修两个学期的**大学物理**，这就好像对大一数学分析的延续一样，不管对计算机有没有用，你都必须学，你需要什么，我不在乎，我只在乎我能教什么。

^pr-037cc1a377fd

**其实代数和离散逻辑不仅是计算机的基础，更是整个数学大厦的基础**，而我们的悲哀就在于从中学到大学花了太多的时间在各种“解析”和“分析”上，一个能考到985的人，圆锥曲线算的那叫一个快，导数题那叫一个花，但是让他谈谈算术基本定理，代数基本定理都说不清楚。

^pr-8a204f4a68d4

**结论一，我国的数学教育重分析轻代数轻组合，不能满足计算机科学的需要。**

再来看看计算机领域内的理论课程，算法和数据结构当然是所有计算机系的必修核心课程，大部分学校也都比较重视。但往往过于关注具体的算法而忽视整个理论体系。期末考试要么是上机写算法题，要么是纸面画二叉树，基本上都是考具体的算法。

^pr-fc202eae0ca3

认真上过算法和数据结构的本科生大都能给你说清楚几种O（nlogn）的排序算法，也能分析出二叉搜索树为什么需要平衡。

但是让他用形式语言或者伪代码系统地讲解一个算法就很困难，让他给你讲清楚什么是NP困难问题，以及为什么我们要研究NP困难问题就更是不可能了。关于这一点，著名的计算机民科王垠先生就向大家生动地展示过，“因为高次数的多项式时间复杂度同样是无法接受的，所以，即使能把指数复杂度降为高次数的多项式复杂度也是毫无意义的，也就是说NP困难问题本身是无意义问题。”不要求他研究复杂度理论，但凡认真读一读CLRS也不至于说出这样的话。

^pr-40025a032ae0

其他的理论计算机课程，比如说密码学，数理逻辑等在国外也普遍是选修的，对一般计算机专业的同学没有太多讨论价值，就不在这展开了。

^pr-271916c36819

**结论二，我国大学的算法数据结构课程过于关注具体的算法，从而没有帮助学生认识整个算法理论体系。**

^pr-0d9b9e891c5e

总的来说，我国的计算机理论教育有很多不足。但由于高考的存在，我国的名牌大学的本科生在数理能力上普遍碾压同档次的欧美大学的本科生，再加上各种算法竞赛，数学竞赛在我国普及的非常好，所以这方面的不足其实并不是拉开国内外差距的主要因素。下面要讨论的问题才是关键。

^pr-af43212bdced

二.系统知识

何为计算机系统知识呢？我的理解就是用人类普遍掌握的物理层面的**工程方法**，来具体实现一个**计算机模型**，并在上面运行各种**应用**所需要的知识。

^pr-76c6c5592d86

现阶段的工程方法当然就是**集成电路**了，用集成电路实现一个图灵机没有多复杂，但是要实现一个快速低成本的图灵机就需要很多复杂的系统知识，比如存储系统分层，流水线架构，多核心架构等。这些知识大致就是计算机体系结构的主要内容。

^pr-9c8337109ee7

当我们实现了一个快速高效的图灵机后，它可以快速高效的跑一个程序了。但现实中，我们需要一台计算机能跑各种复杂的应用，在不同应用间切换，甚至一台机器给多个用户使用，这就是操作系统的功能了。

^pr-b9ad10259495

再之后，由于一台机器算力总是有限的，同时， 不同用户在不同机器上存在通信需求，我们又有了分布式系统和计算机网络。

^pr-602d3d054535

程序员总是希望能有更好用更高效的编程语言，于是编译器被发明了。

总之，系统知识是教我们如何用简单的元件实现复杂的功能，是面向现实问题的工程知识。是必须要动手进行大量实践的。

^pr-ee3f78d6cc93

在国外的一流大学cs课程中，一门体系结构课程肯定是要实现一个cpu的，一门操作系统课程真的要动手写OS的，一门计算机网络课程是要动手写路由器的，一门编译原理课程是要动手写编译器的。

这些课程大项目往往需要课任老师投入大量的时间去设计和维护，但是我国大学向来不会因为老师设计了一个好的课程项目而给奖励。反而一个让大家压力都很大的课程项目会在教务处得到大量投诉，**“反正我写不了代码，我也必须要拿计算机学位，我弱我有理”。**

^pr-aae6f5fd4fcf

在自己不能设计项目的情况下，有的老师为了省事，咱就当文科学，比如操作系统课程，你就回答我啥是线程，啥是进程，啥是内存管理，答得差不多就过。连教材都用翻译本，反正咱就当文科上了。

^pr-ae41b48ecd09
