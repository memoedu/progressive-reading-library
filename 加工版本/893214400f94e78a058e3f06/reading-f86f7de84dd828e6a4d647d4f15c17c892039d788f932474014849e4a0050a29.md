## 核心洞察

一、交换后感到两校差距非常大：就读于浙江一所普通双非一本，大三上通过伯克利 BGA 项目交换一个学期；到伯克利后，感到两校的差距不是一点点大。
[[#^pr-79e849c542f9|正文跳转]]

二、念PPT与强制到课形成消耗：国内所在学校的教师照本宣科严重，上课就是念PPT，如同读操作说明书；缺席还会扣平时分，因此为了绩点不得不到课，到课又感觉非常浪费时间、学不到东西，这种处境如同“温水煮青蛙”，是慢性死亡。
[[#^pr-24e93646036c|正文跳转]]

三、重要课程没有连成知识体系：国内所在学校没有重视计算机知识体系的培养。不算物理、数学，大一上学C语言，大一下学C++和离散数学，大二上学数据结构、计算机网络和Java，大二下学计算机组成原理和数据库，大三上学操作系统、软件工程等。这些课程对计算机科学都非常重要，却只是被强行塞给学生，各门课成为没有连接起来的知识孤岛。
[[#^pr-52392675c9d3|正文跳转]]

四、教材落后、多错且讲解晦涩：国内所在学校的知识体系和教材落后，教材错误多：C语言仍用谭浩强的书，离散数学用学校自编教材，错误极多，老师甚至曾布置寻找教材错误的作业。数据结构用一本不知道具体名称、感觉没什么名气的外国教材；计算机组成原理用白忠英的书，计算机网络用谢希仁的书，两本都很枯燥，讲解很晦涩。
[[#^pr-31e536919026|正文跳转]]

五、实践不足，考试只考零散概念：国内所在学校的实践太少，计算机网络课简直像文科：上课念PPT，没有相关实践，考试只考数量特别多、特别零散的概念。在伯克利认识的一位西交大学生也有实践特别少的情况，实践不足大概是国内的通病。
[[#^pr-477385e5ce58|正文跳转]]

六、大学代码训练应是刻意练习：一个合格的程序员至少应在大学期间写五万到十万行代码，不是简单地堆砌代码，而是刻意练习。
[[#^pr-477385e5ce58|正文跳转]]

七、背 API 和案例也能考高分：国内所在学校的软件工程专业必修 Web 应用开发课，用 Java EE 编写 JSP、Servlet，考试却考 API，考试方式僵化。室友一个学期没怎么学，最后背背 API 和书上的案例，也考了90分。
[[#^pr-929903186987|正文跳转]]

八、工具视野局限于老师所教：国内所在学校的很多同学不会用 GitHub，不知道 Stack Overflow，对 UNIX/Linux 完全不了解，更不用说相关工具链。基本上老师教什么就用什么：Java 老师用 Eclipse 就跟着用，不知道 IDEA；C 语言老师用 VC++ 6.0 就跟着用。
[[#^pr-437e6e731bdd|正文跳转]]

九、伯克利课程有视频，亦有照读 PPT：伯克利一般的 CS 课都有视频，YouTube 上都能找到，即使不去上课也没有关系。也有教授只是照着 PPT 讲，例如交换期间的操作系统老师 Ion Stoica；这并非贬低他，他本人仍非常厉害。教授们都很厉害，基本都是业界大牛。
[[#^pr-3ff173752ef7|正文跳转]]

十、课堂讲授只是学习的一小部分：在国内时，学习一直被理解为上课好好听讲、下课做作业多练习；伯克利的教学资源非常强大，lecture 只是很小的一部分，很多课每周都有 lab 和 discussion，每隔几周还有一个大 project。一门课学生很多，例如 CS61A 这学期好像有1800多人，因此配套助教有几十位。每位助教带一个 discussion，并有 office hour 专门答疑；lab 中不会做的内容也可以直接问，助教会手把手教。
[[#^pr-85812ba6f705|正文跳转]]

十一、按应用方向组织课程内容：伯克利课程内容丰富、视野开阔，不会单独开一门 C 语言之类的课程，而是课程的应用方向是什么就教什么。例如大一上第一门编程课 CS61A，使用伯克利改编的 Python 版本 SICP 作为教材。
[[#^pr-0aecf9db919a|正文跳转]]

十二、入门课不止于语言语法：CS61A 大约两周讲完 Python 语法，随后学习高阶函数、lambda 函数和基本算法，配有大量反转链表、快排、二叉树路径生成与搜索练习，每个练习都有可在本地运行的测试例子。课程再讲面向对象编程，用大约一周讲完 Scheme 语法，介绍惰性求值、lambda 演算，并要求用 Python 实现 Scheme 解释器，体会命令式与函数式语言的不同；后续还涉及 SQL 与宏。函数式编程是交换学习中最喜欢的部分，但对相关内容的理解仍不到位。
[[#^pr-2f3694f07ae9|正文跳转]]

十三、用配套框架支撑项目实践：CS61A 每周基本有一至两次作业和一次实验，个人完成大概要花四小时以上，一个学期还有四个 project，代码框架搭得特别好。例如 Ants 项目要求实现类似《植物大战僵尸》的游戏，图形部分和基本游戏逻辑已经提供，学生负责各种蚂蚁单位与敌人的实现，完成后能对面向对象编程有一些了解。
[[#^pr-2f3694f07ae9|正文跳转]]

十四、基础课程构成后续学习体系：整个计算机科学体系的培养非常重要。伯克利一般 CS 学生大一上修 CS61A，大一下修数据结构 CS61B、离散数学与概率论 CS70，大二上修机器结构 CS61C；完成 61 系列与 CS70，基本完成低年级 CS 课程，此后可以选算法、操作系统、编译原理、图形学、机器学习等课程。
[[#^pr-a934ed3abd31|正文跳转]]

十五、从高层抽象逐步走向硬件：课程体系从计算机抽象的最高层逐步向底层推进，每一步都注重与先前所学结合：CS61A 通过 Python、Scheme、基本算法及大量作业实验建立编程基础，CS61B 用 Java 教数据结构，CS61C 再把抽象层次降到硬件。
[[#^pr-a82a1e96388b|正文跳转]]

十六、数据结构课快速转入算法：CS61B 用一至两周讲完 Java 语法，使学生能够编写基本算法。由于在国内学过数据结构，交换时没有选这门课，不了解具体情况；据认识的同伴说，课业压力也非常大，一次编写正则匹配算法的作业就花了很长时间。
[[#^pr-ca268a412b78|正文跳转]]

十七、组成原理落实到技术与CPU：CS61C 相当于计算机组成原理，用一至两周讲完 C 语言，随后学习 RISC-V 基本汇编指令、cache、浮点数等内容，实践涉及 Spark、OpenMP 和 Intel SIMD 指令，最终用课程提供的程序模拟实现一个简单 CPU。相比之下，国内就读学校的组成原理课只有理论，老师根本不会提这些技术。
[[#^pr-ca268a412b78|正文跳转]]

十八、学系统就应动手实现系统：学操作系统就应该写操作系统，学编译原理就应该写编译器。国内大部分高校这两门课容易教偏，理论大大多于实践，使学生没有兴趣；不过清北复交、南浙之类的一些顶尖高校应该教得很好。国内就读学校只在 XP 上用 Windows API 做简单实验，操作系统教学仍不用 UNIX/Linux；CS162 则要求修改教学操作系统 Pintos，虽然实现过程比较痛苦，也参考了其他组的文档，但收获非常大，这样才能真正理解操作系统，而不只是看书、背书、背概念。
[[#^pr-505c2ae3604d|正文跳转]]

十九、课程少不等于负担轻：伯克利也有水课，但很少，至少计算机专业课基本没有。学生基本每学期修三至四门课，每门三至四学分，整体课业负担比个人在国内修十二门课还大。
[[#^pr-05da89c0c41a|正文跳转]]

二十、不应为基础使用重复开课：伯克利不开无意义的课。Linux 使用没有必要单独开课，找一本鸟哥的书、查文档手册就可以直接上手；已经学过 C/C++ 等命令式语言后，仍专门开 Java 课，每周只讲变量、条件语句等基本语法，不去还扣分，这种安排值得批评。相比之下，伯克利开设的课基本没有轻松的，修完能感到学到了很多。
[[#^pr-add6b0f13623|正文跳转]]

二十一、有条件有能力尽量出国学：有条件、有能力的人，学计算机还是尽量出国。
