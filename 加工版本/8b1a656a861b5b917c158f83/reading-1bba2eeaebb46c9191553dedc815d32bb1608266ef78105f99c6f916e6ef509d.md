# 为什么现在吹Rust的人这么多？ - 锦恢 的回答

## 阅读前置卡

- 价值判断：中。回答以个人经验为主，对 Rust 优势的论述有具体例证，但缺乏系统论证和客观数据，价值中等。
- 信息密度判断：中。信息密度中等，包含 Rust 优势、嵌入式限制、入门门槛等要点，但夹杂个人吐槽和题外话。
- 是否继续阅读：2 概览与关键结论。适合概览 Rust 优势与局限，但深度有限，无需精细阅读。

## 核心洞察

一、Rust 是软件工程与编译原理的结晶：Rust 的设计融合了软件工程和编译原理领域数十年的理论与工程实践，学习多种语言后能在其中看到其他语言的影子，且熟练后很难找到明显缺点。
[[#^pr-1e95e6cd9d01|正文跳转]]

二、Rust 提升底层开发效率与安全性：相比 C++，Rust 能以更少人月完成底层软件开发，遵守规范可避免野指针导致的内存泄漏，编译器保证无畏并发，panic 时能精确定位出错文件行列，减少对调试器的依赖。
[[#^pr-f2fb900fcb6e|正文跳转]]

三、Cargo 简化构建与依赖管理：Rust 的 Cargo 工具链取代了复杂的 Makefile 和依赖配置，一条 cargo build --release 即可完成构建，降低了公司对资深程序员在依赖配置和跨平台编译方面的依赖。
[[#^pr-04aadbc1090c|正文跳转]]

四、Rust 生态完善支撑重写一切：经过数十年发展，Rust 社区生态已相当完善，甚至能找到 SystemVerilog 原型解析器框架，底层所需组件大多具备，为“Rust 重写一切”提供了技术基础。
[[#^pr-ff38b1ff987a|正文跳转]]

五、Rust 编译器自举利于定制化开发：Rust 编译器已完成自举，大量底层组件可直接修改源代码，配合 Cargo.toml 的 path 指定和 git submodule，可实现高度定制化开发，优于某些只能跳到存根文件的编程语言。
[[#^pr-cc37a924f558|正文跳转]]

六、Rust 正渗透软件栈底层：safe tensor、wasm 驱动的 egui 框架底层均为 Rust 实现，最新 WebGPU 据称也由 Rust 编写，显示 Rust 正逐步影响计算机软件栈生态。
[[#^pr-4716330e0af3|正文跳转]]

七、嵌入式领域 Rust 采用受限：嵌入式公司仍用 C/C++ 是因为厂商驱动库和 SDK 多为 C/C++，硬件技术栈变动慢且成本敏感，浅层嵌入式用不到 Rust；但未来自研板子和 FPGA 将提供 Rust SDK。
[[#^pr-4e033bb00779|正文跳转]]

八、Rust 进军嵌入式的四大障碍：经群友补充，Rust 难以进入嵌入式的原因包括：厂家难以自制 Rust 编译器且不愿适配 LLVM/GCC；编译产物体积对 MCU 不友好；原生底层库缺失或质量差；裸机开发可能需 nightly 特性，多数人不愿冒险。
[[#^pr-87d7a3eb64c5|正文跳转]]

九、Rust 入门门槛高：Rust 对新手极不友好，入门速度可能是常规语言中最慢的。作者学 Java 半天即可写 CRUD，但学 Rust 从部署教程到写含线程同步的解析服务器花了三天，cargo checker 的报错难以用大模型解决。
[[#^pr-449005d1b577|正文跳转]]

十、Rust 国内普及面临现实阻力：Rust 和 TypeScript 短期内难以在国内普及，因为部分从业者会为自身利益造势，且公司大规模技术栈变更代价高昂，用作品和社区影响力而非文章来反驳他人。
[[#^pr-03d175deef5d|正文跳转]]

## 正文

开门见山：**Rust 是积累了人类在软件工程学、编译原理等领域上数十载理论和工程细节智慧的结晶。** 是一门在学习熟练后，很难找到缺点的编程语言。如果你学习过 10 种以上的编程语言，并都做过项目，那么你会在 Rust 上面找到很多其他编程语言的影子。

^pr-1e95e6cd9d01

Rust 的整体设计相比于 C++，可以以更少的人月完成底层软件的开发，并且只要你遵守开发规范，开发出的软件不会因为野指针满天飞而内存泄漏；只要编译器不报错，放心地无畏并发；就算是出现 panic，八成也是因为你为了早点下班乱用 unwrap，rust release 模式下的 build 还会直接告诉你出错地点在哪一个文件的哪一行哪一列，生怕你太菜还在狼狈地找你那该死的调试器。真的，当你开始习惯调试器，计算机的很多领域就与你无缘了。

^pr-f2fb900fcb6e

开发者不再需要再折腾那该死的写成绝对路径的 SB Makefile，然后去项目的 issue 上用机翻的英文国粹口吐芬芳；公司也不再需要花费高额开支雇佣“经验老道”的程序员，仅仅因为他们可以完成其他人无法完成的依赖项配置和跨平台编译，现在一个 cargo build --release 直接完事。

^pr-04aadbc1090c

![](https://pic1.zhimg.com/50/v2-de658642c6b11f6ad92149ed549d0577_720w.jpg?source=2c26e567)

而且经过数十年的发展，Rust 的社区生态已经非常完善了，你连 system verilog 的原型解析器框架都能找到，还不止一个。基本上干底层要的组件，Rust 大部分都有，这也为“Rust 重写一切”的现象提供了技术基础。

^pr-ff38b1ff987a

Rust 编译器已经完成了自举，大量的底层组件安装后可以直接修改源代码，对于很多场景的高度定制化开发这是非常重要，不像某些编程语言，一路定义跳转，最终只到一个不明所以的存根文件，Cargo.toml 里面指定一下 package 的 path，和 git submodule 完美配合。

^pr-cc37a924f558

我一个人工智能研究者兼前端爱好者都知道 safe tensor / wasm 驱动的 egui 框架底层都是 rust 写的。最新的 webgpu 据说也是 rust 写的。你就可以看到 Rust 会如何慢慢影响计算机目前的软件栈生态。

^pr-4716330e0af3

搞嵌入式的朋友要站出来反驳了：为啥我们公司还在用 C/C++？因为厂商给的电机/驱动板/芯片的驱动库或者 SDK interface 大部分都是 C/C++，硬件领域的技术栈变动往往非常慢，因为成本敏感。而且大部分的浅层嵌入式其实就是把数字翻译一下输入电机，做个调制解调，用不到 Rust。不过放心，未来我制作的板子和 FPGA，一定会提供 Rust 的 SDK 的。

^pr-4e033bb00779

还是那句话，Rust 适合开发底层软件，嵌入式的驱动程序和顶层的人工智能胶水语言不在我的讨论范围内，要吵架请出门左拐。

> 2025.5.19，经群友 Kenji Mouri 补充，Rust 无法进军嵌入式还有如下几点：  
> \- 厂家没法手搓能用的 Rust 编译器，但是不想公开细节，更不想适配 LLVM 和 GCC 这种复杂框架  
> \- Rust 编译出来的二进制体积相对于 C/C++ 对 MCU 事务不友好  
> \- Rust 的原生实现的底层库没有，或者即使有也质量堪忧（譬如复杂嵌入式设备常用的文件系统解析库等）  
> \- 还有就是 Rust 的语言特性对于裸机整活很可能得开 nightly，而大部分人不会冒险用 nightly

^pr-87d7a3eb64c5

* * *

入门门槛的话，我个人认为 Rust 相对于其他常用编程语言对新手非常不友好，入门速度应该是常规编程语言中最慢的那一个，如果你是整天无所事事的带学生，真心建议你有空学习 Rust。我当初学习 java 到上手开始写 CURD，大概花了半天时间，但是 Rust，从我部署中文版本的 Rust 教程，到我开始入手写一个含有大量线程同步的形式语言解析服务器和异步调度器，花了整整三天，我一开始以为我可以像写 Java，C#，Swift 这些语言一样，只花半天学习就能入门的，结果 cargo checker 的各种我根本无法用大模型解决的报错直接教我重新做人——Rust，它很不一样。
