如果你不熟悉 1983 年的 database 世界，那么，当时的 `INGRES` 是 Stonebreaker 和 Wong 在伯克利开展的一个已被 commercialized 的 research project。`C-INGRES` 是 commercial versionn，而 `U-INGRES` 是 university version。`IDM*` 是 `IDM/500` database machine，也就是第一个被 widely used 的 commercial database machine；`dac` 带有一个“database accelerator”，而 `nodac` 则不带。`DIRECT` 是 DeWitt 于 1977 年启动的一个关于 database machines 的 research project。

在 Bitton 等人的工作中，Oracle 的 performance 显得格外 poor。

Larry Ellison 对这些 results 很不满意，据说他[曾试图让](https://starcounter.com/the-story-of-professor-dewitt/) [DeWitt 被解雇](http://www.citeulike.org/user/marclijour/article/6883245)。考虑到即便教授确实存在不当行为，要解雇他们也很困难，Ellison 因为某人在自己的领域开展 legitimate research 而成功让其被解雇的 probability 几乎为 zero。据说，在 DeWitt 没有被解雇之后，Larry 还禁止 Oracle 招聘威斯康星大学的毕业生，而 Oracle 则在其 EULA 中添加了一项 term，forbidding benchmarks 的 publication。多年来，许多主要的 commercial database vendors 都添加了一项 license clause，使得对其 database 进行 benchmarking 成为 illegal 的行为。

如今，Oracle 会招聘威斯康星大学的毕业生，但 Oracle 仍然 forbids 对其 database 进行 benchmarking。Oracle 那令人震惊的 poor performance，以及 Larry Ellison 的回应，都已载入史册；anti-benchmarking clauses 如今常被称为“DeWitt Clauses”，而且它们已经从 databases 扩散到了所有 software，从 [compilers](https://news.ycombinator.com/item?id=7306121) 到 cloud offerings[1](https://danluu.com/anon-benchmark/#fn:1)。

与此同时，Bitcoin users 已经创建了[用于暗杀的 anonymous markets](http://rt.com/news/bitcoin-assassination-market-anarchist-983/) -- users 可以将钱投入一个资金池，由它向杀死特定目标的刺客支付报酬。

Anonymous assassination markets 看起来像个笑话，但用于 benchmarks 的 anonymous markets 又如何呢？想要知道某个 database 在特定 workload 下能提供何种 performance 的人，可以将钱投入一个资金池，由它向 runs the benchmark 的人支付报酬。

在目前的情况下，你经常会看到一些评论和博客文章，说某人原本在使用 `postgres`，直到管理层让他们 switch 到“某个 commercial database”，而后者的 performance 要差得多；这时很难判断，那个糟糕的 database 究竟是 Oracle、MS SQL server，还是其他某个 database。

如果我们看看如今主要的 commercial databases，就会发现 commericial databases 的三大厂商中有两家 forbid publishing benchmarks。Microsoft 的 SQL server eula 写道：

> 未经 Microsoft 的 prior written approval，你不得 disclose 任何 benchmark test 的 results……

Oracle 写道：

> 未经 Oracle 的 prior consent，你不得 disclose 任何 Program benchmark tests 的 results

IBM 值得一提，因为它确实 allowing benchmarks：

> Licensee 可以向任何 third party disclose 关于 Program 或其 subcomponents 的任何 benchmark test 的 results，前提是 Licensee (A) publicly discloses 该 benchmark test 所使用的 complete methodology（例如 hardware 和 software setup、installation procedure 以及 configuration files），(B) 在其 Specified Operating Environment 中 running 该 Program，使用 IBM 或提供 IBM products 的 third parties（“Third Parties”）为该 Program 提供的最新 applicable updates、patches 和 fixes，来 performs Licensee 的 benchmark testing，并且 (C) 遵循该 Program 的 documentation 以及 IBM 为该 Program 提供的 support web sites 上所有可获得的 performance tuning 和“best practices”指导……

这为人们提出一个 meta-argument 提供了依据：IBM 很可能比 Oracle 或 Microsoft 都能 delivers better performance，因为它是唯一一家不害怕人们 publishing benchmark results 的公司；不过，如果我们能有 actual numbers，那就好了。

In case you're not familiar with the database universe as of 1983, at the time, `INGRES` was a research project by Stonebreaker and Wong at Berkeley that had been commercialized. `C-INGRES` is the commercial versionn and `U-INGRES` is the university version. `IDM*` are the `IDM/500` database machine, the first widely used commercial database machine; `dac` is with a "database accelerator" and `nodac` is without. `DIRECT` was a research project in database machines that was started by DeWitt in 1977.

In Bitton et al.'s work, Oracle's performance stood out as unusually poor.

Larry Ellison wasn't happy with the results and it's said that he [tried to have](https://starcounter.com/the-story-of-professor-dewitt/) [DeWitt fired](http://www.citeulike.org/user/marclijour/article/6883245). Given how difficult it is to fire professors when there's actual misconduct, the probability of Ellison sucessfully getting someone fired for doing legitimate research in their field was pretty much zero. It's also said that, after DeWitt's non-firing, Larry banned Oracle from hiring Wisconsin grads and Oracle added a term to their EULA forbidding the publication of benchmarks. Over the years, many major commercial database vendors added a license clause that made benchmarking their database illegal.

Today, Oracle hires from Wisconsin, but Oracle still forbids benchmarking of their database. Oracle's shockingly poor performance and Larry Ellison's response have gone down in history; anti-benchmarking clauses are now often known as "DeWitt Clauses", and they've spread from databases to all software, from [compilers](https://news.ycombinator.com/item?id=7306121) to cloud offerings[1](https://danluu.com/anon-benchmark/#fn:1).

Meanwhile, Bitcoin users have created [anonymous markets for assassinations](http://rt.com/news/bitcoin-assassination-market-anarchist-983/) -- users can put money into a pot that gets paid out to the assassin who kills a particular target.

Anonymous assassination markets appear to be a joke, but how about anonymous markets for benchmarks? People who want to know what kind of performance a database offers under a certain workload puts money into a pot that gets paid out to whoever runs the benchmark.

With things as they are now, you often see comments and blog posts about how someone was using `postgres` until management made them switch to "some commercial database" which had much worse performance and it's hard to tell if the terrible database was Oracle, MS SQL server, or perhaps another database.

If we look at major commercial databases today, two out of the three big names in commericial databases forbid publishing benchmarks. Microsoft's SQL server eula says:

> You may not disclose the results of any benchmark test ... without Microsoft’s prior written approval

Oracle says:

> You may not disclose results of any Program benchmark tests without Oracle’s prior consent

IBM is notable for actually allowing benchmarks:

> Licensee may disclose the results of any benchmark test of the Program or its subcomponents to any third party provided that Licensee (A) publicly discloses the complete methodology used in the benchmark test (for example, hardware and software setup, installation procedure and configuration files), (B) performs Licensee's benchmark testing running the Program in its Specified Operating Environment using the latest applicable updates, patches and fixes available for the Program from IBM or third parties that provide IBM products ("Third Parties"), and (C) follows any and all performance tuning and "best practices" guidance available in the Program's documentation and on IBM's support web sites for the Program...

This gives people ammunition for a meta-argument that IBM probably delivers better performance than either Oracle or Microsoft, since they're the only company that's not scared of people publishing benchmark results, but it would be nice if we had actual numbers.
