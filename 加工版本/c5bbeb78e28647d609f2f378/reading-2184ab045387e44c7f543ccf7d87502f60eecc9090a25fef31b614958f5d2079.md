# Why I'm taking operating systems

---

## 正文

有几个人问我，这学期为什么要上一门关于 operating systems 的课。他们大概是因为我正式学的是 math，而 systems programming 又非常 un-theoretical，才这样问。不过，我之所以觉得这个决定特别棒，有几个原因。第一个（无需解释）是，这绝对是我上过的教得最好的 CS 课。第二个原因更有意思：了解 abstractions 在实践中如何 work，真的很有帮助。

Operating systems 和 math 课程从根本上说，都是在 building 一层层的 abstractions，让你能做 increasingly complex 的事情。在 math 中，这体现为像 [category theory](http://en.wikipedia.org/wiki/Category_theory) 这样 extremely general 的 tools；而在 operating systems 中，我们最终得到的是 [incredibly deep functional stacks](http://upload.wikimedia.org/wikipedia/commons/5/5b/Linux_kernel_map.png)。

无论哪种情况，想法都是：在每个 level，你巧妙地把在 lower levels 上 work 的 ideas 进行 bundle together，实质上将大量工作 compress 成更容易装进脑子里、却同样 effective 的东西。因为人类的 working memory 不多，一旦我们把正在使用的 ideas 进行了 compressed，就能更 efficiently 地思考。

例如，没有 high-powered mathematical abstractions，我们就绝不可能 prove 像 Fermat’s Last Theorem 这样的东西。仅仅通过将 proof 使用的所有 abstractions 进行 expanding out，化为关于 natural numbers 的 basic statements，给出一个“elementary”的 proof 或许在 technically 上是 possible 的。但那个 proof 会比我们现有的还要庞大骇人——庞大到根本不可能有人真正想得出来。同样，如果 programmers 每次想 copy 一个 string 时，都得 rewrite libc，他们就永远做不出什么来。

区别在于，mathematicians 不必真正 execute 他们的 proofs 中的 tools。因此，他们可以自由地仅根据 expressive power 来 pick abstractions。另一方面，如果你 write 一个 operating system，就必须考虑与你的 abstractions 有关的所有实际困难：它们容易 implement 吗？performance overhead 是多少？它们会在多大程度上 [leak](http://www.joelonsoftware.com/articles/LeakyAbstractions.html)？这些问题在 math 中往往被掩盖过去。但如果你想 write 能快速完成困难任务的 code，就必须习惯在 computer 中的每个 level of abstraction 上思考，从在 processor 周围 moving 的 electrons，一直到像 Python interpreter 这样的东西。因此，我很期待这学期从实践的角度了解 abstractions。

## 原文

A couple people have asked me why I’m taking a course on operating systems this term. Presumably they ask because I’m officially studying math and systems programming is very un-theoretical. But there are a couple reasons why I think it was an awesome decision. The first (which needs no explanation) is that it’s definitely the best-taught CS course I’ve taken. The second, and more interesting, is that it’s really helpful to learn how abstractions work in practice.

Operating systems and math classes are both fundamentally about building towers of abstractions that let you do increasingly complex things. In math, this manifests as extremely general tools like [category theory](http://en.wikipedia.org/wiki/Category_theory), while in operating systems we end up with [incredibly deep functional stacks](http://upload.wikimedia.org/wikipedia/commons/5/5b/Linux_kernel_map.png).

Either way, the idea is that at each level, you bundle together ideas that work at lower levels in clever ways that essentially compress a lot of work into something that is easier to fit in your brain, but just as effective. Because humans don’t have much working memory, we can think much more efficiently once we’ve compressed the ideas we’re using.

For example, without high-powered mathematical abstractions we would never have been able to prove something like Fermat’s Last Theorem. It might be technically possible to give an “elementary” proof, just by expanding out all the abstractions that the proof uses into basic statements about the natural numbers. But that proof would be even more monstrous than our current one—so huge that nobody could have actually come up with it. Similarly, programmers could never get anywhere if they had to rewrite libc every time they wanted to copy a string.

The difference is that mathematicians don’t have to actually execute the tools in their proofs. So they’re free to pick abstractions based solely on expressive power. On the other hand, if you write an operating system, you have to worry about all the practical difficulties associated with your abstractions: are they easy to implement? What’s the performance overhead? How much will they they [leak](http://www.joelonsoftware.com/articles/LeakyAbstractions.html)? These are issues that get swept under the rug in math. But if you want to write code that does hard things fast, you have to be comfortable with thinking at every level of abstraction in your computer, from electrons moving around your processor up to something like a Python interpreter. So I’m excited to get the practical take on abstractions this semester.
