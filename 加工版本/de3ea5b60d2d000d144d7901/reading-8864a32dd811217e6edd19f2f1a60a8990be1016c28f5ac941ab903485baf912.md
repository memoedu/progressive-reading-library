# Mini Blog Post 21: Taking the first step — Neel Nanda

---

## 正文

### 引言

我之前的很多文章都在谈 prioritisation 和 planning——我们很容易陷入采取不 lead to 自己的 goals 的 actions 这一陷阱，而 predict 和 avoid 这一点极其重要。但另一项关键 skill 是 _implementation_ \- 从 _knowing_ 应该采取哪些 actions，到真正 _doing_ 一些事情。我们很容易觉得深受鼓舞，觉得自己有了方向，但最终却毫无进展。因此，培养 **get shit done** 的能力至关重要。

我是个严重的 procrastinator，也是个 perfectionist，所以默认情况下，我很不擅长这一点。我发现自己很容易一直拖延，一想到要开始就觉得 overwhelmed。或者，因为没有 getting started 而感到 guilt，却又始终觉得不够 _urgent_，不足以让我为此做些什么。接着，要么错过 deadlines，要么把一切留到最后一刻，直到 pressure 越积越大，最后敷衍了事。这是 _极其_ sub-optimal 的，但基本上就是我的默认生活状态。在这篇文章中，我会尝试概述自己用来克服这些 failure modes 的一些 tools，尤其关注 _getting started_——这是我最常失败的环节。

我的底层 model 已在[之前关于 systems 的文章](https://www.neelnanda.io/blog/mini-blog-post-19-on-systems-living-a-life-of-zero-willpower)中概述：**willpower** 是一种 limited resource。当我们有一项令人不快的 task 要做时，开始之前会有一道 barrier，有一份需要付出的 **activation energy**。而 deadlines 和 obligations 带来的大量 **mental pressure**，最终会促使我们付出所需的 willpower，越过这道 barrier。这引出了两种显而易见的 approaches，我会在前半部分概述——increasing mental pressure，以及 lowering activation energy。这也解释了我为什么关注 _getting started_ \- activation energy 与我继续做一项 task 所需付出的 costs 并不是一回事，其中存在显著的 **switching costs**；而如果我已经进入一项 task 的 flow，就会有 inertia 推动我继续。

我觉得，我们也很容易陷入只会 [pushing the Try Harder button](https://www.neelnanda.io/blog/mini-blog-post-6-stop-pressing-the-try-harder-button) 的陷阱——更加努力，投入更多 effort，却只采用最显而易见、最容易想到的方式。世界纷繁复杂，往往存在一些 creative solutions，能在 _不_ incurring 这些 costs 的情况下 achieve 我们的 goals。但你需要 zoom out，有时还得超越自己的 instincts，才能找到它们。因此，在后半部分，我会尝试概述一些更 creative 的 solutions，它们在当下未必显得自然。

### 更加努力（Trying Harder）

增加 pressure（Increasing pressure）

我发现 deadlines 是一种强有力的 motivator——我经常会 procrastinate 一阵子，直到 deadline 逼近，产生一种 _urgency_。但这个过程中会有大量无谓的折腾。下面是一些能更 effectively 地利用这种 pressure 的 tools

**健康警示：**我觉得，依靠很高的 mental pressure 来促使自己做事的 motivation system 相当 unhealthy——我不喜欢把 guilt 作为自己 motivation system 的核心基础，而且我觉得这在很多重要方面阻碍了我。如果你对此有共鸣，我强烈推荐阅读概述另一种 approach 的[这一系列文章](http://mindingourway.com/guilt)。但这 _确实是_ 一套对我有效的 system，学会如何用好它也有价值。而且，从实际情况来看，有些人在基于 pressure/guilt 的 systems 下确实表现得很好！如果这些想法让你感兴趣，我建议试一试；但如果觉得它们对你不起作用，或者让你不开心，就停下来。

-   创建 deadlines（Creating deadlines）——deadlines 是一种相当强大的 pressure，因此，如果你能 create _artificial_ deadlines，那就是一项很棒的 skill！

    -   首先可以试试的，就是直接决定把某个时间当作 deadline！有些人能让这种办法奏效，但我很难做到——对我来说，它没有真实感

    -   为你的工作日 Add structure

        -   我按 50 minute pomodoros 来工作，并尝试为每个 pomodoro 给自己 set 一个 target，在结束时检查完成得如何——对于 unfocused pomodoros，我常常会在后半段突然感到一阵 deadline pressure。

        -   一般来说，好的 deadlines 给人的感觉是 **clear** 而且 **concrete** \- 你应该很难钻空子逃避一个 deadline。Structure 让这样的 deadlines 更容易建立起来

    -   我非常喜欢能 automatically lock 我的 laptop 的 software——通过把 laptop 设置为在睡觉时间 lock，它能阻止我熬通宵，并把 _那个时间_ 变成 deadline

-   **Accountability：**让 deadlines 更难摆脱——setting artificial deadlines 对我来说很难，因为它们显得虚假而空洞；另一项 skill，就是让它们显得真实

    -   向他人作出承诺（Social commitment）

        -   很多时候，只要把一个 commitment 告诉朋友，它就会显得更真实！

    -   Public accountability（硬核版）——公开发布自己的 deadline

        -   这可能让人觉得 aversive，因为感觉自己在 _打扰_ 别人

    -   Financial accountability（硬核版）——如果没赶上 deadline，就设定一项 financial penalty

        -   像 [Stickk](https://www.stickk.com/) 和 [Beeminder](https://www.beeminder.com/) 这样的网站会 automatically enforce deadline，而且有许多 tools，让你更难钻空子逃避 deadline

        -   这一点 _极其_ 因人而异——人们往往觉得这些办法相当 stressful，有些人讨厌它们，另一些人却觉得它们无比宝贵（我从没让它们在自己身上很好地奏效）

-   另一种 approach，是给 artificial deadlines 加上 _meaningful_ consequences！

    -   约好在真正的 deadline 之前，对朋友的工作进行 peer-review——这样就有了一个带有 _meaning_ 的 artificial deadline

    -   每当我在准备 talk 或 workshop 时，我都喜欢约好提前几天和朋友做一次 trial run——这样就有了一个 meaningful deadline！

-   为浪费时间的 _costs_ 建立 intuition

    -   我发现自己很容易把事情拖到 _超过_ 最后一刻，还用“没关系，deadline 还没到”来为自己的所有 procrastination 辩解

    -   底层的 error 在于，浪费时间会有 **opportunity costs** \- 我本可以在那段时间做其他自己重视的事情。而且，[opportunity costs 并不让人觉得 concrete](https://www.neelnanda.io/blog/mini-blog-post-15-the-illusion-of-doing-nothing)。

    -   所以，一种 solution 就是 _建立_ 更 concrete 的 intuitions！我发现，经常练习 time estimates 并 calibrating 自己很有帮助，这能让事情给人的感觉更加 _visceral_，而这对于 shaping 我当下的 actions 很重要

-   我们很容易 _无限期_ 拖延事情 \- 我尝试建立这样的 mental habit，问自己：“如果我 _永远_ 不做这件事，我会惊讶吗？”

    -   由此产生的感觉比我那颗 procrastinating 的大脑可靠得多，也更能让我集中注意力

降低 activation energy（Lowering activation energy）

另一种 naive approach，是 **lower 开始所需的 energy**。

对我来说，很难开始做事有几个常见原因：

-   它让人觉得 _overwhelming_ \- task 很 big，而且 monolothic、confusing，我不知道从哪里开始

-   **Analysis paralysis**：我陷在不断 prioritising 和 planning 的状态中

    -   底层的要点是——**planning 和 doing 会用到我脑中不同的部分**。当我试图同时做两者时，我就会僵住，哪件事都做不好

-   一个相关的想法：**babble** 与 **prune**。如果我想做到 creative，就需要 generate 好的 ideas。但在“这必须是好的”这一 filter 存在的情况下 generating，是 _很难的_——我会陷入 perfectionism。因此，solution 就是把它们 separate！

    -   **Babble** 是 generation step——我自由地 generate ideas，不考虑 quality

    -   **Prune** 是 filtering step，我逐一查看 generated ideas，并 select 其中好的那些

    -   归根结底，babbling 和 pruning 会 use 我脑中不同的部分；如果我尝试同时做两者，就会陷入 switching costs

一种极其强大的 tool，能用来 lowering 开始做事所需的 energy，就是 **setting 5 minute timers**。如果我想开始做一项 task 中的一小部分，我就 set 一个 5 minute timer，并告诉自己：“我有接下来的 5 minutes 来完成这件事。”我发现这是一种非常强大的 tool，因为它让我专注于 _doing_。这段时间足够短，让我能持续专注于具体的 task，并 short-circuits 那种“这是对我时间的最佳利用吗”的怀疑。它也让我更 creative——time pressure 足够强，让我没有时间进行充分的 planning 和 prioritisation，因此更容易进入一种更 free-flow 的 mode，并 break out of 自己陷入的任何 local maxima。

一个有用的 hack：让 set 一个 5 minute timer 这件事 _真的_ 足够 low friction，这样你就能把转瞬即逝的行动冲动转化为 action。对我来说，只需要说“Alexa, 5 minute timer”。

这些方法该怎么用？

-   留意一项 task 什么时候让你觉得 overwhelming、让你感到 stuck，然后 set 一个 timer 来“plan，并把 task break down 成 concrete actions”

    -   timer 让我专注于 planning，而不是 doing，因此没那么 overwhelming。我没有足够的 _时间_ 陷入 option paralysis！

    -   _大量_ energy 都花在 overcoming option paralysis，以及弄清 _如何_ 开始上。如果我有一个 concrete starting point，就更容易投入其中并 make progress

-   如果我不知道该做什么，而且觉得 stuck，就 set 一个 timer 来“brainstorm 可能的 next steps”

    -   设一个 _只用于 babbling_ 的 timer 往往很有帮助 \- 尽可能多地 generate creative ideas，不考虑 quality

        -   timer 有助于让我专注于“_重点_ 是以 unfiltered 的方式 generate”

    -   之后，我可以 prune——这一步通常很容易

    -   我发现，这样做通常至少能找到一个真正让我感兴趣的 creative solution——往往直接沿着它做下去就有效，而不必 analysing 它是否是 _最佳的_ solution

-   即使 task 已经显得更 concrete，它往往仍然有 _一点_ overwhelming，这时 recurse 可能会有帮助

### Zooming Out：跳出局部看全局

这些想法是我在 stuck 时，为了 making progress 而尽量记住的基本 tools。但重要的是，要记住我的 goal 是 **get shit done**。人极其容易用“[try hard](https://www.neelnanda.io/blog/mini-blog-post-6-stop-pressing-the-try-harder-button)”这个 proxy goal 来 _substitute_ 它，但这很少是 achieve 我的 goals 的最佳方式。然而，感到 pressured 和 stressed 会让我变得相当 short-sighted，很难清楚地记住这一区别。因此，建立能够 _强迫_ 我 Zoom Out 的 systems 很有用，因为我很难在当下作出正确判断

休息一下

有件令人费解的事——当我在某件事上 procrastinating，而且我 _知道_ 自己在 procrastinating 时，我可以一连花上几个小时做 low priority 的事，同时感到有点 guilty。但如果直接放下手头的事，休息一下，去做些真正能让我 rejuvenating 的事，却会觉得 _不对_。然而，empirically，如果我花半小时散步、读一本好书，或和朋友聊聊天，往往回来时 headspace 会 _很好_，也会感到 energised，能够取得 genuine progress——这对我的 _所有_ goals 都是好事。

即使我确实休息了，也经常感到 guilty，觉得自己还不够 trying hard。你 _绝不_ 应该因为 taking the optimal action 而感到 guilty！guilt 的 purpose 是确保你在自身 limits 的 constraints _之内_，take better actions

归根结底，人生是一场马拉松，而不是短跑。从 short-term、着眼于短跑的 perspective 来看，休息 _感觉_ 不对，而这正是我在 pressure 下的感受，但这对我真正的 goals 并无意义。

因此，我希望生活在自己会更多休息的 worlds 中。而我的 default algorithm 是“当我觉得休息是个好主意时就休息”，这显然正在 failing。所以我需要改变这个 default algorithm。我目前的做法是建立 [robust systems](https://www.neelnanda.io/blog/mini-blog-post-19-on-systems-living-a-life-of-zero-willpower)，确保自己在 pomodoros 之间进行能让我 rejuvenating 的休息。此外，还要训练这样一种 habit：察觉自己在原地打转、感到 overwhelmed 时，就 reflexively 离开书桌，休息一下。如果感到 resistance，就看看笔记本电脑上方的便利贴，提醒自己为什么这是一个好的 policy。

一种有用的 framing：我可以生活在两种 possible worlds 中。在 **relaxed world** 中，只要事情让我感到有点 overwhelming，或者我注意到自己没有 making progress，我就休息。在 **stressed world** 中，我 _不_ 休息，只是不停逼迫自己，直到事情终于有了进展。然而，还有第三种幻想中的 world，即 **optimal world**，在那里，我会立刻 take 那些自己一直拖着不做的 actions。而 optimal world 并不存在，striving for 它只会 results in stressed world。但我 _感觉_ 它存在，也 _感觉_ 自己是在 comparing relaxed world 和 optimal world。而我选择不让 [pleasant fantasies 阻碍我实现自己的 goals](https://www.neelnanda.io/blog/mini-blog-post-13-beliefs-are-for-true-things)。

Expanding working memory：扩展工作记忆

事情会让人感到 overwhelming，还有一个原因——人类的 working memory 是 _strongly_ limited。一些 experiments 表明，我们只能同时在脑中 hold 大约 4 个 concepts。这意味着，如果我们试图同时在脑中 hold 更多内容，就会觉得事情 overwhelming、stressful，而且 high energy。这也是为什么 planning 和 doing _不_ 应该同时进行的部分原因——这会 exceeds 我的 working memory。我们很容易把这看作 weakness，并因此感到沮丧，但这显然不是！这是我们 brain’s architecture 的 fundamental consequence，为此感到沮丧，就像因为自己无法向空中跳起一米而感到沮丧一样——这在 physically 上是不可能的。

_相反_，正确的应对方式是寻找办法，_expand_ 我的 working memory。寻找把 thoughts 移到脑外的办法，让它们不那么 overwhelming，也更容易 process。我发现，每当自己 stuck 时，下面这些技巧都很有用：

-   把我的 thoughts 以文字形式 Brain-dump 出来

    -   我建立了一个 reflex，所以每当注意到自己“没有 Making Progress”时，就开始 brain-dump 自己 _为什么_ 感到 stuck，以及究竟发生了什么

        -   [Dynalist Pro](https://dynalist.io/) 让我可以在任何 window 中按 CTRL+SHIFT+I，把 text add 到我的 inbox；我发现这对于保持这件事的 low friction 很有价值

        -   在这里，你需要让自己的 thoughts 感觉 free-flowing。我发现，使用一种让人感觉很容易 edit、也容易挪动 ideas 的 writing medium 很有用，这样就不会害怕犯错

            -   这是“把 planning 和 doing separate” 的另一个 application

            -   我发现，[Roam](https://roamresearch.com/)、[Workflowy](https://workflowy.com/) 或 [Dynalist](https://dynalist.io/) 这样的 outlining software，在这方面 _棒极了_

-   和朋友聊聊

    -   这是另一种强迫你把 thoughts 用 words 表达出来的方式，而且没那么刻意

        -   通常，一旦用 words 表达出来，obvious mistakes 或 understanding 中的 holes 就会变得 clear！

    -   另一个人的 perspective，可能有助于 exposing 你 thinking 中的 holes、blind spots、你正在犯的 mistakes 等

        -   通常，_他们_ 觉得 obvious 的 advice，是我根本没有想到过的！

    -   注意：对方能否有效地帮助你 work through 自己的 problems，也需要相当的 skill。我发现，大多数人的帮助都远胜于没有帮助，但努力建立良好的 norms 和 environment 仍然很有用！

        -   确保对方是你能自在地与之谈论一些尴尬、傻气的事情的人——一个让你能放心展露 vulnerable 一面的人

        -   他们的 goal 是帮助 _你_ understand 这个 problem，而不是 solve 它——[你们的 minds 是 different](https://www.neelnanda.io/blog/mini-blog-post-14-minds-should-make-sense)，如果他们忽略了这一点，就可能认为一个 difficult problem 有着 obvious solution

-   Rubber duck debugging：小黄鸭调试法

    -   和朋友聊天可能并不容易——human labour 很昂贵，而且需要朋友时，往往不容易找到他们。那为什么不用一只小黄鸭代替朋友呢！

    -   seeking advice 的很大一部分 value，其实只是把 thoughts 用 words 表达出来——我发现，在桌上放一只小黄鸭，在对某件事感到 confused 时对它说话很有用。这比按理说应有的帮助 _大得多_！

注意：对于所有这些 techniques，minimise 从“注意到自己 stuck／事情正在 exceeding 我的 working memory”到 applying 这些 techniques 之间的 friction，_真的_ 很有用——这会大大提高你使用它们的可能性。把纸和小黄鸭放在手边。如果可以，就和朋友一起 co-working，在休息时聊聊 problems——确保 seeking advice 是 easily accessible 的！

对 question 进行 Reframe

开始做一件令人害怕的事时，很多 resistance 可能来自 fear of failure，或对 risks/costs 的恐惧。我发现，这 _特别_ 令人 paralysing——世界是 complex 的，所有 actions 都有 downsides。而且默认情况下，[我的 mind 会 overweights 那些 costs](https://www.neelnanda.io/blog/mini-blog-post-15-the-illusion-of-doing-nothing)。在一个 _ideal_ world 中，我会进行 cost-benefit analysis，进行 [prioritise](https://www.neelnanda.io/blog/2glo4ww7hd035m56cc5l7zq9r7bxhc)，然后 choose 最佳 action。但我的 intuitions 对此并不是一个好的指引，而要进行 robust calculation 又太 complicated。

我用来 short-circuiting 这一过程的主要 tool，是 **改变 question**。我根本无法 answer“这是不是 short-term 内的最佳 choice”这个 question。因此，如果我仍想能够 take 这样的 actions，就需要改变自己正在 answering 的 question。让它关乎 _action_，而不是 consequences。让自己无论 outcome 是 _什么_，都能感到高兴！我常用的做法有：

-   让 task 关乎 [**changing my self-image**](https://www.neelnanda.io/blog/become-a-person-who-actually-does-things)——做这件事，会让我更接近自己想成为的那种人吗？一个 competent、brave、kind 或 interesting 的人会做这种事吗？

    -   这种事确实有效——taking 那些稍微超出我 comfort zone 的 actions

-   让 task 关乎 **gaining a skill** \- 如果我开始一个令自己兴奋的 ambitious programming project，那么它能否 works 并不 _重要_——到最后，我的 programming 水平会好得多。怎么都不会输！

-   让 task 关乎 **gaining information**。明确地把它 frame 为一个 [experiment](https://www.neelnanda.io/blog/the-value-of-experiments)。

    -   一句不错的 mantra：**Failure 只是另一个 data point**

    -   我发现，这是一个 _极其_ powerful 的 technique，能帮我 break out of local optima，尝试新事物。

    -   例如，我最近正在写一场 [talk](https://www.facebook.com/events/2861328290657229/)，却一直 procrastinating，迟迟没有尽快整理出一个 rough version。我想到，可以尝试为每个 sub-chapter 各用 10 minutes 制作 slides。这似乎不够久，我也感到了很大的 resistance，但我决定为了 experiment 而试一试。结果，这对 clarifying 我关于 structure 的 thoughts，以及让它变得 concrete，_真的_ 很有用！

-   为 _别人_ 做这件事。我发现，身处一个 group 中，看到其他人都因为太尴尬而不愿行动时，我更容易 take the social initiative——_我的_ awkwardness 感觉只像一个 background factor

-   我在关于 [intrinsic motivation](https://www.neelnanda.io/blog/mini-blog-post-11-live-a-life-you-feel-excited-about) 的文章中，更详细地讨论了这些 tactics

让 uncertainty 成为一个 _background_ thought

一种有趣的 approach，是想象自己 _master_ 了 getting shit done 这门艺术，会是什么样子。而 mastery 的感觉，往往与刚开始时 qualitatively different。比如，刚接触 maths 的某个 area 时，我会感到很犹豫。我不确定自己在做什么，不断 second-guess 自己、check definitions，也不确定该做什么。我感觉，要 make progress 就得 _try harder_，而有一天，我会拥有大量 knowledge，能够妥善 tackle 这种 uncertainty。

然而，看看我 _确实_ 擅长的 maths areas，比如我大一时修过的 pre-requisite courses，感觉却并非如此。感觉我只是 **do the obvious thing**。这并不是说我知道 _一切_——maths 是 complicated 而 messy 的，我仍会遇到 edge cases。但这种 uncertainty 和 confusion 感觉像一个 _background thought_——我并没有把注意力放在它上面，只是在 doing the obvious thing，因为我已经逐渐建立了良好的 intuitions。这类似于教一名低年级学生时的 mindset——我的 mind 并没有 focused on uncertainty 和 confusion，而是 focused on 帮助他们、answering 他们的 questions。我的 uncertainty 是一个 **background thought**。

而且我发现，在感到 stuck 时，这是一个值得追求的 goal！我知道，我的 [intuitions contain valuable information](https://www.neelnanda.io/blog/mini-blog-post-20-emotions-are-bayesian-evidence)，尽管默认情况下，我感觉很 stuck，我的 intuitions 告诉我放弃。但妥善 accessing intuitions 是一种 skill，并不会自然而然地发生。我发现，在这里，access 这些 intuitions 的正确方式往往是大声 explain 情况，详细地把它讲一遍，然后说：“**什么是 obvious next step?"** 我发现，seeking advice 或 rubber duck debugging 往往正是在做这件事——给我另一种 access 这些 intuitions 的方式。

而 mastery 按 definition 来说，就是困难的！这些 intuitions 并不总是 accurate。但我发现，把这个 goal 记在心里很有帮助！有时，当我越过 activation energy 的 barrier 后，就会开始 reflexively doing the obvious thing。我认为，这在很大程度上正是 [**flow states**](https://en.wikipedia.org/wiki/Flow_\(psychology\)#:~:text=In%20positive%20psychology%2C%20a%20flow,the%20process%20of%20the%20activity.). 的 characteristic。

Nate Soares 在[这里](http://mindingourway.com/stop-trying-to-try-and-try/)非常出色地 outlines 了这一点

切换 motivation source

用 deadlines 和 pressure 来 motivating 我自己的 underlying problems 之一，在于这是一种 **guilt-based motivation**。我的脑海里有一堆 cached rules，也就是我必须遵守的 obligations。而这_确实_ work，却让我感到不开心。而且它需要一段时间，感觉像是在对自己使用 mental force，总体上对我不好。而它让我感觉不好的这个事实，是 [important evidence，不应该被忽略！](https://www.neelnanda.io/blog/mini-blog-post-20-emotions-are-bayesian-evidence)

相比之下，通过 **intrinsic motivation** 来做 tasks 虽然困难，但也是可能的——对它们感到特别兴奋！我在[这里](https://www.neelnanda.io/blog/mini-blog-post-11-live-a-life-you-feel-excited-about)概述了自己对此的一些粗浅想法，Nate Soares 也有一个[真正出色的系列](http://mindingourway.com/guilt)，讨论该如何应对这一问题。而 shifting motivation sources 很困难，也并非总能 work，不过我有几个 techniques 可以帮上忙：

-   让它变得 social！就我个人而言，我发现，和别人谈论一个 task 时，更容易对它感到兴奋（注意：这一点可能因人而异）

    -   在 coworking 时，我发现，先向对方描述自己为什么对这个 task 这么来劲，很有帮助

    -   对于持续时间较长的 projects，我会尽量在和朋友聊起它时，尽情聊聊其中让我着迷的东西

-   进行 Introspect——“我为什么对此感到兴奋？”“如果我不做这件事，会发生什么？”

    -   guilt-based motivation 的一个 underlying problem，是它把“我需要做的事情” stores 为 _obligations_。我不再对它进行 reasoning，也不再 prioritising；它现在成了我_必须_完成的事情。对我来说，这往往源于一种需要掌控一切的心态，以及不相信自己在没有这种掌控的情况下也能把事情做完。

    -   但这很傻，因为这个 task 往往确实就是我眼下能做的最好的事情！（如果不是，[你是否在 prioritising correctly？](https://www.neelnanda.io/blog/prioritisation)）

    -   要 unlock intrinsic motivation，我就需要始终立足于这个 action 将如何 achieve 我的 goals！

    -   我发现，set 一个 timer，比如 2 minutes，并试着真正 _visualise_ 这个 action 将如何 achieve 我的 goals，很有价值。为什么做这件事会让我更开心，让我更接近自己想生活于其中的世界？

        -   或者，visualise 一个我_不_做这件事的世界，然后问：“为什么这个世界不好？”

    -   这样做常常能让我获得一阵 motivation，而几个小时的 guilt 都做不到！

        -   这种感觉往往指向 project 的某个具体部分；我发现，不管这份 curiosity 和 excitement 把我引向哪里，跟着它们走都很有帮助，而不是陷入 prioritising 之中

这也能帮助应对 procrastination。尤其对于没有实际 deadline 的 tasks，比如给一位有段时间没联系的朋友发消息，很容易一拖再拖。我把这称为 **myth of doing it later**——从 empirically 来看，当我这样做时，我往往_永远_都不会去做那个 task！

这又是一个我在对 fantasy worlds 进行 reasoning 的例子：

-   World 1：我现在就做

-   World 2：我永远不做

-   World 3：我在 optimal time 做（而那总是在以后！）

从 Empirically 来看，World 3 并不存在。而 choosing world 3 实际上就是 choosing world 2。也许那_确实_是正确的选择！但直接沿用 default decision 是不好的——我应该越过 world 3，问自己：“这是我想_现在就_做的事，还是_永远不_做的事？”

而这种 reframing 往往就足以 unlock 一些 intrinsic motivation——我意识到，自己_确实_真正在乎这个 task 是否完成！而做这件事也不再像是在工作。

### 结语

我认为，getting shit done 是一项_非常_有价值的 skill。我在这篇文章中概述了一组相当零散的 tools——它们都很个人化，也很 subjective，但我希望其中至少有一个让你觉得有趣，值得尝试！在实践中，我发现，setting 5 minute timers、decoupling planning 和 doing、把我的 thoughts 倾倒到 text 中，以及 reframing the question，对我最有价值。如今，它们也成了我 workflow 中相当 core 的部分。

关于 getting shit done 这项 skill，有一个令人难过的事实：你最没有能力使用它时，恰恰是它最有用的时候。在你有点累、工作让你感到 overwhelming、觉得自己 stuck 的那些日子里，要记得 apply 一种不熟悉的 technique，_很难_。它从来都不显得_必要_。我最需要休息的时候，恰恰是我最不愿意休息的时候，因为我已经一整天都行动迟缓、进度落后了。

这并不意味着它不可能做到，而是意味着你需要用不同的方式去 learn 它。如果这些 techniques 要真正对你有用，它们就需要成为你 mental toolkit 中 reflexive 的部分，而不只是有趣的 ideas。它们需要能在当下 override 你原有的 intuitions。

而这需要时间，也需要 practice。试试这些 techniques，即使感觉_并不_必要，也看看什么对你有用。进行 Minimise friction，并安排好你的 workflow，让你_能够_以 minimal effort 使用它们。刻意尝试它们，即使 getting started 只是_有一点_ effortful，也看看它们是否对你有用。如果确实有用，就试着_处处_使用它们，直到它能成为一种 reflex！

如果这让你觉得有点太 high effort、没有必要，而且似乎并不能真正帮上忙，那么——这听起来就像是一个你正难以 get started 的 hard task。我建议 reframing the question——把这当作一个 experiment，试一种新的 technique，看看你能从中 learn 什么。从这个角度来看，failure 从一开始就不再是一个 meaningful idea。

## 原文

### Introduction

A lot of my previous posts have been about prioritisation and planning - it’s easy to fall into the trap of taking actions that don’t lead to your goals, and extremely important to predict and avoid this. But another key skill is _implementation_ \- going from _knowing_ the actions to take, to actually _doing_ anything. It’s easy to feel inspired, and to feel as though you have direction, but for this to ultimately go nowhere. So it’s vital to cultivate the ability to **get shit done**.

I’m a massive procrastinator, and a perfectionist, so by default I’m pretty bad at this. I find it very easy to perpetually put things off, and feeling overwhelmed at the thought of starting. Or, feeling guilt centred around not getting started, but it never quite feels _urgent_ enough to do anything about it. And to then either miss deadlines, or leave everything until the last minute, where the pressure builds up, and then I end up doing a half-assed job. This is an _incredibly_ sub-optimal, but is essentially the default state of the world for me. In this post, I will attempt to outline some of my tools for getting past these failure modes, and especially focusing on _getting started_ - the point where I most often fail.

My underlying model is outlined in my [previous post on systems](https://www.neelnanda.io/blog/mini-blog-post-19-on-systems-living-a-life-of-zero-willpower): **willpower** is a limited resource. When we have an unpleasant task to do, there’s a barrier to starting, an **activation energy** we need to spend. And we have a bunch of **mental pressure** from deadlines and obligations that eventually get us to spend the required willpower to get past this barrier. This motivates two obvious approaches which I’ll outline in the first half - increasing the mental pressure, and lowering the activation energy. And explains why I focus on _getting started_ \- activation energy isn’t the same thing as what it costs me to continue working on a task, there are significant **switching costs**, while if I’m already in the flow of a task I have inertia behind me.

I think it’s also easy to fall into the trap of just [pushing the Try Harder button](https://www.neelnanda.io/blog/mini-blog-post-6-stop-pressing-the-try-harder-button) - trying harder and putting more effort in, but in the most obvious and accessible ways. The world is messy and complicated, and there are often creative solutions that achieve our goals _without_ incurring these costs. But you need to zoom out, and sometimes move past your instincts to find them. So in the second half I’ll try to outline some of the more creative solutions, that don’t quite feel natural in the moment.

### Trying Harder

Increasing pressure

I find deadlines are a powerful motivator - I’ll often procrastinate for a while until a deadline looms, and creates a sense of _urgency_. But this involves a ton of wasted motion along the way. Here are some tools for using this pressure more effectively

**Health Warning:** I think a motivation system built upon high mental pressure getting me to do things is pretty unhealthy - I dislike having guilt as the central basis of my motivation system, and I think this holds me back in significant ways. If this resonates with you, I highly recommend reading [this series](http://mindingourway.com/guilt) outlining an alternate approach. But this _is_ a system that works for me, and it is useful learning how to use it well. And empirically some people thrive under pressure/guilt based systems! I recommend trying these ideas if they seem interesting, but stopping if it feels like something that isn’t working for you, or is making you unhappy.

-   Creating deadlines - deadlines are a pretty powerful form of pressure, so if you can create _artificial_ deadlines, that’s an awesome skill!

    -   The first thing to try is just deciding something is a deadline! Some people can make this work, though I struggle - it doesn’t feel real to me

    -   Add structure to your work-day

        -   I work in 50 minute pomodoros, and try to set myself a target for the pomodoro, and check in on how that went at the end - for unfocused pomodoros, I often feel a burst of deadline pressure in the second half.

        -   Generally, good deadlines feel **clear** and **concrete** \- it should be hard to weasel your way out of a deadline. Structure makes it easier to build these

    -   I am a big fan of software to automatically lock my laptop - this stops me pulling all-nighters, by setting my laptop to lock at my bedtime, and makes _that_ the deadline

-   **Accountability:** Make deadlines feel stickier - setting artificial deadlines is hard for me because it feels fake and insubstantial, another skill is making them feel real

    -   Social commitment

        -   Often just telling a commitment to a friend makes it feel more real!

    -   Public accountability (hardcore) - post publicly about a deadline

        -   This can feel aversive because it feels like you’re _bothering_ people

    -   Financial accountability (hardcore) - set a financial penalty if you don’t make the deadline

        -   Websites like [Stickk](https://www.stickk.com/) and [Beeminder](https://www.beeminder.com/) will automatically enforce the deadline, and have a bunch of tools to make it harder to weasel out of the deadline

        -   This is _strongly_ your mileage may vary - people tend to find these pretty stressful, some people hate them, while some people find them invaluable (I’ve never got it to work well for me)

-   Another approach, attaching _meaningful_ consequences to artificial deadlines!

    -   Arrange to peer-review a friend’s work in advance of the true deadline - this is now an artificial deadline with _meaning_

    -   Whenever I’m writing a talk or workshop, I like to set a time a few days before when I’ll do a trial run with a friend - this is now a meaningful deadline!

-   Building intuition for the _costs_ of wasted time

    -   I find it easy to leave things _beyond_ the last minute, and to justify all my procrastination as “it doesn’t matter, the deadline isn’t here yet”

    -   The underlying error is that wasted time has **opportunity costs** \- other things I value which I could have been doing there. And [opportunity costs don’t feel concrete](https://www.neelnanda.io/blog/mini-blog-post-15-the-illusion-of-doing-nothing).

    -   So, a solution is to _build_ more concrete intuitions! I’ve found it useful to practice regular time estimates and calibrating myself, this makes things feel a lot more _visceral_, which is important for shaping my actions in the moment

-   It’s easy to put things off _indefinitely_ \- I’ve tried to build the mental habit of asking myself “am I surprised if I _never_ do this?”

    -   The resulting feeling is a lot more reliable than my procrastinating brain, and can focus me much more

Lowering activation energy

An alternate naive approach is to **lower the energy required to start**.

For me there are a few common reasons it’s hard to start things:

-   It feels _overwhelming_ \- the task is big, and monolothic, and confusing, and I don’t know where to start

-   **Analysis paralysis**: I’m caught up in constantly prioritising and planning

    -   The underlying point - **planning and doing take different parts of my brain**. When I try to do both at once, I freeze up and do neither well

-   A related idea: **babble** vs **prune**. If I want to be creative, I need to generate good ideas. But generating, with the filter of “this must good” in place, is _hard_ - I fall into perfectionism. So the solution is to separate them!

    -   **Babble** is the generation step - I generate ideas freely, with no concern for quality

    -   **Prune** is the filtering step, I go through the generated ideas and select the good ones

    -   Ultimately, babbling and pruning use different parts of my brain, and if I try to both at once, I get mired in switching costs

An extremely powerful tool for lowering the energy to get started on things is **setting 5 minute timers**. If I want to get started on a small piece of a task, I set a 5 minute timer and tell myself “I have the next 5 minutes to get this done”. I find this a very powerful tool, because it focuses me on _doing_. It’s such a short period of time, that I can remain focused on the specific task, and it short-circuits the “is this the best of my time” doubts. And it makes me a lot more creative - there’s strong enough time pressure that I don’t have time for proper planning and prioritisation, and so it’s easier to enter a more free-flow mode, and break out of whatever local maxima I’m stuck in.

Useful hack: Make it _really_ low friction to set a 5 minute timer, so you can convert the fleeting impulse to action into action. For me, I just need to say “Alexa, 5 minute timer”.

How to use these?

-   Notice when a task feels overwhelming, and you feel stuck, and set a timer to “plan, and break the task down into concrete actions”

    -   The timer focuses me on planning, rather than doing, so it’s less overwhelming. I don’t have enough _time_ for option paralysis!

    -   A _lot_ of energy goes into overcoming option paralysis, and figuring out _how_ to start. If I have a concrete starting point, it’s much easier to dig in and make progress

-   If I don’t know what to do, and feel stuck, set a timer to “brainstorm possible next steps”

    -   It’s often good to have a timer for _just babbling_ \- generate as many creative ideas as I can, with no concern for quality

        -   The timer is useful for focusing me on “the _point_ is to generate in an unfiltered way”

    -   Afterwards, I can prune - this step is normally easy

    -   I find that doing this normally finds at least one creative solution that feels actually interesting - often it works to just run with that, rather than analysing whether it’s the _best_ solution

-   Even when the task feels more concrete, it’s often still a _bit_ overwhelming, and it can be useful to recurse

### Zooming Out

Those ideas are the basic tools I try to keep in mind for making progress when stuck. But it’s important to remember that my goal is to **get shit done**. It’s extremely easy to _substitute_ this for the proxy goal of “[try hard](https://www.neelnanda.io/blog/mini-blog-post-6-stop-pressing-the-try-harder-button)”, but this is rarely the best way to achieve my goals. But feeling pressured and stressed makes me pretty short-sighted, and it’s hard to keep this distinction crisply in mind. So it’s useful to have systems in place that will _force_ me to Zoom Out, because I struggle to make the right call in the moment

Take breaks

A mystery - when I’m procrastinating about something, and I _know_ I’m procrastinating, I can spend hours on end doing low priority things and feeling a bit guilty about it. But it feels _wrong_ to just give up and take a break, to go off and do something I’ll find properly rejuvenating. While, empirically, if I take half an hour to go for a walk, or read a good book, or chat with a friend, I can often return in a _great_ headspace, and feel energised to make genuine progress - this is a win for _all_ of my goals.

Even when I do take breaks, I often feel guilty, and like I’m not trying hard enough. You should _never_ feel guilty for taking the optimal action! The purpose of guilt is to ensure you take better actions, _within_ the constraints of your limits

Ultimately, life is a marathon, not a sprint. Taking breaks _feels_ wrong, from the short-term, sprint focused perspective, which is how I feel when under pressure, but this is not meaningful for my true goals.

Thus, I want to live in worlds where I take more breaks. And my default algorithm is “take breaks when I feel like it’s a good idea”, which clearly is failing. So I need to change this default algorithm. My current approach is to have [robust systems](https://www.neelnanda.io/blog/mini-blog-post-19-on-systems-living-a-life-of-zero-willpower) to ensure that I take rejuvenating breaks between pomodoros. And further, to train the habit of noticing when I’m going in circles, and feeling overwhelmed, and to reflexively step away from my desk and take a break. And if I feel resistance, to look at a post-it above my laptop, reminding me of why this is a good policy.

A useful framing: There are two possible worlds I can live in. In the **relaxed world**, I take breaks whenever things feel a bit overwhelming, or I notice that I’m not making progress. In the **stressed world**, I _don’t_ take breaks, I just keep pushing myself until things eventually happen. Yet, there’s a third, fantasy world, the **optimal world**, where I immediately take the actions I’m putting off. And the optimal world does not exist, and striving for it just results in the stressed world. But it _feels_ like it does, and it _feels_ like I’m comparing the relaxed world and the optimal world. And I choose not to let [pleasant fantasies hold me back from my goals](https://www.neelnanda.io/blog/mini-blog-post-13-beliefs-are-for-true-things).

Expanding working memory

Another reason things can feel overwhelming - humans have _strongly_ limited working memory. Some experiments indicate we can only hold about 4 concepts in our head at once. And this means that if we’re trying to hold more in our head at once, things feel overwhelming, and stressful, and high energy. This is part of why planning and doing should _not_ be done at the same time - this exceeds my working memory. And it’s easy to see this as weakness, and feel frustrated, but this clearly is not! This is a fundamental consequence of our brain’s architecture, and feeling frustration is like feeling frustrated at not being able to jump a metre into the air - this is not physically possible.

_Instead_, the correct response is to find ways to _expand_ my working memory. Find ways to take thoughts outside my head, less overwhelming, and easier to process. I find these tricks highly useful any time that I’m stuck:

-   Brain-dump my thoughts into text

    -   I have a reflex set up, so every time that I notice I am “Not Making Progress”, I start to brain-dump _why_ I feel stuck, and what’s actually going on

        -   [Dynalist Pro](https://dynalist.io/) lets me add text to my inbox by pressing CTRL+SHIFT+I from any window, I’ve found this valuable for keeping this low friction

        -   You want your thoughts to feel free-flowing here. I find it useful to use a medium for writing that feels very easy to edit, and move ideas around in, so there’s no fear of making mistakes

            -   This is another application of “separate planning & doing”

            -   I find outlining software, like [Roam](https://roamresearch.com/), [Workflowy](https://workflowy.com/) or [Dynalist](https://dynalist.io/) are _awesome_ for this purpose

-   Talk to a friend

    -   This is another, less artificial way to force you to put your thoughts into words

        -   Often obvious mistakes, or holes in your understanding become clear when put into words!

    -   Another person’s perspective can be valuable for exposing holes in your thinking, blind spots, mistakes you’re making, etc

        -   Often, the advice _they_ think is obvious isn’t something that occured to me!

    -   Note: There’s a significant skill on the other person’s end of helping you work through your problems effectively. I find most people are a lot better than nothing, but it’s useful to try to create good norms and a good environment!

        -   Ensure it’s someone you feel comfortable talking about somewhat embarrassing and silly things to - somebody you’re comfortable being vulnerable around

        -   Their goal is to help _you_ understand the problem, not to solve it - [your minds are different](https://www.neelnanda.io/blog/mini-blog-post-14-minds-should-make-sense), and if they miss this, they may think a difficult problem has an obvious solution

-   Rubber duck debugging

    -   Talking to a friend can be hard - human labour is expensive, and it’s often hard to get access to a friend when you need them. So why not replace the friend with a rubber duck!

    -   A good chunk of the value from seeking advice is just putting thoughts into words - I find it valuable to keep a rubber duck on my desk, and speak to it when I feel confused about something. This is _way_ more helpful than it has any right to be!

Note: With all of these techniques, it’s _really_ useful to minimise friction between “noticing I’m stuck/things are exceeding my working memory” and applying the techniques - this makes you much more likely to use them. Keep paper and a rubber duck handy. If possible, do co-working with a friend and chat about problems during breaks - ensure seeking advice is easily accessible!

Reframe the question

A lot of resistance to starting something scary can be fear of failure, or fear of risks/costs. I find this _super_ paralysing - the world is complex, and all actions have downsides. And by default, [my mind overweights the costs](https://www.neelnanda.io/blog/mini-blog-post-15-the-illusion-of-doing-nothing). In an _ideal_ world, I’d do a cost-benefit analysis, [prioritise](https://www.neelnanda.io/blog/2glo4ww7hd035m56cc5l7zq9r7bxhc), and choose the best action. But my intuitions are a poor guide to this, and it’s too complicated to do a robust calculation.

The main tool I have for short-circuiting this is to **change the question**. I fundamentally cannot answer the question “is this the best choice in the short-term”. So if I want to be able to take such actions anyway, I need to change the question I’m answering. Make it about the _action_, not the consequences. Make it so that I’m happy no matter _what_ the outcome is! Common ways I do this:

-   Make the task about [**changing my self-image**](https://www.neelnanda.io/blog/become-a-person-who-actually-does-things) - does doing this bring me closer to the kind of person I want to be? Is this the kind of thing someone competent, brave, kind, or interesting would do?

    -   This kind of thing really works - taking actions that are a bit outside my comfort zone

-   Make the task about **gaining a skill** \- if I start an ambitious programming project that I feel pumped about, it doesn’t _matter_ if it works - at the end of the day I’m much better at programming. There’s no way to lose!

-   Make the task about **gaining information**. Explicitly frame it as an [experiment](https://www.neelnanda.io/blog/the-value-of-experiments).

    -   A good mantra: **Failure is just another data point**

    -   I find this an _incredibly_ powerful technique to break out of local optima and try new things.

    -   Eg, I’m currently writing a [talk](https://www.facebook.com/events/2861328290657229/), and procrastinating on getting a rough version together ASAP. And I had the idea of trying to make the slides for each sub-chapter in 10 minutes each. And this didn’t seem long enough, and I felt a lot of resistance, but I decided to do it for the sake of experiment. And this turned out to be _really_ useful for clarifying my thoughts on the structure, and making it concrete!

-   Do it for somebody _else_. I find it much easier to take the social initiative when I’m in a group, and can see everyone else feels too awkward to - _my_ awkwardness feels like a background factor

-   I elaborate more on these kinds of tactics in my post on [intrinsic motivation](https://www.neelnanda.io/blog/mini-blog-post-11-live-a-life-you-feel-excited-about)

Make uncertainty a _background_ thought

One interesting approach is to imagine what it would like to _master_ the art of getting shit done. And mastery often feels qualitatively different from when you start out. When I’m new to an area of maths, say, I feel very hesitant. I’m not sure what I’m doing, I constantly second-guess myself, check definitions, and feel uncertain about what to do. And I feel like the way to make progress is to _try harder_, and that one day I’ll have a big pool of knowledge and can properly tackle this uncertainty.

Yet, when I look at the areas of maths I _am_ good at, like pre-requisite courses I did in first year, it doesn’t feel like that. It feels like I just **do the obvious thing**. It’s not that I know _everything_ - maths is complicated and messy, and I still run into edge cases. But this uncertainty and confusion feels like a _background thought_ - it’s not something I’m paying attention to, I’m just doing the obvious thing, because I have good intuitions I’ve built up. It’s similar to the mindset of teaching a younger student - my mind isn’t focused on uncertainty and confusion, I’m focused on helping them, and answering their questions. My uncertainty is a **background thought**.

And I find this a valuable goal to aim for when I feel stuck! I know that my [intuitions contain valuable information](https://www.neelnanda.io/blog/mini-blog-post-20-emotions-are-bayesian-evidence), though by default I feel pretty stuck, and my intuitions tell me to give up. But accessing intuitions well is a skill, not something that just happens by default. And I find here, that often the right way to access these intuitions is to explain the situation aloud, talk through it in detail, and say “**what is the obvious next step?"**. And I find this is often what seeking advice, or rubber duck debugging is doing - it’s giving me another way to access these intuitions.

And mastery is, by definition, hard! These intuitions aren’t always accurate. But I find that having this goal in mind is helpful! And that sometimes, when I’ve got past the barrier of activation energy, I will start reflexively doing the obvious thing. I think this is much of what characterises [**flow states**](https://en.wikipedia.org/wiki/Flow_\(psychology\)#:~:text=In%20positive%20psychology%2C%20a%20flow,the%20process%20of%20the%20activity.).

Nate Soares outlines this point excellently [here](http://mindingourway.com/stop-trying-to-try-and-try/)

Switching motivation source

One of the underlying problems with motivating myself with deadlines and pressure is that this is **guilt-based motivation**. I have a bunch of cached rules in my mind, obligations that I must follow. And this _does_ work, but makes me feel unhappy. And takes a while, feels like I’m using mental force on myself, and is generally bad for me. And the fact that it feels bad for me is [important evidence, and shouldn’t be ignored!](https://www.neelnanda.io/blog/mini-blog-post-20-emotions-are-bayesian-evidence)

In contrast, it’s difficult but possible to do tasks by **intrinsic motivation** \- feeling super excited about them! I outline my rough thoughts on this [here](https://www.neelnanda.io/blog/mini-blog-post-11-live-a-life-you-feel-excited-about), and Nate Soares has a [genuinely excellent series](http://mindingourway.com/guilt) on what to do about this. And shifting motivation sources is difficult, and doesn’t always work, but I have a few techniques that help here:

-   Make it social! I, personally, find it much easier to be excited about a task when talking to somebody else about it (note: your mileage may vary on this one)

    -   When coworking, I find it useful to begin by describing to the other person why I’m pumped about this task

    -   For longer projects, I try to make a point of geeking out about it when chatting to friends about it

-   Introspect - “why am I excited about this?” “What will happen if I don’t do this?”

    -   An underlying problem with guilt-based motivation is that it stores “things I need to do” as _obligations_. I’m not reasoning about it, or prioritising, it’s now something I _need_ to get done. For me, this often comes from a place of needing to be in control, and not trusting myself to get things done otherwise.

    -   But this is dumb, because often the task is genuinely the best thing I can be doing right now! (And if it isn’t, [are you prioritising correctly?](https://www.neelnanda.io/blog/prioritisation))

    -   To unlock intrinsic motivation, I need to remain grounded in how this action will achieve my goals!

    -   I find it valuable to set a timer for, say, 2 minutes, and try to really _visualise_ how this action will achieve my goals. Why will doing this make me happier, and bring me closer to a world I want to live in?

        -   Or, visualise a world where I _don’t_ do it, and ask “why is this world bad?”

    -   Often doing this can give me a burst of motivation, that hours of guilt don’t!

        -   Often this is directed at a specific part of the project, I find it’s useful to follow this curiosity and excitement wherever it leads, rather than getting caught up in prioritising

This can also help with procrastination. Especially for tasks with no actual deadline, eg messaging a friend I haven’t spoken to in a while, it’s easy to perpetually put it off. I call this the **myth of doing it later** - empirically, when I do this, I often _never_ get round to the task in question!

This is another case where I’m reasoning about fantasy worlds:

-   World 1: I do it right now

-   World 2: I never do it

-   World 3: I do it at the optimal time (which is always later!)

Empirically, World 3 does not exist. And choosing world 3 is really choosing world 2. And maybe that _is_ the right call! But it is bad to just go with the default decision - I should look past world 3, and ask myself “is this something I want to do _right now_, or _never_”.

And often this reframing is enough to unlock some intrinsic motivation - I realise that I genuinely _do_ care about whether the task is done! And doing it no longer feels like work.

### Conclusion

I think that getting shit done is a _really_ valuable skill. I’ve outlined a pretty scattershot set of tools in this post - they’re all pretty personal and subjective, but I hope that at least one stood out as interesting, and worth trying out! In practice, I find setting 5 minute timers, decoupling planning and doing, dumping my thoughts into text, and reframing the question are the most valuable for me. And are now pretty core parts of my workflow.

A sad truth of the skill of getting shit done is that this skill is most useful when you’re least able to use it. On the days when you’re a bit tired, the work feels overwhelming and you feel stuck, it’s _hard_ to remember to apply an unfamiliar technique. It never feels _necessary_. The times I most need a break are the times when I’m least willing to take one, because I’ve spent an entire day being slow and behind.

This doesn’t mean it’s impossible, but it means that you need to learn it in a different way. If these techniques will be truly useful to you, they need to become reflexive parts of your mental toolkit, not just interesting ideas. Something that can override your old intuitions in the moment.

And this is something that takes time, and practice. Try these techniques out, even when it _doesn’t_ feel necessary, and see what works for you. Minimise friction, and set up your workflow so you _can_ use them with minimal effort. Make a point of trying them out, even if getting started is just a _bit_ effortful, to see if they work for you. And if they do work for you, try to use them _everywhere_, until it can become a reflex!

And if that feels a bit too high effort and unnecessary, and something that wouldn’t really help, well - that sounds like a hard task you’re struggling to get started on. I recommend reframing the question - make this an experiment, try a new technique, and see what you can learn from it. And from that point of view, failure ceases to be a meaningful idea in the first place.
