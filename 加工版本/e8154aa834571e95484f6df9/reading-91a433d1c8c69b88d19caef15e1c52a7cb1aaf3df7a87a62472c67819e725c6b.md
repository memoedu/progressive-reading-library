# Learning J

## 正文

我最近觉得，自己已经太久没有自学一门随意挑来的冷门 programming language 了。（其实大概有五年了。天哪！）于是，我开始学习 [J](http://www.jsoftware.com/)。J 是 [APL](https://en.wikipedia.org/wiki/APL_%28programming_language%29) 的 descendant，而 APL 出名主要是因为输入它时要用到世界上最疯狂的 character set：

![世界上最疯狂的 character set。](https://upload.wikimedia.org/wikipedia/commons/9/9f/APL-keybd2.svg)

APL 用这些 characters 作为你可能想要的每一种 array manipulation primitive（以及 array manipulation primitives 的 higher-order function）的 one- and two-letter mnemonics，而且还要再多出大约 10x。J 就像是不需要 custom keyboard 也能编写的 APL。

J 与常见的 functional language 有什么不同？最有意思的大概是 functions 如何工作。大多数 programming languages 使用 standard functional syntax：带有 comma-separated arguments 的 prefix notation。相比之下，J _只有_ unary prefix operators 和 binary _infix_ operators，而且 function notation 更加 linguistically structured（甚至把 functions 称作 _verbs_）。

对于 complicated architecture-astronautics，这不如 prefix-paren notation 好用，但它允许使用简洁的 primitives 来进行 function combination（例如 [forks](http://www.jsoftware.com/jwiki/Vocabulary/fork) 和 [hooks](http://www.jsoftware.com/jwiki/Vocabulary/hook)），弥补了这一点，而这些在其他 languages 中是无法 parse 的。例如，你可以把一个 average function define 为 `average =: +/ % #`——应读作“average 是 running sum divided by length”。这里使用一个 _fork_（`_ ? _`，其中左边和右边的 verbs 是 unary，中间的是 binary）和一个 _adverb_（`/`，相当于“fold”或“reduce”），用一行（并且以 [tacitly](https://en.wikipedia.org/wiki/Tacit_programming) 的方式）写出在 less-expressive language 中可能需要三四行才能写出的内容。

你可以在 Python 之类的语言中用一行写出 `average`（`lambda x: sum(x) / len(x)`），但对于人们用 J 所做的一些更 complex 的事情，你就无法这样做了。[Rosetta Code](http://rosettacode.org/wiki/Rosetta_Code) 是寻找这类 examples 的好地方；最经典的一个就是用一行写出的 Conway’s Game of Life：

```
life=: (_3 _3 (+/ e. 3+0,4&{)@,;._3 ])@(0,0,~0,.0,.~])
```

它当然比用 Python 等语言写出的同样内容更难 parse，但试着弄明白其中的一切是如何工作的，也挺有意思！

## 原文

I recently decided it had been too long since I taught myself a random obscure programming language. (Something like five years, in fact. Yikes!) So I started to pick up [J](http://www.jsoftware.com/). J is a descendant of [APL](https://en.wikipedia.org/wiki/APL_%28programming_language%29), which is known mostly for being typed with the world’s craziest character set:

![World&rsquo;s craziest character set.](https://upload.wikimedia.org/wikipedia/commons/9/9f/APL-keybd2.svg)

APL uses those characters for one- and two-letter mnemonics of every array manipulation primitive (and higher-order function of array manipulation primitives) you could ever want, and then about 10x more. J is like APL that you can write without a custom keyboard.

What does J do differently from your garden-variety functional language? The most interesting thing is probably how functions work. Most programming languages use the standard functional syntax: prefix notation with comma-separated arguments. J, by contrast, has _only_ unary prefix operators and binary _infix_ operators, and function notation is more linguistically structured (even going so far as to call the functions _verbs_).

This isn’t as nice as prefix-paren notation for complicated architecture-astronautics, but it makes up for it by allowing concise primitives for function combination (like [forks](http://www.jsoftware.com/jwiki/Vocabulary/fork) and [hooks](http://www.jsoftware.com/jwiki/Vocabulary/hook)) that would be impossible to parse in other languages. For instance, you can define an average function as `average =: +/ % #`—to be read as “the average is the running sum divided by the length.” This uses a _fork_ (`_ ? _` where the left and right verbs are unary and the middle is binary) and an _adverb_ (`/`, the equivalent of “fold” or “reduce”) to write in one line (and [tacitly](https://en.wikipedia.org/wiki/Tacit_programming)) what could take three or four in a less-expressive language.

You can write `average` in one line in something like Python (`lambda x: sum(x) / len(x)`), but you can’t do that with some of the more complex things people do in J. [Rosetta Code](http://rosettacode.org/wiki/Rosetta_Code) is a great place to find examples of this; the most classic one is Conway’s Game of Life in one line:

```
life=: (_3 _3 (+/ e. 3+0,4&{)@,;._3 ])@(0,0,~0,.0,.~])
```

It’s certainly harder to parse than the same thing in e.g. Python, but it’s kind of fun to try and figure out how everything works!
