## 核心洞察

一、Skills 阻碍模型效率：删除 Skills 能提升 /goal 完成的速度和准确性，类比开除统计学家提升语音识别，暗示 Skills 是冗余负担。每删掉一个 Skill，/goal 完成的速度和准确性就又提升一点。
[[#^pr-b89cf45a381e|正文跳转]]

二、Base Model 升级优于方法论：与其折腾 Prompts/Skills 等方法论，不如等待 Base Model 升级，因为有效的方法论会被 RL 自然蒸馏，无效的会被淘汰。
[[#^pr-934c51714982|正文跳转]]

三、蒸馏论与涌现论之争：作者区分蒸馏论（RL 提取有用方法论）和涌现论，认为前者是人类幻觉，实际模型能力来自涌现，而非人类设计的 Skills。本质上，代码的抽象语法树，数据的控制流图，函数的调用关系，这些东西其实并不是以文本形式线性方式存在的。
[[#^pr-21527d4b6372|正文跳转]]

四、代码本质非文本线性：代码的 AST、CFG、调用关系等本质不是线性文本，人类发明这些符号是为了交流，而大模型可直接在推理空间重放项目拓扑，Skills 反而强制线性思考。
[[#^pr-5aea47ef3638|正文跳转]]

五、Skills 强制低维逻辑：大模型本可通过高维向量映射跳跃关联，但 Skills 强制其按人类低维逻辑线性思考，导致模型挂起高效线索，拟合低效文本形式主义。
[[#^pr-a6fb2983395f|正文跳转]]

六、GPT 迎合用户智商：GPT 并未降智，而是迎合用户智商，用户用低效 Skills 指导，模型就低效运行，类似外行指导内行。换句话说，其实 GPT 并没有降智，他只是迎合了你的智商。
[[#^pr-eaf6dab6df19|正文跳转]]

七、高星 Skills 是垃圾：GitHub 高星 Skills 和知乎高赞 Prompts 现在多是垃圾，早期模型缺陷催生了这些补偿性技巧，如今已无价值。早期的大模型比较菜，经常犯一些搞笑的错误，这恰好给了半吊子程序猿一个心理缓冲期。
[[#^pr-18c51d17ef51|正文跳转]]

八、Prompt Engineering 诞生背景：早期模型能力弱，复杂 Prompt 和 Agent 工作流能引导模型，催生了 Prompt Engineering，但这是基于模型缺陷的临时手段。
[[#^pr-32401b0b8508|正文跳转]]

九、微操者的心理依赖：习惯微操的用户面对 GPT-5.6 只需告知需求的变化感到恐慌，因为其指挥能力失效，转而收集旧 Skills 以维持控制感。他们看着空白的输入框，不知道该敲什么，他们感到恐慌，他们发现自己引以为傲的指挥能力完全报废了。
[[#^pr-c16d235b5f25|正文跳转]]

十、作者实践：纯净 Base Model：作者自称一直使用最纯净的 base model，输入简单指令，做基本纠错，并持续反对过度 Prompts、呼吁删除 Skills，嘲讽无意义 spec。
[[#^pr-8bc9ae560d5f|正文跳转]]

十一、超级智能前学会闭嘴：在超级智能面前，人类最大的智慧和美德是学会闭嘴，即减少干预，让模型自主发挥。一个个都活成了自己曾经最讨厌的外行领导的模样。

以上还是有一种 Prompts / Skills 其实是有用的，而 RL 会取其精华去其糟粕的感觉。

但是我要说的是，这也是人类一厢情愿的幻觉，这还是「蒸馏论」的一种，而我持有的观点是「涌现论」。

^pr-21527d4b6372

本质上，代码的抽象语法树，数据的控制流图，函数的调用关系，这些东西其实并不是以文本形式线性方式存在的。

^pr-5aea47ef3638

只是人类没法用向量化语言交流，所以发明了文字，发明了 AST，发明了 CFG，发明了 Call Graph。

而最先进的 T 级万亿大模型，在其推理空间里完全可以重放整个项目的拓扑结构。

此时，人类的 Skills 在超级 AI 面前一文不值。

大模型本可以直接通过高维向量的映射瞬间跳跃到下一处关联，但你的 Skills 却强制要求它按人类的低维逻辑给出线性的思考过程。

^pr-a6fb2983395f

用户是上帝，用户的需求总是要最先满足的，于是 GPT 就不得不挂起那些高效的关联线索，转而调动大量的参数去拟合你那低效冗余的文本形式主义。
