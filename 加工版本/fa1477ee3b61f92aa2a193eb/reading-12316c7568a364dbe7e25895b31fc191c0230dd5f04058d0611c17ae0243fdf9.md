# AI4MATH的一些更新，以及理论计算机界的感受

## 阅读前置卡

- 价值判断：高。材料记录了AI数学能力的最新进展（GPT-5.6、Fable 5等）及作者亲测案例，并包含理论计算机界对AI影响的真实看法，信息时效性强、来源具体，对关注AI与数学交叉领域的人有较高参考价值。
- 信息密度判断：高。全文围绕AI数学能力与理论计算机界反应展开，几乎每段都包含具体模型、实验数据或观点，信息密度高，无冗余铺垫。
- 是否继续阅读：3 全文。内容涉及多个重要进展和作者实测，值得全文阅读以获取完整细节；但部分内容为个人主观感受，非系统性综述，故未达精细阅读级别。

## 核心洞察

一、AI数学能力已突破传统harness局限：作者原本认为现有模型要么靠few-shot等简单方法就能解题，要么无论如何都解不出，harness不会带来质变。但First Proof Second Batch和Danus两个harness成为反例：前者最好的ProofCouncil在十道题中六道达到“至多需要minor revisions”，优于直接调用GPT-5.5 Pro的五道；后者用fact graph管理中间结论，让多个proof-search agent积累中间结果，解决了一些5.5无法直接解决的问题。这证明harness确实能提升模型解题能力。
[[#^pr-0af1c41c575c|正文跳转]]

二、GPT-5.6的prompt可临时构建强大workflow：GPT-5.6 Sol Ultra生成的Cycle Double Cover Conjecture完整证明稿仅两页，但更关键的是其配套prompt：要求系统同时保持多条独立路线、动态调度agent、持续做adversarial audit，发现路线卡在关键lemma就换方向，由root agent不断综合。配合ultra模式的多agent协调能力，一次run内即可临时组织出高度动态的workflow，效果可能接近长期维护的数学harness。
[[#^pr-fa48c73c5e56|正文跳转]]

三、作者实测5.6解决未解难题并扩展：作者将一个GPT-5.5 Pro和自己都未解出的matroid optimization问题配上CDC prompt交给5.6，43分钟后得到解法。随后加大难度，5.6花14小时完成一个重大extension，过程中自动写文档和代码，并在作者提醒下用计算服务器加速搜索，排除大量失败路径后找到解法。这是“one shot scale to many shots”的成功案例，但也怀疑不用harness跑多次可能也能做出来。
[[#^pr-66f434764ddb|正文跳转]]

四、数学harness价值将下降：基于5.6的表现，写数学harness的价值会下降。如果进一步打磨CDC prompt，例如让系统使用其他AI做验证、调用gurobi等专业软件而非Python暴力脚本，估计就能碾压现有所有math harness。这意味着模型自身动态构建workflow的能力正在削弱外部harness的必要性。
[[#^pr-c08e98c81660|正文跳转]]

五、理论计算机界对AI的复杂态度：在STOC的Can AI do Theory? workshop上，作者听到多种看法：AI仍处于人类知识凸包内；AI擅长的事稀缺性会下降，解题数学家需转型；年轻人承担转型代价；AI成本远低于人力（美国PhD年成本数万美元）；少数研究者迷茫甚至暂停招学生；多数人仍乐观。作者主观感觉理论计算机领域采用AI的速度显著快于传统数学。
[[#^pr-2d4ed72f99df|正文跳转]]

六、AI量产open problem带来意义感危机：有poster将MOR文献中的open problems整理出来让AI逐个尝试，作者进一步设想把AI接到所有论文上，尝试每篇文章提到的open problem。但作者之前做过类似事情后感到空虚：一旦东西可以量产，意义感会迅速下降。这反映了AI自动化研究可能带来的价值重估问题。
[[#^pr-e27c774ba575|正文跳转]]

七、理论领域古法研究将消亡：未来会有更多结果、更快进展，大量open几十年的问题会被解决，但靠个人长时间手工解题、把“我能做出这个题”当作最稀缺能力的古法研究将消亡。作者肯定5.2时代解题能力已不比自己差，5.6则完全碾压自己，任何自己能做出的问题5.6都能做出。
[[#^pr-6945d9331e46|正文跳转]]

八、AI实践：远程开发与工具选择：作者分享实践更新：Codex App的Remote SSH已相当可用，执行在远程服务器、UI在本地；使用Herdr管理多个coding agents，session跑在远程机器上可随时查看；定制工具最好跑在coding agent内以免追不上更新；AgentHub-OSS可统一控制多台机器的Codex/Claude runtime，但尚不成熟；作者理想状态是full autonomy，但目前仍需人工介入。
[[#^pr-ea32456800a3|正文跳转]]

九、环境搭建比harness更重要：作者用AI参加Optimization Grand Challenge，前期靠AI进top 10，中期掉到top 20。分析发现瓶颈不是智力问题，而是实验性代码后期变成“终极屎山”，上百个flag和feature让AI都搞不清canonical implementation。作者删掉大部分代码，只留核心，花一天搭建科学环境和实验contract后排名回升。结论是对于长期运行的项目，环境比harness更重要。
[[#^pr-ea32456800a3|正文跳转]]

十、模型正逐步吃掉人设计的上层结构：Fable 5和GPT-5.6 Sol Ultra在任务中会主动拆解问题、分配subagent、根据中间结果换方向并回头检查，且做得不错。旧版本容易丢失目标，新版本能根据具体问题临时搭建harness-like scaffolding。模型进化正一层层吃掉原来人设计的上层结构，未来AI可能扔到环境里就自己根据问题和环境搭好harness。

## 正文

[距离上一次写东西](https://zhuanlan.zhihu.com/p/2042064356804973433)，我觉得可以分为两个节点。GPT-5.6之前和之后。

### GPT-5.6之前

大新闻：unit distance conjecture被OpenAI证伪。完了，不准备说更多，因为大家该说的都说完了。不了解的随便搜搜就行。

Fable 5出现，在我的一些问题上看起来甚至比GPT-5.5 Pro更强，至少做出了更大的进展。它又能直接在Claude Code里跑，所以不必把它当成一个纯粹的prover oracle，而是可以直接当数学agent用。但它还没有为这类数学问题做过多少适配。我遇到过几次，它一路输出到超过output limit，像是某种产品层面的bug，导致有的数学问题就是完全做不了。

[First Proof Second Batch](https://link.zhihu.com/?target=https%3A//1stproof.org/assets/docs/report.pdf) 和 [Danus](https://link.zhihu.com/?target=https%3A//arxiv.org/abs/2607.06447)也是该被关注的。

First Proof Second Batch刻意比较了直接调用GPT-5.5 Pro和几个学术团队做的harness。最好的ProofCouncil在十道题里有六道达到“至多需要minor revisions”的状态，直接调用5.5 Pro是五道。这个比较当然不完美：差距不算巨大，harness贵得多，而且也不是严格的同模型controlled experiment。但它至少说明了harness有点用。

Danus是个harness，它用fact graph管理中间结论，让多个proof-search agent可以积累中间结果，证明了一些听说5.5没法直接解决的问题。这个我是信的，但我觉得fact graph可能overengineer了，但肯定这个说明了harness是有用的。

因为有一个opinion，就是现有模型面对一个问题，要么few-shot、best-of-N，或者多说几次“keep going”就能解出来；要么**怎么样都解不出来**，harness再强也没有办法让它自己最终在没有人的input情况下找到解法。以前我也觉得，大多数harness只是proof + review这类常见方法，稍微有点用，但不会带来质变。First Proof Second Batch和Danus就是反例。

^pr-0af1c41c575c

当然5.6是更大的反例。

### GPT-5.6之后

更大新闻：GPT-5.6 Sol Ultra 生成的 [Cycle Double Cover Conjecture 完整证明稿](https://link.zhihu.com/?target=https%3A//cdn.openai.com/pdf/04d1d1e4-bc75-476a-97cf-49055cd98d31/cdc_proof.pdf)。竟然整个证明就两页纸。

虽然这个证明很重要，但没想到更重要的是那个 [prompt](https://link.zhihu.com/?target=https%3A//cdn.openai.com/pdf/04d1d1e4-bc75-476a-97cf-49055cd98d31/cdc_prompt.pdf)。那prompt强得离谱。它要求系统同时保持多条独立路线，动态调度 agent，持续做 adversarial audit，发现路线卡在关键 lemma 上就换方向，再由 root agent 不断综合。

^pr-fa48c73c5e56

GPT-5.6 Sol 的 ultra 模式本来就能协调多个 agent。配上这个 prompt，它可以在一次 run 里临时组织出一个高度动态的 workflow。很可能它和一个长期维护、带专门工具和 memory 的数学 harness 差不多了。

所以我去测试了一下。我有一个GPT-5.5 Pro没解出来的matroid optimization的问题，我自己和不少人也没做出来的问题。我配上这个CDC prompt交给5.6，四十三分钟以后，它给出了解法。难道是因为ultra的自己给自己建的workflow实际上是非常强的math harness的原因嘛？怀疑，因为GPT-5.6 Sol Ultra不用harness跑k次可能也能做出来（不过我没去试）。

^pr-66f434764ddb

所以我决定加大药量，开始问那个问题的几个很大的extension。然后它花了14个小时做出了其中一个重大extension。看session里，文件夹里写了一大堆文档和代码。而且中途在我的提醒下，用我一个compute服务器来加速搜索，找到一大堆方法失败的例子（上面可以跑gurobi之类的），看到一条一条路它发现走不通，直到最后找到了成功的暂时还没发现错误的解法。是成功的one shot scale to many shots的例子。

感觉之后写数学harness价值会下降。把这个prompt再打磨打磨（比如让它可以用其他AI做verification而不仅仅是自己的模型，让它用gurobi等软件而不是写python暴力脚本）估计就碾压现有所有math harness了。

^pr-c08e98c81660

### 理论计算机界怎么看 AI

今年我去了STOC的[Can AI do Theory? workshop](https://link.zhihu.com/?target=https%3A//pritishkamath.github.io/ai-tcs-stoc-2026/)。

用AI的理论研究者越来越多。这次在会场和私下聊天里，我反复听到了一些看法：

- AI现在做的事情，仍然在我们人类已有知识的凸包里。
- AI能做的事情，稀缺性会迅速下降。如果一个人只会做AI擅长的那类事，他的价值也会下降。很会解题的数学家需要转型。
- 年轻人会承担转型期里最大的代价。
- 现有模型面对一个问题，要么few-shot、best-of-N，或者多说几次“keep going”就能解决；要么怎么样都解决不了，harness也没有用。（First Proof Second Batch、Danus，以及后来5.6的表现，让我感觉这个判断是不对的。）
- AI虽然看起来不便宜，但和人相比仍然便宜得多。一个美国PhD每年的总成本是数万美元。
- 少数researcher表示，迷茫了，不知道未来应该做什么，甚至决定暂时不再招学生。
- 大多数人仍然很hopeful。他们觉得未来会更好，会有更多原来碰不到的问题被解决，也会发现更多有价值的东西。
- 我的主观感觉是，理论计算机方向adopt AI的速度，显著快于传统数学领域。

^pr-2d4ed72f99df

Workshop 上有不少 [poster](https://link.zhihu.com/?target=https%3A//pritishkamath.github.io/ai-tcs-stoc-2026/%23posters)。我觉得其中有个有意思，[Open Problems in Operations Research](https://link.zhihu.com/?target=https%3A//pranav-nuti.github.io/open-problems-in-or/index.html) 把 MOR 文献里的 open problems 整理出来，让 AI 一个个去试。

那再往前一步呢？把 AI 接到所有论文上，把人类每篇文章里提到的 open problem 都试一遍呢？

我之前也做过类似的东西。做完以后反而有点空虚。一个东西一旦可以量产，它的意义感似乎也会迅速下降，至少对做这件事的人来说是这样。

^pr-e27c774ba575

所以我感觉这个领域要完了。我认识一些OpenAI里的theory人，有些表示theory已经不值得再自己去做了。（话说我至少可以想到15个很强的theory人在OpenAI（就是能在top school拿到或者已经拿到tenure的人），这样密度的从来没有其他公司做到过）

以后会有更多结果、更快的进展，过去碰不到的问题也会被解决，一堆堆open几十年的问题会沦陷。但靠个人长时间手工解题，并把“我能把这个题做出来”本身当成最稀缺能力的古法研究要消亡了。我现在能肯定的说，在5.2时代解题能力就不比我差了，5.6我相信是完全碾压我，也就是任何我能做出的问题，5.6肯定是可以做出的😭。

### 实践上的一些更新

1.  AI-pilled的人还是少数。把它当成默认工作方式，甚至愿意为此重做自己的工具和infra，走到这一步的人还不够多。AI推广真是任重道远。
2.  我的fleet有一堆电脑。`earth`是跟着我走的 MBP，`saturn`是主要的 dev server，一台顶配 Mac mini。 之前几个 coding agent 对 remote dev 的支持都不太好；现在 Codex App 的 Remote SSH 已经相当能用了。执行都在 `saturn`，UI 仍然在 `earth`。偶尔还有些边角问题，但日常用起来已经几乎感觉不到区别。 但我现在用TUI还是更多，因为用了[Herdr](https://link.zhihu.com/?target=https%3A//herdr.dev/)，可以更好的管理各种不同家的coding agents。session 跑在远程机器上，人离开以后不会停，手机 SSH 上去也能继续看。等它的多机器管理再完整一点，我甚至可以想象一个平时只需要打开Herdr。 很推荐哦，没用过看看官网的 demo，看看它到底长什么样。
3.  Codex 和 Claude Code 进展太快了，模型和产品本身都在不断补功能。 我之前试过手搓各种 agent、UI 和 workflow，最后发现基本都追不上。 所以定制的东西最好跑在这些 coding agent 里面，这样不必自己追每一次产品更新。
4.  有没有办法用自己喜欢的 UI 操作 Codex 和 Claude Code？它们没有真headless版（就是真的ui可以随便换的那种）。要完整复刻官方客户端的交互和能力，还要跟上它们飞快的更新，维护成本太高。如果目标是尽量不丢功能，最省事的办法往往还是直接用官方GUI（所以我在用herdr）。 最近看到的 [AgentHub-OSS](https://link.zhihu.com/?target=https%3A//github.com/holdonyb/AgentHub-OSS) ：它给多台机器上的 Codex、Claude 等 runtime 直接读TUI输出，这样可以有个统一的控制面。可自定义UI。但这也不成熟，随着TUI改版整个系统可能也会出问题。 真的需要所有的软件都有headless版本啊。
5.  我理想状态是把任务丢进 issue board，睡一觉，第二天早上起来一切都做完。Full autonomy 是 agent 从头到尾自己做完所有判断，不需要我介入。Async 只是我不用一直盯着它：碰到不确定的地方，它停下来，在 issue 里留个 comment；我第二天醒来再看，做一次 course correction，然后继续。 我觉得我现在用起来，full autonomy还有一点距离。完全放着不管，第二天拿到的东西往往还得自己大修。
6.  快速迭代想法时，我最近经常用 [Gemini 3.5 Flash](https://link.zhihu.com/?target=https%3A//ai.google.dev/gemini-api/docs/models/gemini-3.5-flash)。在这种场景里，我更在意低延迟和来回次数，而不是单次回答有多完整。它速度太快了。 不过以后可能会用gpt-live。语音及时聊可能感觉更smooth。
7.  如果只是出门了还想能远程控制AI，也许不需要带电脑。我想要的一台 e-ink tablet：能 SSH+语音输入。计算、文件和 agent 都在远程机器上，本地只负责输入和阅读。 以前我会觉得，这种硬件想法比 AI 软件难落地。但现在感觉做个prototype也不麻烦。最近可能会试一下。
8.  最近我在用 AI 打 [Optimization Grand Challenge](https://link.zhihu.com/?target=https%3A//optichallenge.com/)，主要是为了练手。我对问题本身几乎还没搞清楚的时候，就靠 AI 在前期进过 top 10 这一档；到了中期，又掉到了 top 20 档。 问题直接丢给 AI，前期进展很快，但很快就会碰到难以逾越的瓶颈。原先以为是智力问题，但看了看session（它自己也分析分析），还是因为这种实验性代码后期就会是终极屎山，上百个flag开关feature，甚至AI连哪个才是 canonical implementation 都说不清，Fable都搞不懂，不断的在confused的状态做错的事情。最后我全删了，只留下其中的核心代码，然后花了一天搭建好的科学环境，和实验contract。这之后才又开始排名上升，虽然感觉AI怎么刷都不可能回到top 10了😂。感觉环境还是要建好，对于这种长久跑的东西，环境就是比harness还重要了。
9.  前面已经说到模型已经开始自己给自己搭workflow。Fable 5（Ultracode）和 GPT-5.6 Sol Ultra的几次任务里，它们会主动拆问题、分配 subagent、根据中间结果换方向，再回头检查结果。而且做的不差。以前也会做，但是很快就会丢失目标，跑着跑着轨道就偏了。 而新版本里，它们能根据具体问题，临时搭出一部分 harness-like scaffolding。 模型的进化真的一层一层地吃掉原来人设计的上层结构。 可以想象几个版本之后的AI应该是扔到了环境里自己就根据要解决的问题和检测到的环境，自己就把harness搭好了。
