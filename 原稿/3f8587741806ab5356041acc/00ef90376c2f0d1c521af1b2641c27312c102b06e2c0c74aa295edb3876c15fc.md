## 功能简述

这是一个OpenCode Go专用的多账号管理器，支持本地托盘运行和服务器部署。

![](https://pic4.zhimg.com/v2-a218b712d976251f4843c134772f01d7_1440w.jpg)

在本机运行的时候，默认URL为[http://127.0.0.1:9042/v1](https://link.zhihu.com/?target=http%3A//127.0.0.1%3A9042/v1)。

上游默认为[https://opencode.ai/zen/go](https://link.zhihu.com/?target=https%3A//opencode.ai/zen/go) （这个应该没有人想去改它吧）。

网关支持接收以下EndPoint：

-   `POST /v1/chat/completions`
-   `POST /v1/responses`
-   `POST /v1/messages`
-   `GET /v1/models`

客户端协议和模型的原生协议不一致时，会自动转换请求，再把上游响应转回客户端需要的格式。

和一般的网关不同的是，OCG Mgr只会处理401、403、429错误，也就是OpenCode Go的账号错误/限额不足。

当出现错误以后，会自动熔断当前Key，根据OpenCode Go反馈的具体时间，对对应的Key进入冷却。

账号支持手动和OpenCode Go进行同步设置，作为新增账号时候的预设，但是这个数值仍然仅供参考，并不作为实际熔断的判定。

![](https://pic4.zhimg.com/v2-ef1fb071ac832d03498ca2638d9fac3b_1440w.jpg)

目前没有任何负载均衡、或者其他路由逻辑，采用的是简单的从上到下依次路由，跳过其中已经熔断/进入冷却的KEY。

因为根据我个人实测（New API随机/轮询模式），OpenCode Go的缓存是根据Key来配置的（指GLM-5.2）。也有可能是New API自己的BUG，这里我不多做猜测。

![](https://pic3.zhimg.com/v2-a2c099de1bb71541407aa53ca6267172_1440w.jpg)

因为OpenCode Go官方并没有开放Usage接口，所以上面的额度都是根据流经网关的流量计算的，并不代表实际额度。只能仅供参考，会出现额度看起来被打满了但是实际仍能运行的情况。

## 服务器模式

支持Cli启动和Docker两种模式。目前只推荐Cli启动。

PS：如果你本机使用，但是不想安装托盘，也可以Cli启动。

![](https://pica.zhimg.com/v2-27f9c2f58b5b6f53a300ec67c3ff7bc4_1440w.jpg)

同时你可以直接用Cli对网关进行直接的管理。

```
ocg-manager-cli key add main sk-...
ocg-manager-cli key list
ocg-manager-cli key ping
ocg-manager-cli status
ocg-manager-cli serve --port 9042
```
