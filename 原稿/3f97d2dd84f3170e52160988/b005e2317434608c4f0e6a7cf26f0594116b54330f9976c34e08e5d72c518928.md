非科班，目前在nginx团队。要说对编程能力提升最大的一件事，是学会手写parser。

parser就是解析器，比如HTTP——服务器收到的请求本质是一串字节流，得有人把它变成程序能用的数据结构。这事有现成库，看起来自己写就是重复造轮子。但现成库不是所有场景都适用，尤其C语言写的项目涉及更多细节，光内存分配就每家处理不一样。真正造过这个轮子之后，对编程能力的提升是另一个量级的。

碰到一个解析需求，是手写还是用第三方库？这本身是个判断力的问题。会手写的人多了一个选项，判断自然更准。

nginx对第三方库的依赖极少，正则用了pcre基本就到头了。

HTTP解析器是手写的，一个状态机，逐字节读请求行、读header、处理各种边界情况。HTTP解析是nginx的命脉，性能和安全都压在这一步，引入外部库意味着在最关键的环节妥协。

nginx的配置文件也是手写解析的。表面看是个配置格式：

```text
http {
    server {
        listen 80;
        location / {
            proxy_pass http://backend;
        }
    }
}
```

看着像YAML那种简单格式，其实不是——它有if、有变量、有嵌套block，本质是一门小型脚本语言。nginx出现是二十多年前的事，当时json都不普及，Igor Sysoev给nginx设计了专属格式，对程序员比较友好，写了完整的解析器。现在大家更倾向于用web管理配置，json那种更受欢迎，但在当时这是很自然的选择。理解这个之后，再碰到”要不要自定义配置格式”这种问题，思路完全不同了。

后来给njs（nginx的JavaScript模块）贡献代码，到现在贡献排行第3，也是对我编程能力提升最大的一段时间。nginx大概2017年开始支持JS，njs是Igor手写的JS引擎——当时已有一些JS引擎，但他觉得都不适合nginx的场景，需要高性能和极致的内存效率，找不到合适的就自己写了。从零手写一个JS引擎，这难度不是一般的大，但对Igor这种顶级程序员来说，他觉得有价值，就能做出来。我开始贡献时，njs要从ECMAScript 5.1升级到ES6，加一个语言功能就得动parser——词法分析、语法分析、AST构建。刚开始难度很大，以前看编译原理觉得离自己很远。但真正上手改一个生产环境的语言解析器，做久了就习惯了那种难度，那些概念全变活了。

再后来实现fetch，这是我给njs写的功能里最满意的一个——它让nginx内部可以发起HTTP请求到第三方服务。这等于用C从零写一个HTTP client，又回到了HTTP解析，只不过这次是自己写解析器，不是读别人写的。nginx的基因就在那里，除非第三方库非常适合，否则不会考虑引入。能手写parser，就决定了你做不做得出来这种功能。

回头看这条线：读HTTP parser，知道了字节流怎么一步步变成数据；读配置解析器，知道了设计的边界；改njs的parser，编译原理从书本变成手感；写fetch，从读别人的parser到自己写一个。每一步变的不是”会写更多代码”，是判断力变了——知道什么时候该用现成的，什么时候值得自己写。

最近我用AI写了两个真实项目，jsbench是让AI自由发挥，jsmock是先设计好架构再让AI实现。做下来最大的感受是，AI写代码很快，但判断该怎么写、该不该写，还是得人来。手写parser会实实在在提升你的判断力。而判断力这件事，在AI时代只会越来越重要。
