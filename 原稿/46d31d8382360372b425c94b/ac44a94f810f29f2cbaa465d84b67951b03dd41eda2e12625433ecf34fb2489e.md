## 2\. 我的个人知识库迭代过程

有知友问：“这些工具布置需要时间，迭代也很快，那怎么平衡学习本身和这些辅助学习的工具呢”。这个问题很有趣，它涉及了ai时代中一种典型的技能焦虑。借这个问题也顺便说一下我这个知识库是怎么变成现在这样的，每个部分是否都是必须的。

先说一下我学习工具的流程，大概是：遇到问题->网上搜索是否有开源现成的解决方案（一般能找到，没找到就让claude code vibe一个最小的的可以work的工具）->试一下工具是否能用->使用工具(->也许比较闲的时候写一篇文章分享一下）。我的流程不一定就是对的，但是你可以发现，在我的流程里面是没有主动去找工具的环节，只有根据需求去筛选工具。

其实会有工具火到你不得不直视它，比如OpenClaw，最近的Hermes Agent，还有各种层出不穷的skill，关键是它们看起来都很好用。我们会不自觉地创造需要用到这样的工具的场景，觉得自己能够提升效率；或者想象别人用了这样的工具而你没用，生产力又被拉低好多。这种焦虑推着你去学这些工具，最终你还没开始做事情，先浪费很多时间学习工具。更糟糕的可能是这些工具学会之后对你的效率没多大帮助。

或许正确的做法是：对于你现在已经存在的场景，但是你觉得生产力不够高，或者出现了很多问题，这个时候可以去找工具，我的知识库就是被需求倒逼优化的例子。

所以说说我为什么做这个个人知识库。

最开始是纯手写，参考的bilibili上一位up主，叫PiKaChu345 ([出错啦! - bilibili.com](https://link.zhihu.com/?target=https%3A//space.bilibili.com/180947374%3Fspm_id_from%3D333.337.0.0))。这位up主提出了写笔记的一些原则。因为我笔记很乱，到处乱放（物理意义上），最开始我还想的只是做一个电子笔记本，把笔记拍照给gpt转成md，放到obsidian里面做一个电子存档，方便找。

再后来是发现这种存档根本用不了，于是想把笔记拆成原子化的形式，也就是按照知识点记录，这个时候其实已经初具雏形了。

后面发现这并不能完全解决所有问题，首先肯定你自己写这个太麻烦，而且找双向链接的过程其实很繁琐，这个时候就已经有了让claude接管的想法。而且还有个之前没解决的问题：全是知识点，我找不到记录我想法的地方，如果是创建一个idea的笔记，去找idea对应的知识点也很麻烦。于是让claude code重新整理我的笔记，新建了目录，分开放。但这个其实只是一个临时的补丁，因为它没有解决任何问题，仅仅只是让笔记变得更整洁，看起来更美观，但没什么用，还是需要人去维护。作为参考，重构之后的目录大致如下

## 3\. 准备工作

所以，如何拥有这样的个人知识库呢？下面是详细的步骤。

首先你得有一个Obsidian，然后有一个Claude Code（或者其他可以帮你使用终端的agent）。这两个东西的配置过程网上已经很详细了，这里不在赘述。

进入Obsidian的文件目录下，找到这个文件夹在你本地的位置

![](https://pic2.zhimg.com/v2-c61c1c45fc146a57dd217bb227f30e47_1440w.jpg)

以macos系统为例

然后进入到Obsidian Vault目录下，git clone我的仓库

```bash
git clone https://github.com/Erber102/Personal-Knowledgebase.git
cd Personal-Knowledgebase
```

核心框架如下

```text
research-wiki
├── claude.md
├── raw
│   ├── assets
│   ├── books
│   ├── clips
│   ├── courses
│   └── papers
└── wiki
    ├── concepts
    ├── connections
    ├── questions
    ├── index.md
    ├── learner_profile.md
    ├── log.md
    ├── papers
    ├── progress.md
    ├── revision_notes.md
    └── system.md
```

由于我后面自己又不断优化，加入了新的功能，所以github上的版本可能和我这里列出来的原始版本有出入，不过核心是一样的。

这里面raw 文件夹是使用者手动维护的，具体的步骤只有加东西进去。网站可以用浏览器的 Markdown 插件转成 .md 文件，要学的书，课程ppt，论文直接放pdf进去就可以。assets 文件夹下本地存放一些图：网站上的存下来的图，课程讲义里的图之类的。

wiki 文件夹是这个体系的核心，它包含了两个部分：第一个部分是LLM-Wiki 的区域

```text
wiki 
├── concepts 
├── connections
├── questions
├── papers
├── index.md
└── log.md
```

简单介绍一下：

papers/**：** 一篇论文一个页面。记录核心贡献、方法、结果、局限。是原始知识的粗处理，每个页面对应raw/里的一个源文件。

concepts/**：** 一个概念一个页面。多篇论文可能都贡献到同一个concept页面。这是wiki里最有价值的层，因为它把分散在不同论文里的同一个idea聚合到一起。

connections/**：** 跨概念的桥梁。这些页面记录的不是单个概念，而是"A和B之间的关系"。这是idea产生的地方。

questions/**：** 你还回答不了的开放问题，你觉得有联系但还没想清楚。这些页面是你未来研究方向的种子。随着wiki长大，有些question会被resolved（变成connection），有些会被refined（拆成更具体的子问题）。

四层的关系是：papers喂进来 → 长出concepts → concepts之间碰撞出connections → 还想不清楚的变成questions → questions驱动你去找新的papers喂进来。这是一个循环。

然后index.md 和 log.md 的作用就和它们看起来一样。index 记录你目前所有的文件和简要介绍，log 记录你每次增加的内容。

第二个部分是用苏格拉底式问答法学习concepts 文件夹下的概念的部分（或者其他你想学的东西）

```text
wiki
├── progress.md
├── learner_profile.md
├── revision_notes.md
└── system.md
```

这些文件的作用也和看上去差不多。progress记录你的进度，learner\_profile记录你的偏好，不会被AI更改。revision\_notes记录你概念可能有漏洞的地方，总结出需要复习的知识点。system是对于这个系统的初始化，记录这套系统如何运转的。

## 4\. 使用指南

进入research-wiki 目录下后启动Claude Code，然后直接说：

帮我ingest raw/papers 下的所有论文，读完一篇之后先跟我讨论核心要点，然后再编译进wiki

这样的好处在于你可以控制哪些东西进入wiki中，比如你不关心论文中的工程技巧，你就在Claude Code询问的时候人为把那些东西筛掉。

然后你翻看concepts如果遇到不懂的，可以直接让它

使用苏格拉底法给我讲讲某个概念

然后Claude Code就会开始以对话问答的形式教你。

具体来说

怎么 ingest（自然语言触发，见 CLAUDE.md §5）  

| 你说 | 系统做什么 |
| --- | --- |
| 「正式 ingest 这篇论文」 | 完整读一篇论文，生成 paper 页 + 相关 concept 页 + claims |
| 「我想学习这篇论文」 / 「带我读」 | 带读模式，边读边讲 |
| 「ingest 这篇论文，我后面再看」 | 先轻量入库（停车场），之后再细读 |
| 「把这个 idea 放进系统」 | 把一个研究想法登记成 question / claim |
| 「帮我 ingest 这节课」 | 把一节课材料整理进 courses/ |

怎么用苏格拉底法  

| 你说 | 系统做什么 |
| --- | --- |
| 「用 Socrates 模式问我」 | 以提问驱动，带你一步步想清楚某个主题 |
| 「考我」 | 出题检验掌握度，记录错题 |
| 「用 Feynman 模式检验\[某概念\]」 | 你来讲、它扮演零基础同学追问，暴露你没真懂的地方 |

对于苏格拉底法更多的细节可以去看吴乐旻老师的原文，链接放在文末参考处。

## 5\. 后期优化空间（已经更新）

学习的过程中遇到了几个很自然的问题，比如读论文和学习课程本质上的不同。论文相互之间的逻辑关联顺序并不强，大部分时候也没有"在学B论文之前一定要读A论文“这种说法。而课程是一个逐渐递进的关系，天然适合这样的系统。

出于上面的原因，产生了下面的几个问题

问题一是，用苏格拉底法学论文会天然慢一点，这会涉及到概念嵌套的问题。不懂概念 $a$ ，就要去看 $a$ 衍生出来的 $a_1,a_2,\cdots,a_n$ ，然后每个衍生概念又有它自己的衍生概念，这样递归下去颇有种要把所有知识都学完的势头。

第二个问题是，论文读完的判定标准：我到底要学到什么程度才算把一篇论文读完了？不可能是把所有概念都学完吧，所以就又回到问题一了。

第三个问题是，苏格拉底法每次都是深入一个局部的概念，导致我不知道这个概念在整篇文章中的作用，而我总是想要知道我为什么在学这个。

解决方案：关键变化是，不要让 AI 只是总结论文，而是让 AI 帮你决定怎么读这篇论文。

先给每篇论文和每个概念划分等级，具体划分方式如下

1\. Blocking concepts: 不懂就无法理解主线，最多 5 个

2\. Interface concepts: 只需要知道输入、输出、作用

3\. Local details: 第一次阅读可以跳过

4\. Future debt: 以后值得学，但当前不学

论文等级划分

Level 0：知道它存在

适合大量扫文献。

完成标准：

```text
我知道这篇论文大概做什么。
我知道它是否和我的问题相关。

```

时间：5-15 分钟。

Level 1：能定位它

完成标准：

```text
我知道：
1. 它解决什么问题
2. 它的方法大概是什么
3. 它和我的研究问题有什么关系
4. 是否值得继续读

```

时间：30-60 分钟。

大多数论文到这里就够了。

Level 2：能使用它

完成标准：

```text
我能把它放进我的 wiki，并解释：
1. 它的核心 claim
2. 它的主要 evidence
3. 它和其他论文的关系
4. 它对我的 idea 有什么启发
5. 它有什么 limitation

```

时间：2-4 小时。

对你有用的论文应该读到这一级。

Level 3：能复述 / 推导 / 实现核心机制

完成标准：

```text
我能：
1. 不看原文讲清主线
2. 解释关键公式或算法
3. 走一遍 toy example
4. 指出它的假设和弱点

```

时间：半天到几天。

只有核心论文需要到这里。

Level 4：能扩展它

完成标准：

```text
我能：
1. 修改它的方法
2. 推广它的理论
3. 设计新的实验检验它
4. 写出它和我的 idea 的区别
5. 判断它是否能成为 paper 的 foundation

```

时间：几天到一周以上。

只有极少数论文需要到这里。

读论文流程改变：为了针对只看局部的问题，我把苏格拉底法流程稍微改变了一下：

```text
1. Global orientation，5 分钟
先告诉我当前概念在整篇论文里的位置。

2. Local drilling，20-40 分钟
用苏格拉底法追问一个核心概念或公式。

3. Global reintegration，5-10 分钟
把刚刚学的东西重新接回 paper、wiki、Q1-Q6。

```

也就是说，不能一上来就 Socrates。

每次读论文前，先让 AI 生成一个任务单。

```text
Reading Mission

Paper:
Role:
- survey / ingredient / nearest prior work / baseline / theory foundation

Target level:
- L0 / L1 / L2 / L3 / L4

Why I am reading this:
它和我的哪个研究问题有关？

Main question:
读完这篇论文，我要回答什么问题？

Must understand:
最多 5 个点。

Can ignore:
第一次阅读可以跳过的部分。

Stopping criterion:
达到什么程度就停止，不继续深挖。
```

我把读论文的部分优化了之后，它和目前课程的体系也不兼容了，因为课程没有这些问题，挨个学就完了。所以我把论文和课程分为两个文件夹管理。
