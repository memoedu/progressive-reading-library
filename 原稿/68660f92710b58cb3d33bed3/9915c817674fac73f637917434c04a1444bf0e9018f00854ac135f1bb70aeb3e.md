## 前言

使用 rust 开发商业级软件中，跨平台构建一定是无法绕开的一道坎，如何优雅地使用大型服务器一次性构建出所有目标平台的二进制文件是每一个工程师的必修课。

这篇文章就简单记录一下如何进行跨平台构建。

---

## 准备

本次开发平台为 x86 linux，需要安装如下的工具链：

- rust
- docker

---

## rust 原生跨平台

rust 本身就支持跨平台，运行如下的命令查看所有的支持平台：

```bash
rustup target list
```

输出：

```
...
x86_64-pc-windows-msvc (installed)
x86_64-unknown-freebsd
x86_64-unknown-fuchsia
x86_64-unknown-illumos
x86_64-unknown-linux-gnu (installed)
x86_64-unknown-linux-gnux32
x86_64-unknown-linux-musl
x86_64-unknown-linux-ohos
x86_64-unknown-netbsd
x86_64-unknown-none
x86_64-unknown-redox
x86_64-unknown-uefi
```

从 arm 到 x86，从 windows 到 darwin（MacOS），甚至连 RiscV 都支持。

直接使用 cargo 构建跨平台虽然可以，但是会产生很多的依赖项，对于软件分发而言，这是非常不方便的一件事。所以社区内出现了 `cross`，一款用于进行跨平台编译到纯静态文件的命令行工具，下面就演示一下如何使用 cross 在 x86 linux 上把rust项目编译成 x86 windows。



## 使用 cross 进行跨平台编译

### 编译 x86 windows

我们先在我们的rust 项目中安装 cross：

```bash]
cargo install cross
```

从上面 `rustup target list` 的结果中选择 x86 windows 的，发现有三个：

```
x86_64-pc-windows-gnu (installed)
x86_64-pc-windows-gnullvm
x86_64-pc-windows-msvc (installed)
```

> 我这边因为已经下载了对应的工具链，所以显示 installed

我们此处采用 gcc 编译工具链，因为在大部分的 Linux 上，gcc 都是默认编译器，所以我们先安装 x86 windows gcc 的工具链：

```bash
rustup target add x86_64-pc-windows-gnu
```

安装完成后，就可以直接开始编译了，超级方便~

```bash
cross build --release --target x86_64-pc-windows-gnu
```

</div>

这条命令会让 docker 去下载 x86_64-pc-windows-gnu 的镜像。在下载完成后，cross 就会开始进行构建。

:::info 显示没有 docker 权限

在运行上述命令时，有可能会出现下面的错误：

```
docker: permission denied while trying to connect to the Docker daemon socket at unix:///var/run/docker.sock: Head "http://%2Fvar%2Frun%2Fdocker.sock/_ping": dial unix /var/run/docker.sock: connect: permission denied.
See 'docker run --help'.
```

这说明你没有对应的权限，此时只需要把添加用户到当前组即可：

```bash
# 添加用户到组
sudo usermod -aG docker $USER
# 重启 docker
newgrp docker
# pull 一个小项目测试一下权限
docker run hello-world
```

:::

### 编译 M 系列芯片的 Mac

M系列也就是 arm，Mac 也就是 darwin，所以目标为 `aarch64-apple-darwin`。

:::info

老版本的 Mac 也就是 x86_64-apple-darwin

:::

不同点在于，Mac 需要额外下载工具链，先下载一下，并增加环境变量：

```bash
cd ~/package
curl -L https://github.com/roblabla/MacOSX-SDKs/releases/download/13.3/MacOSX13.3.sdk.tar.xz | tar xJ
# 下面的写入配置文件中
export SDKROOT=$HOME/package/MacOSX13.3.sdk
```

然后这里有一个非常坑的点，原生 MacOS 上的程序在编译时需要依靠 xcode 内置的工具链，这个工具链的链接器有一些特殊的参数，常规的 gnu gcc 的链接器没有这些参数，这会导致编译失败。幸亏rust允许我们通过环境变量来指定编译不同架构时采用的链接器。

环境变量的名字为 `CARGO_TARGET_{平台标识符}_LINKER`。平台标识符也就是 `rustup target list` 的输出结果，记得需要全部单词大写并且把所有 短横线 换成 下划线。比如 `x86_64-apple-darwin` 对应的链接器环境变量就是 `CARGO_TARGET_X86_64_APPLE_DARWIN_LINKER`。rust 提供的链接器 rust-lld 刚好可以完成跨平台编译的任务。

因此，编译 x86_64-apple-darwin 只需要输入：

```bash
export CARGO_TARGET_X86_64_APPLE_DARWIN_LINKER=rust-lld
cross build --release --target x86_64-apple-darwin
```

编译 aarch64-apple-darwin 的命令为：

```bash
export CARGO_TARGET_AARCH64_APPLE_DARWIN_LINKER=rust-lld
cross build --release --target aarch64-apple-darwin
```

### 编译 龙芯 LoongArch64

目前 LoongArch64 主要支持的操作系统是 Debian 系列的 Linux，那就算是 Linux 吧，那么编译 LoongArch64 版本的 Linux 也是 Rust 目前支持的。

首先添加 Rust 的 LoongArch64 标准库并下载工具链：

```bash
rustup target add loongarch64-unknown-linux-gnu
rustup toolchain install stable-loongarch64-unknown-linux-gnu
```

然后去龙芯的 github release 下载最新的交叉编译工具包和对应的 glibc 源文件：[龙芯 GNU 编译工具链](https://github.com/sunhaiyong1978/CLFS-for-LoongArch/releases).

我下载的是 CLFS-loongarch64-8.1-x86_64-cross-tools-gcc-glibc.tar.xz

```bash
cd ~/package
wget -c  https://github.com/sunhaiyong1978/CLFS-for-LoongArch/releases/download/8.1/CLFS-loongarch64-8.1-x86_64-cross-tools-gcc-glibc.tar.xz
tar -xvf CLFS-loongarch64-8.1-x86_64-cross-tools-gcc-glibc.tar.xz
```

进入你的项目，然后写一个脚本来完成（因为 cross 似乎并没有很好地支持龙芯）

脚本名称：`build_loogson.sh`

```bash
export LC_ALL=POSIX
export CROSS_TARGET="loongarch64-unknown-linux-gnu"
export MABI="lp64d"
export BUILD64="-mabi=lp64d"

export PATH=$PATH:$HOME/package/cross-tools/bin
export CARGO_TARGET_LOONGARCH64_UNKNOWN_LINUX_GNU_LINKER=loongarch64-unknown-linux-gnu-gcc
export CC_loongarch64_unknown_linux_gnu=loongarch64-unknown-linux-gnu-gcc
export CXX_loongarch64_unknown_linux_gnu=loongarch64-unknown-linux-gnu-g++

cargo build --release --target "${CROSS_TARGET}"
```

然后运行 `build_loogson.sh` 即可完成构建。
