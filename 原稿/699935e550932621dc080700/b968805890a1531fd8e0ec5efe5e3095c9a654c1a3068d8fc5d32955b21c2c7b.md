## 场景

最近在开发一个类似于分布式猫娘的客服机器人，然后嘛，一是考虑到 python 这种垃圾语言不太适合做软件开发，二是方便后续的负载均衡，我把客服 bot 系统设计成了如下三个部分：

- NTQQ 客户端的 server（ws）
- 根据 onebot v11 协议实现的逻辑路由层（ws，http）
- 用 python 搭建的 RAG 系统（http）

很显然上述三个每个都是一个需要挂在后台，长期运行的 server，如果每次运行都要 `screen -r xxx` 或者 `tmux attach-session -t xxx` 未免显得有点不优雅。于是，我在想有没有好用的进程管理器，然后我这日渐衰退的脑子瞬间想到了一个工具——`pm2`。

`pm2` 是一款基于 nodejs 开发的生产级别的进程管理器。所以阁下需要先在你的服务器上下载一个 nodejs。

基于 `pm2`，可以很好地完成进程的创建，后台挂载，管理，自动重启等等一系列功能。简直就是运维神器。

[[nodejs] pm2 : nodejs 的进程管理工具 - 千千寰宇 - 博客园](https://www.cnblogs.com/johnnyzen/p/18091142) 是非常棒的一篇有关 pm2 的文章。

## 安装

使用 npm 安装即可：

```bash
npm install pm2 -g
```

使用版本展示验证安装：

```bash
pm2 -v
```

输出：

```
5.4.0
```

## 基本使用

### 在后台启动进程

基本指令为：

```bash
pm2 start /path/to/可执行文件
```

比如我来启动QQ的拉格朗日后端：

```
pm2 start ./Lagrange.OneBot
```

输出：

```bash

[PM2] Done.
```

对于复杂指令，考虑通过 "" 进行包裹：

```bash
pm2 start "npx tsx src/main.ts --update-something" --name "boring process"
```

对于常用的脚本语言，比如 JavaScript，Python，通过 `pm2 start` 直接就可以启动， pm2 会自动根据文件类型使用正确的脚本解释器：

```bash
pm2 start main.py
```

输出：


如果你是需要指定特定的解释器，比如你用的是某个 anaconda 的环境，那么可以通过 `--interpreter` 指定解释器

```bash
pm2 start main.py --interpreter=/path/to/python3
```

通过 `--name` 参数可以指定创建的进程的名字，否则，默认按照 `pm2 start ` 后的执行文件去除后缀名后的字符串作为 `name`。比如：

```bash
pm2 start main.py --name 'llm-rag'
```

```bash
./filebrowser --address 0.0.0.0 --port 8080 --root ~/files/filebrowser
```

```bash
pm2 start ./filebrowser --name filebrowser -- --address 0.0.0.0 --port 8080 --root ~/files/filebrowser
```

### 结束进程 / 删除进程

使用 `pm2 stop <name>` 结束进程

```bash
pm2 stop main
```

输出：

```bash
[PM2] Applying action stopProcessId on app [main](ids: [ 1 ])
[PM2] [main](1) ✓
┌────┬────────────────────┬──────────┬──────┬───────────┬──────────┬──────────┐
│ id │ name               │ mode     │ ↺    │ status    │ cpu      │ memory   │
├────┼────────────────────┼──────────┼──────┼───────────┼──────────┼──────────┤
│ 0  │ Lagrange           │ fork     │ 0    │ online    │ 0%       │ 125.1mb  │
│ 1  │ main               │ fork     │ 0    │ stopped   │ 0%       │ 0b       │
└────┴────────────────────┴──────────┴──────┴───────────┴──────────┴──────────┘
```

或者使用 `pm2 stop <id>` 也行，对于进程 `main`，它的 id 是 1，所以使用方法为

```bash
pm2 stop 1
```

需要注意，结束进程并不会真正杀死进程，进程的运行上下文等信息还会留存在 pm2 的系统中，此时运行 `pm2 ls` 的结果为

```bash
┌────┬────────────────────┬──────────┬──────┬───────────┬──────────┬──────────┐
│ id │ name               │ mode     │ ↺    │ status    │ cpu      │ memory   │
```

## 使用进阶

相信在经过一段时间的使用后，你一定会发现 pm2 的一些美中不足的地方，因此，pm2 提供插件系统来定制额外的功能。

### 自动保存

这个功能非常重要，但是我打算放到这里讲。

假设你开启了一万个后台进程，然后服务器突然断电了，这个时候你 pm2 ls 了一把，发现啥也没了，一觉回到解放前，那么怎么办？

为了避免这种情况，你可以使用 pm2 save 来极速保存当前的运行快照，这个命令会将当前每一个 pm2 托管的进程的命令，cwd，环境变量等等记录起来。如果哪天你的服务器断电了，假设你 pm2 save 过了，那么只需要输入下面的命令就可以一键拉起所有服务：

```bash
pm2 resurrect
```


### 更新环境变量

pm2 reload 默认不会刷新当前的环境变量，如果你修改了环境变量，使用下面的方法重启服务进程才能刷新环境变量：

```bash
pm2 reload <name> --update-env
```

### 日志管理器 pm2-logrotate

pm2 打开的每一个进程就会自动记录它们的标准输出到 `~/.pm2/logs` 中，pm2 自己默认是不会进行清理的，因此，长时间运行的 pm2 会产生大量的日志，为了自动清理庞杂的日志，我们可以安装日志管理器 `pm2-logrotate` ：

```bash
pm2 install pm2-logrotate
```

安装完成后的 pm2-logrotate 默认有如下的配置，你也可以通过下面的指令来设置它们：

```bash
# 常用配置选项
pm2 set pm2-logrotate:max_size 10M  # 单个日志文件最大大小(如10M)
pm2 set pm2-logrotate:retain 30     # 保留的日志文件数量
pm2 set pm2-logrotate:compress false # 是否压缩日志
pm2 set pm2-logrotate:dateFormat "YYYY-MM-DD_HH-mm-ss" # 日期格式
pm2 set pm2-logrotate:workerInterval 30 # 检查间隔(秒)
pm2 set pm2-logrotate:rotateInterval "0 0 * * *" # 每天午夜轮转
```
