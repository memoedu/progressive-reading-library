## 问题背景

最近在给我的宝贝网站汇尘轩增加一堆新的功能，其中就涉及到了点赞，订阅呀这些一个稍微正规一点的博客网站都有的功能。但是在实现的时候遇到了一点小问题：`onMounted` 中一直获取不到当前用户关于这篇文章的状态（比如是否已经点赞了，是否已经订阅了这个作者，当前，现在作者就我一个）。

经过足足5秒的思考后，我想起来，是因为此时「用户登陆请求」还没有执行完，变量还没有同步到全局，所以在点赞模块中看，用户当前可能是没有登陆的（全局的 user 还都是默认值），因此，就没有执行后续请求用户状态的操作。

用代码解释就是：

```javascript
// 文件：login.vue
onMounted(async () => {
	// 先进行登陆
	const user = await reqLogin();
	// 将当前登陆的用户同步到全局
	store.state.User = user;
});

// 文件：like.vue
onMounted(async () => {
	const user = store.state.User;
	// 如果 login.vue 中的 reqLogin 还没执行完成，那么此时的 user 就是空
	// 下面的判断就会被自动过滤，获取点赞状态的请求就不会被执行
	if (user) {
		like.value = await reqGetUserLike({ articleID });
	}
});
```

也就是说，想要解决这个 bug，就需要让点赞模块的「获取用户点赞状态的请求」在「用户登陆请求」之后才能执行。怎么做呢？一个非常麻瓜的做法就是，在「获取用户状态的请求」之前一直 `setInterval` 一直轮训全局的 user ，如果 `user.login` 为 true 了，再去执行获取「获取用户点赞状态的请求」。这么做可以，但是并不优雅，而且代码的可维护性也差。

我们再想想，这种要求保持一定的顺序进行调度的问题，在计算机理论中你能联想到什么？

当然是操作系统中的进程调度，进程调度的一个核心章节也是教你如何控制进程调度的顺序，还记得怎么做的吗？当然是通过信号量或者锁。

> 除了这个之外，另一个优雅的做法就是维护几个变量，结合 v-if 用于在登陆完成后再去挂载某些模块，这样也能保证点赞模块内的请求全部都在登陆请求结束后才被调度。受限于时间，此处就不讲了。

---

## 在前端实现异步锁

所以自然而然，我们想到，只需要在前端实现一把锁就行了，前端也就是 js，实现阻塞可以依靠 loop 中对于 Promise 的无损跳过。而 js 的调度针对 Promise 的 task 都是异步的，因此，我们实现的也就是一把异步锁。

---

## 功能定义

我们先定义需要用到的功能，假设我们实现了一把全局的异步锁，差不多我们应该在上面的程序中如此去调用：

```javascript
// 文件：login.vue
onMounted(async () => {
	// 先进行登陆
	const user = await reqLogin();
	// 将当前登陆的用户同步到全局
	store.state.User = user;
	userLock.releaseAll();
});

// 文件：like.vue
onMounted(async () => {
	await userLock.wait();
	const user = store.state.User;
	// 如果 login.vue 中的 reqLogin 还没执行完成，那么此时的 user 就是空
	// 下面的判断就会被自动过滤，获取点赞状态的请求就不会被执行
	if (user) {
		like.value = await reqGetUserLike({ articleID });
	}
});
```

因为我们此处不需要争夺锁的所有权，所以不需要使用 acquire，使用 wait 即可。

所以我们可以想到一个大致的异步锁类的定义应该如下：

```javascript
// 文件 async-lock.js
export class AsyncLock {
    constructor(config) {}
    
	// 等待锁被释放
    async wait() {}
	
	// 等待锁被释放并重新占据
    async acquire() {}
	
	// 释放锁并让一个阻塞的函数继续
    release() {}
	
	// 释放锁并让全部阻塞的函数继续
    releaseAll() {}
}
```

因为这并不是什么高深莫测的技术，所以我判断这在大模型的能力边界中，把上述需求输入大模型，并输入上面这个模板代码，大模型就能补全剩下的部分。

---

## 完整代码

经过测试的完整代码如下：

```javascript
export class AsyncLock {
    constructor(config) {

        const {
            lock = false
        } = config || {};

        this._locked = lock;
        this._waitingResolvers = [];
    }
    
    async wait() {
        if (this._locked) {
            // 如果被锁，则等待锁释放
            await new Promise(resolve => {
                this._waitingResolvers.push(resolve);
            });
        }
    }

    async acquire() {
        if (!this._locked) {
            // 如果没有被锁，直接锁上并返回
            this._locked = true;
            return;
        }

        // 否则等待前一个锁释放
        await new Promise(resolve => {
            this._waitingResolvers.push(resolve);
        });

        // 被唤醒后自动加锁
        this._locked = true;
    }

    release() {
        if (!this._locked) {
            throw new Error("Cannot release an unlocked lock");
        }

        if (this._waitingResolvers.length > 0) {
            // 唤醒下一个等待者
            const nextResolve = this._waitingResolvers.shift();
            nextResolve();
        } else {
            // 无等待者，释放锁
            this._locked = false;
        }
    }

    releaseAll() {
        if (!this._locked) {
            throw new Error("Cannot releaseAll an unlocked lock");
        }

        this._locked = false;
        this._waitingResolvers.forEach((resolve) => resolve());
        this._waitingResolvers = [];
    }
}
```

通过上述使用，就能完美解决这个问题了。
