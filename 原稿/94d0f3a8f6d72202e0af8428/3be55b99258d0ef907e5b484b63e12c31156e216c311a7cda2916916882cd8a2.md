## 前言

最近打算将我的机器人TIP从家里的服务器搬到树莓派上，也是翻出了好久没用的树莓派。带往学校宿舍的时候遇到了一个小的问题——如何用我的笔记本来直接访问树莓派？毕竟我手头并没有micro usb到htmi的转接线也没有一块闲置的屏幕，所以必须得通过ssh的方法才能访问和操作树莓派。这不巧我翻到了之前的笔记找到了对应的方法：[如何优雅入门树莓派.md](https://kirigaya.cn/blog/article?seq=241)

目前最适合我的方法那就是通过以太网线和以太网线转type c接口直接将笔记本和树莓派连接起来。这样笔记本就可以通过mdns广播的域名来直接访问树莓派了。但是这样做有一个很大的问题——这样形成的网络连接并不稳定，很快会断开，此时就必须得重新插拔网口，所以非常麻烦。

好吧，好吧，我得承认这个问题在当年我就遇到了，但是当时为了完成课程作业就没有管那么多。现在“故友”重逢，我必须得立刻根本的解决这个问题，那么应该怎么办呢?

## 解决方案，直接写死 IP

说实话我专精的领域主要在于应用层和人工智能，对于网络接口的了解程度没有那么深刻。所以我想到的一个方法也很笨，那就是直接将双方的网络ip固定。也就是当前的这个被识别为网卡的usb接口以及树莓派的以太网接口，直接将这两个接口在网络层面的ip直接写死反正也只是本地的ip不用管那么多，后续笔记本访问树莓派就不通过mdns广播的本地域名了，而是通过事先写死的ip来完成访问。我简单尝试一下发现确实可以这样做，所以简单记录一下吧，顺便打一个备忘录防止以后我再访问的时候忘记了当前写死的ip，访问方式：

```bash
ssh kirigaya@192.168.10.1
```

## 操作日志

修改树莓派 eth0 的IP

```bash
# 这里的 "有线连接 1" 必须和你之前 nmcli 查到的一致
sudo nmcli connection modify "有线连接 1" \
    ipv4.addresses 192.168.10.1/24 \
    ipv4.method manual \
    ipv4.gateway "" \
    ipv4.dns ""
sudo nmcli connection up "有线连接 1"
```

修改笔记本的被识别为网口的typec接口的IP： win + R -> ncpa.cpl -> 选择对应的以太网 -> 属性 -> 双击 Internet 协议版本 4 (TCP/IPv4)

选择“使用下面的 IP 地址”：

* **IP 地址**: `192.168.10.2`

* **子网掩码**: `255.255.255.0`

* **默认网关**: **留空**（千万不要填，否则笔记本会试图通过树莓派上网而导致笔记本断网）。

你问我没有mdns广播的域名必须得敲ip不觉得麻烦吗，抱歉孩子，我可是使用了命令行自动补全的：[我的windows terminal美化方案（oh-my-posh3）](https://kirigaya.cn/blog/article?seq=52)
