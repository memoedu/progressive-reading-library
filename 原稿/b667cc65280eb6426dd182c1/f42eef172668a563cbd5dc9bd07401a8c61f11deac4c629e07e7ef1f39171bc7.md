这确实是一个非常简单的例子，我们先定义变量，然后分别赋值，最后计算一个表达式，哪怕你没学过编程语言，靠一些初中高中知识，上面的源代码也不难看懂。

但我们抓住核心问题：编译器的目的是为了让机器执行我们的源码，但一般来说，现代的计算机系统的是严格按照[ISA](https://zhida.zhihu.com/search?content_id=786168553&content_type=Answer&match_order=1&q=ISA&zhida_source=entity)（指令集架构）来完成的，或者你可以简单把它理解成[汇编语言](https://zhida.zhihu.com/search?content_id=786168553&content_type=Answer&match_order=1&q=%E6%B1%87%E7%BC%96%E8%AF%AD%E8%A8%80&zhida_source=entity)（汇编中大多数指令和其编译的结果是一 一对应的），但是，汇编并不支持a=b+c\*d这种表达式，甚至可以说它不认识a，b，c，d，**变量只是上层的某种抽象表达形式，大多数时候，它最终需要映射到内存空间里，才能用它完成存储和运算操作。**

所以我们一步一步来

![动图封面](https://pic1.zhimg.com/50/v2-dfafa64e06b215677829916d1fae43a2_720w.jpg?source=2c26e567)

我们先给变量映射到内存空间（如上如所示），当编译器扫描完变量定义的时候，我们就能获得一些变量的初步信息，例如变量的类型，变量的名字（助记符），通过变量的类型，我们可以知道变量的大小，因此我们就可以在内存中划出一片区域给这个变量。

例如a，b都是int类型的变量，这里它们是32位也就是4字节的，因为都是全局变量，所以你可以看到它们的scope是global，最后我们把a分配在偏移量为0的位置，b偏移量为4的位置，通过这个操作，变量就映射到了内存空间。

那么，第二个问题又来了，我们如何给它赋值呢，就像代码中的

```text
a=1;
b=2;
c=3;
```

实际上赋值语句也是一个非常基础的表达式类型，如果有一些初学汇编经验的同学可能想到了mov语句，但是多数isa中mov语句并不能直接给内存数据赋值

因此我们也迎来了我们第一个**“如何把源码信息转换为机器能够理解的形式”**或者我们换一种说法”如何用汇编（IR）来实现和源码同样的语义呢“

![动图封面](https://pic1.zhimg.com/50/v2-079697264f2a4099fb15b1b636f2668d_720w.jpg?source=2c26e567)

我们继续看软件分析，首先

mov r0,1 表示先把寄存器r0设置为值1，然后我们在利用一个store32指令，这个指令能够将一个寄存器的值保存在一个内存区域中，而gp+0(全局变量偏移为0），恰好就是变量a的地址，所以，我们把b=1这个语句，成功翻译成了内存模型中的等价汇编语句。

那么现在，你已经学会了编译器中最基础也是重要的两个概念

1.  如何把数据映射到内存
2.  如何把源码中的数学表达式等价”翻译“成汇编指令。

是时候玩一点进阶的内容了。

```text
a=b+c*d
```

如何翻译成汇编呢，其实这个很简单，如果你会写汇编，你可能已经有了方案了，比如先把b，c，d加载到内存，然后分别完成一次乘法一次加法，最后store到a的内存空间。

这里真正的难点在于，虽然写源码很简单，写汇编也简单，但是我们需要一个确定的算法，来吧这个表达式完成机械等价的翻译，而不是靠人脑完成代码的重构。

不卖关子，我们继续看图

![动图封面](https://picx.zhimg.com/50/v2-c6e29f0881cf465a0a6501a273db9c33_720w.jpg?source=2c26e567)

动画有点长，这也是一个稍微有一点复杂的分析结构，首先，表达式中的a，b，c，d都是变量，或者现在我们换种叫法，把它叫做操作数（operand），而=+\*这三个运算符我们叫做操作码（[opcode](https://zhida.zhihu.com/search?content_id=786168553&content_type=Answer&match_order=1&q=opcode&zhida_source=entity)），很好理解，操作码就像函数，操作数就像函数的参数，生成汇编的过程，就是这个函数的执行过程。

然后怎么解释呢？

1.  首先这是一个表达式，所以我们先压入一个expr\_begin的特殊opcode
2.  然后我们碰到了a，这是一个操作码，你可以在动画里看到那个index：3的operand，这就是a
3.  然后压入一个=号操作码，因为=号操作码需要至少两个操作数才能工作，所以我们继续。
4.  压入操作数b，现在=号的操作数数量够了，但是这个时候我们可以进行=号赋值操作了么？不行，我们得再看下一个操作码，**因为=号的运算优先级很低**
5.  然后我们碰到了+号运算符，果然它的运算优先级比=号更高，但是我们还是不能进行+号运算，因为后面还可能有更高优先级的运算符。
6.  压入操作数c
7.  碰到\*号运算符了，果然，它的优先级比+更高，还是不能计算，继续看。
8.  表达式结束，压入expr\_end，这是一个一个表达式最低优先级运算符，那么，现在我们可以按从高到低的顺序进行计算了。

因此，表达式可以等价为（temp表示临时变量）

```text
temp=c*d;
temp=b+temp;
a=temp;
```

你看，整个大表达式被拆分成了小表达式，现在我们就可以轻松等价的写出汇编代码了。

但在最后一步，我还是故意不小心给大家埋了一个小坑。

你看，源码中c是一个整数，d却是一个浮点数，那么，如果我们把它进行相乘，那么就是一个源码中的类型信息，如何转换成汇编中的表达信息了。

因为通用寄存器无法直接处理浮点运算，所以，这里我们需要用到一个FPU来辅助计算（如下图，先加载c，d到寄存器，转换c为浮点，最后进行浮点乘法）

![](https://pic1.zhimg.com/50/v2-a8c6d9cebd1e26f7484ddf4b26a57557_720w.jpg?source=2c26e567)

因为一个类型是浮点类型所以后续类型都应该是浮点运算，而最后的赋值类型是整数类型，因此，最后还需要一个转换，把浮点转换成整数类型
