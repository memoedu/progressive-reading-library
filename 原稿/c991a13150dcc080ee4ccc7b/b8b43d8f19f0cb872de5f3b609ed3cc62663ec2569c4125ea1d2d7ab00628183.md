我学编译原理之前经常会猜编译器的行为，觉得这么写可能会慢、那么写可能会慢，然后自以为是地“优化”代码。实际上具体什么地方快、什么地方慢是个非常非常非常复杂的问题，尤其是在有虚拟机环境下，很难猜到运行时优化的具体行为。不要凭借直觉去乱优化代码就是我从编译原理课上学到的最有价值的事情。CPU 缓存、自动向量化对性能影响非常大，这些才是我应该去针对性优化的地方，而非热点代码其实应该以可读性为主，这样对于维护而言才是经济的。

比如我最近才知道 C# 的 `Sse.isSupported` 是 JIT 时期的常量， 所以我们如果在一些非常密集的地方写 `if Sse.isSupported { f_sse() } else { f() }` 几乎不会在运行时有任何 branching 开销，因为这个判断在运行时会被替换成对应硬件架构的函数。说“几乎”是因为在 JIT 之前可能还会 if 几次。这些事情如果我没有事先的知识，我可能就会认为这是在热点代码干蠢事，然后搞一些奇奇怪怪的方法去“优化”之，最后适得其反。甚至我可能还会听信一些谣言，说什么 native 编译会比 JIT 编译快，这种话你要是信了，上面那代码你就 native 编译去吧。了解虚拟机技术的优势之后，才能有自己的判断。谣言止于智者。

这类知识正是应该在高校学习的，在我看来属于编程基础知识（而非应用知识），离现实编程是很近的。尤其是现在 vibe coding 这么厉害，人类更应该学会把握编程中的重点、难点，而不是琐碎的细节。
