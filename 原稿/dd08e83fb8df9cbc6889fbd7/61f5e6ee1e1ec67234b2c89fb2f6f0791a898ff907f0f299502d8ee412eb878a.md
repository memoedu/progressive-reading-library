## 基本打包流程

一个完整的`vscode`插件项目，内部的代码和资源大致可以分为：

- node_modules（`nodejs`第三方库）
- src（工程源代码）
- 插件配置文件（package.json，jsconfig.json等）
- 静态资源（图片，字体，webview的HTML项目等）
- 其他（比如脚本文件，测试文件）

## step 1. webpack

webpack的目的是将一个项目的所有的JavaScript代码全部融合到一个JavaScript文件中，并对代码做一些等价变换，从而达到项目瘦身，或者降低可读性（有时候你并不希望用户偷看你的实现逻辑）。

webpack打包一般基于`webpack.config.js`进行工作，这个文件需要被安放在项目的根目录上。一般一个标准的`webpack.config.js`如下：

```javascript
const path = require('path');

const config = {
    target: 'node',
    entry: './out-js/extension.js',
    output: {
        path: path.resolve(__dirname, 'out'),
        filename: 'extension.js',
        libraryTarget: 'commonjs2',
        devtoolModuleFilenameTemplate: '../[resource-path]',
    },
    externals: {
        vscode: 'commonjs vscode'
    },
    resolve: {
        extensions: ['.ts', '.js'],
    },
};

module.exports = (env, argv) => {
    if (argv.mode === 'development') {
        config.devtool = 'source-map';
    }
    return config;
};
```

上述的几个重要参数如下：

- entry：需要打包的JavaScript项目的入口文件。因为我是基于Typescript开发的，TSC编译之后的文件夹被我定义为`out-js`，所以我的入口文件就是`out-js/extension.js`。
- output -> path：输出的打包内容的文件夹，这里是`out`，意味着打包之后的文件会被放在`out`文件夹中。
- output -> filename：打包之后的文件名。webpack默认情况下把entry的文件所构建出的依赖树（只要是存在require或者ES6的import，就说明存在依赖）上的所有文件全部整合到一个文件中，并做一些等价变换。这个最终的一个文件名就是通过这个参数定义的。

运行如下命令即可根据`webpack.config.js`执行对应的打包命令：

```bash
webpack --mode production
```

很明显，最终打包的结果就是一个Javascript文件，这个文件包含了所有的项目代码、node_modules代码。需要注意的是，如果项目中通过路径的方式引入了静态资源，比如：

```javascript
const lib = fs.readFileSync("./resources/lib.wasm");
```

webpack不会负责变换这个静态资源的路径，它会选择让这个路径保持不动。因此，最好写个脚本来让自己处理对应静态资源的摆放，你只需要知道所有的发起资源请求的文件都只有打包完后的那个`extension.js`，相对路径只需要相对于这个文件来就行。

## step 2. vsce

vsce是一款vscode扩展的打包工具，用于装载打包整个vscode项目，读者需要注意它和webpack的区别，两者是平行的关系。webpack用于将JavaScript项目的所有js文件整合进一个JS文件中并进行压缩；而vsce则是将一个vscode扩展的所有运行时文件压缩成一个安装包文件。

运行如下命令即可进行vsce打包：

```bash
vsce package
```

这个命令默认会将当前目录下所有的文件都塞到一个文件夹里面，并且将这个文件夹进行zip压缩得到最终的`<extension>-<version>.vsix`，这是一个vscode的扩展安装包，可以直接双击然后安装。

很明显，并不是所有扩展开发时的文件和资源都需要打包。比如测试文件，脚本文件，Docker等等都是不需要放到最后的安装包里面的，而且如果你使用了webpack进行了压缩，那么`node_modules`和扩展源代码所在的文件夹`src`，通常也是不需要打包进安装包的。为了删除那些不必要的，vsce提供了一个叫做`.vscodeignore`的文件，这个文件中支持glob路径，可以用于指明哪些文件不需要被打包进安装包。比如针对上面所说的情况，可以这么写：

```
src/**
node_modules/**
.git/**
.gitignore
webpack.config.js
README.md
```

上面所指的都是只在开发中才要用到的，所以忽略。
