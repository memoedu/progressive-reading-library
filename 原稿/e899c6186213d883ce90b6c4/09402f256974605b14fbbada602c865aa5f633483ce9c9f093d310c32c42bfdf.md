## webgl2 是 canvas 的一个渲染上下文

webgl2 并不是 ES 系列的一个库或者全局对象，而是 canvas 的一个上下文。当我们创建一个 canvas 对象后，为了在上面画东西，我们需要指定使用什么后端来进行画画。比如常用的上下文有如下几个：

```js
const canvas = document.querySelector('...'); // 根据某个规则找到某一个 canvas

const ctx2d = canvas.getContext('2d');
const ctxwebgl = canvas.getContext('webgl');
const ctxwebgl = canvas.getContext('webgl2');
```

简单介绍一下它们的不同：

- `2d`：这是调用 **浏览器自己的图形渲染引擎**（如 Firefox 的 Gecko，旧版 Safari 和 Chrome 的 WebKit ，新版的 Chrome 的 Blink） 来作为 canvas 图形绘制的后端，它遵循一套与 svg 绘制类似的 API。
- `webgl`：基于 OpenGL ES 2.0 标准实现的3D绘图协议，可以直接调用 **操作系统的图形驱动**（如 Windows 的 DirectX，Linux 的 OpenGL） 执行图形的光栅化。webgl 始于 2007 年的 Firefox，如今已被所有主流浏览器支持。
- `webgl2`：基于 OpenGL ES 3.0 标准实现的3D绘图协议，相比于 webgl 第一代，webgl2 在性能上有极大的提升，并且引入了一些额外的，数据结构上的优化，而且完全兼容 webgl 的语法。webgl2 始于 2017 年的 Chrome，如今已被所有主流浏览器支持。

简答说就是， 2d 上下文还依赖浏览器的渲染引擎，但是 webgl 系列的上下文可以直接绕过浏览器的限制，去访问图形驱动层的API。所以在性能上，webgl 自然占有优势。

讲到这里，有一些比较喜欢追逐时尚的年轻人就会说了：我们那么大一个 WebGPU 呢？别急，别急，我正准备讲呢。

<img src="https://pica.zhimg.com/80/v2-386765f375c0fef8cbb1847462acfd82_1440w.png"/>
</div>

web 端除了利用 canvas 调用底层图形 API 绘制图形外，最近还多出了一个新的方法——WebGPU，它是 2023年4月6号由 Google 发布的新一代高性能 3D 计算与并行计算标准。虽然发布时间只有一年，但是目前主流浏览器的最新版本也都支持。与 WebGL 相比，WebGPU 的 API 使用更加简单，但是目前还在开发中，仍然会存在一些问题：

- 生态不完整：网上的相关资料也不是很多，而且相关 API 在极端条件下会出现 bug。
- 兼容性问题大：WebGPU 需要最新版本的浏览器才能使用（**Chrome 113 Beta 以上**），兼容性问题比较大。

所以对于小白而言，不是很推荐直接上手 WebGPU。而且现在主流技术仍然是 WebGL，和 WebGPU 相比，其中的一些基础概念都是类似的。学完 WebGL 后，再去学 WebGPU 会比直接上手 WebGPU 更快。

## 第一个 WebGL2 程序

### step.1 创建着色器程序

接下来，我们进入正题，开始编写第一个 webgl2 程序，我们先打开 index.html ，写入如下内容：

```html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Document</title>
</head>
<body>
    <canvas id="canvas" height="500", width="500"></canvas>
</body>
</html>

<script src="./main.js"></script>

<style>
    body {
        background-color: var(--vscode-editor-background);
    }
    #canvas {
        top: 20px;
        position: absolute;
    }
</style>
```

`--vscode-editor-background` 是 vscode 的一个全局 CSS 宏，这样可以让渲染效果更加贴合你的 vscode 主题。

我们接下来可以把重心放在 `main.js` 上了。

> 不推荐直接在 html 中打 js 的原因我在上一章简单提到了，因为 html 内嵌 js 的自动补全等功能不如 js 文件下的强大。

在 `main.js` 中，我们先创建主函数，并获取 canvas，创建 webgl2 上下文：

```js
window.onload = async () => {
    const canvas = document.getElementById('canvas');
    const gl = canvas.getContext('webgl2');

    if (!(gl instanceof WebGL2RenderingContext)) {
        console.log('浏览器不支持 webgl2');
        return;
    }
    
    
}
```

这里对于不熟悉 naive html 编程的同学简单说一下， 可以认为 `window.onload` 就是 html 的入口文件，相当于 C 语言 和 Go 语言中的 main 函数。我们后续提到的“主函数”就是 `window.onload` 中的剩下的部分。

webgl 的执行需要依赖“着色器程序”（shader program），着色器程序中需要定义着色器，而着色器对象需要通过 glsl 代码生成，整个过程如下图所示：

<div align=center>
<img src="https://pic1.zhimg.com/80/v2-84bb498a4154c6c92eb2143639b43b44_1440w.png" style="max-width: 80%"/>
</div>

从上图中可以看到，我们接下来需要先编写顶点着色器和片元着色器， glsl 的语法与 C 基本是一致的。

`vertex.shader.glsl` 如下：

```glsl
#version 300 es
in vec4 a_position;
void main() {
    gl_Position = a_position;
}
```

- 第一行指定version 为 ES 3.0，代表使用 webgl2 的语法。
- 第二行申明了一个输入变量 `a_position`，后续我们会通过缓冲区给这个值赋值，这个值默为（0, 0, 0, 1），代表三维齐次坐标系的原点。
- `gl_Position` 是内置变量，代表顶点着色器的返回值，此处是一个4维向量，代表 (x, y, z, w)。(x, y, z) 代表点的坐标，如果不去管 z ，那么这个坐标就是一个二维坐标。 w 是用于空间变换的齐次坐标。
- 需要说明的是，`gl_Position` 每一个维度必须是 -1 到 1 的浮点数，也被称为裁剪空间或者透视空间。后续会通过 `gl.viewport` 将这个裁剪空间的坐标映射到 canvas 对应的真实的，以像素为单位的坐标系。

`fragment.shader.glsl` 如下：

```glsl
#version 300 es
precision mediump float;
out vec4 outColor;
void main(){
    outColor = vec4(0.4, 0.0, 1.0, 1.0);
}
```

不同于 webgl，webgl2 的片元着色器的输出变量需要自己指定了（之前是 `gl_FragColor` ），此处是 `outColor`，也是一个4维向量，代表 rgba，取值范围为0-1. 我们为了方便，此处输出固定值 `rgba(0.4, 0.0, 1.0, 1.0)` 代表紫色。

然后，我们在主函数中读取这两个文件：

```js
/**
 * 
 * @param {string} path
 * @return {string} 
 */
async function getSource(path) {
    const response = await fetch(path);
    const source = await response.text();
    return source;
}

window.onload = async() => {
    ...
	const vertexSource = await getSource('./vertex.shader.glsl');
    const fragementSource = await getSource('./fragment.shader.glsl');
}

```

接下来编写着色器创建程序，这一步非常固定简单，按部就班即可：

```js
/**
 * @description 创建着色器对象
 * @param {WebGL2RenderingContext} gl 
 * @param {'VERTEX_SHADER' | 'FRAGMENT_SHADER'} type 
 * @param {string} source
 * @return { WebGLShader | undefined }
 */
function makeShader(gl, type, source) {
    // 创建 shader
    const shader = gl.createShader(gl[type]);
    // 给 shader 提供 glsl 代码
    gl.shaderSource(shader, source);
    // 编译 glsl 生成 shader
    gl.compileShader(shader);
    const ok = gl.getShaderParameter(shader, gl.COMPILE_STATUS)
    // 如果成功，则返回 shader，否则返回 undefined
    return ok ? shader : gl.deleteShader(shader);
}

window.onload = async() => {
    ...
    const vertexShader = makeShader(gl, 'VERTEX_SHADER', vertexSource);
    const fragmentShader = makeShader(gl, 'FRAGMENT_SHADER', fragementSource);
    if (!vertexShader || !fragmentShader) {
        console.log('着色器创建失败');
        return;
    }
}
```

根据之前的流程图，在着色器创建完成后，就应该创建着色器程序了。过程也非常固定，代码如下：

```js
/**
 * @description 创建着色器
 * @param {WebGL2RenderingContext} gl 
 * @param {WebGLShader} vertexShader 
 * @param {WebGLShader} fragmentShader 
 * @return { WebGLProgram | undefined }
 */
function createProgram(gl, vertexShader, fragmentShader) {
    // 创建着色程序
    const program = gl.createProgram();
    // 加载着色器到着色程序
    gl.attachShader(program, vertexShader);
    gl.attachShader(program, fragmentShader);
    // 连接着色程序
    gl.linkProgram(program);
    const ok = gl.getProgramParameter(program, gl.LINK_STATUS);

    return ok ? program : gl.deleteProgram(program);
}


window.onload = async() => {
    ...
    const program = createProgram(gl, vertexShader, fragmentShader);
    if (!program) {
        console.log('着色程序创建失败');
        return;
    }
}
```

以上的步骤完全固定，我们一般都会把它封装成一个易用的函数。后续的教程会省略上面的步骤，假设着色程序已经创建完成。

### step.2 缓冲区

创建完成着色器程序后，就需要往 webgl 传递数据然后绘制了。

在绘制之前，需要介绍一个概念，也就是缓冲区，有多媒体底层组件开发经验的同学对于缓冲区应该不陌生，因为软件层面发号施令与底层硬件执行操作不可能完全同步，所以需要缓冲区暂存和中转应用层发送给硬件设施的数据。webgl 中也是一样，我们无法直接在 js 层将绘图数据传递给着色器，而需要通过缓冲区。

比如我们在之前的例子中创建了两个着色器，其中顶点着色器有输入数据 `a_position`，是一个四维变量。我们就需要在 js 层将数据传递给它。

第一步，我们先获取 `a_position` 的位置，用 C 语言的话来说，就是先获得 `a_position` 的指针。

```js
window.onload = async () => {
    ...
    const webglLocations = {
        a_position: undefined
    }
    // 获取顶点着色器变量 “a_position” 的位置
    webglLocations.a_position = gl.getAttribLocation(program, 'a_position');
}
```

接下来，我们先构造一组数据，用于绘制一个三角形，三个点的坐标分别为（0，0），（0，0.7），（0.7，0），请注意，坐标需要是裁剪空间内的，也就是取值范围为（-1，1）. 而且在 js 层创建的数组一定需要是类型确定的数组，比如 Float32Array：

```js
window.onload = async () => {
    ...
    const positions = new Float32Array([
        0  , 0,
        0  , 0.7,
        0.7, 0
    ]);
}
```

接下来，我们创建缓冲区，并且将 它 设置成全局缓冲区 `gl.ARRAY_BUFFER`：

```js
window.onload = async () => {
    ...
    // 为 a_position 创建缓冲区
    const buffer = gl.createBuffer();
    // 将 buffer 绑定到 webgl 全局绑定点 ARRAY_BUFFER 上面
    gl.bindBuffer(gl.ARRAY_BUFFER, buffer);
}
```

绑定完成后，绑定点 `gl.ARRAY_BUFFER` 现在就存在一个可以使用的缓冲区了，我们将之前在 js 层创建的 Float32Array 装载进这个缓冲区：

```js
window.onload = async () => {
    ...
    // 通过 全局绑定点 ARRAY_BUFFER 向 buffer 内传递数据
    gl.bufferData(gl.ARRAY_BUFFER, positions, gl.STATIC_DRAW);
}
```

在正式绘制前，我们再简单设置一下画布：

```js
window.onload = async() => {
    ...
    
    // 将 webgl 裁剪空间的 (-1, 1) 映射到 canvas 画布的 x 轴的 (0, width) 和 y 轴的 (0, height)
    gl.viewport(0, 0, gl.canvas.width, gl.canvas.height);

    // 使用 rgba(0, 0, 0, 0) 清空画布
    gl.clearColor(0, 0, 0, 0);
    gl.clear(gl.COLOR_BUFFER_BIT);
}
```

### step.3 数组绘制

开始启动之前创建的着色程序上下文进行绘制，先开启着色程序和之前选定的着色器变量 `a_position`：

```js
window.onload = async() => {
    ...
    // 加载运行之前的着色程序
    gl.useProgram(program);

    // 启用属性 a_position
    gl.enableVertexAttribArray(webglLocations.a_position);
}
```

在执行绘图API之前，有一个非常重要的步骤，那就是配置 webgl 如何从缓冲区读取我之前装载的 Float32Array，因为 webgl 提供的绘图 API `gl.drawArrays` 执行逻辑是，在每一个输入变量绑定的缓冲区的某个地方放置一个指针，在画图程序开始执行时，所有指针根据之前的配置并行地移动读取数值，交给对应的着色器变量，然后着色器根据当前这一次迭代指针返回的值计算出对应的顶点和片元，合成出最终的像素。而这个指针从哪个位置开始移动，每次迭代怎么移动，每次迭代读多少东西都是用户需要配置的。一个大体的 drawArrays 如何从缓冲区中读取数据并交付给着色器如下图所示，需要说明，这并不是实际的执行过程，但是逻辑上是符合的，为了便于初学者理解，我绘制了这张图：

<div align=center>
<img src="https://pic1.zhimg.com/80/v2-abdae957160ee6fd12b369e743454910_1440w.png" style="max-width: 80%"/>
</div>

上图中的 offset， size 等参数都是需要用户配置的，正是因为这些参数的存在，我们在使用 webgl 传递数据时可以更加地高效、灵活、可掌控。

这个例子中，我们因为使用的点都是二维坐标，所以每次都只取两个数字，所以 `size=2`；一开始是从头开始读，所以 `offset=0`；读取是连续，不需要跳跃，所以 `stride=0`；并且按照32位浮点数进行读取交给 `a_position`，所以 `type=gl.FLOAT`，代码如下：

```js
window.onload = async() => {
    ...
    // 配置 a_position 这个属性如何从 buffer 中读取数据
    gl.vertexAttribPointer(
        webglLocations.a_position, 
        2,               // size: 每次迭代运行提取两个单位数据
        gl.FLOAT,        // type: 每个单位的数据类型是32位浮点型
        false,           // normalize: 不需要归一化数据
        0,               // stride: 每次迭代运行运动多少内存到下一个数据开始点
        0                // offset: 从缓冲第0号位置（也就是开头）开始读取
    );
}
```

这样，第 `t` 次迭代，`a_position` 拿到的数据就是之前那个 Float32Array 的 2t 和 2t + 1 这两个位置上的数字，并且会赋值给 `a_position` 的 x 和 y，z 和 w 则采用默认值 0 和 1.

这下，我们可以调用 `drawArrays` 进行绘制了，因为我们要绘制三个点，所以 `count=3`；因为是绘制三角形，所以创建完三个点后使用 `gl.TRIANGLES` 作为图元构造片元形态，代码如下：

```js
window.onload = async() => {
    ...
    // 运行 glsl 着色程序
    gl.drawArrays(
        gl.TRIANGLES,   // mode: 图元类型
        0,              // first: 也就是 offset
        3               // count: 迭代 3 次，因为我们之前设置 positions 是 一个 3 * 2 的
                        // 之前的迭代设置 size = 2，迭代次数自然是 3 了
    );
}
```
