## 前言

git 的登陆算是一个非常常见的问题了，过去好多年，我都是稀里糊涂的配置过去的，最近开始和好哥们一起共用我们自己私有的 git 了，开始简单记录一下如何在新的环境配置你的开发环境，来快速免密地把代码推送到目标远程仓库。

---

## git 的验证方式

当你把代码推送到远端时，有两种验证方式：

- ssh：根据你事先配置的 ssh 公钥来判断你是否是本人
- https：需要你输入账号和密码（github 目前输入的并不是密码，而是 token）

通过 git remote -v 你可以看到你的 origin 使用的是 https 还是 git。此处我们只讨论 https。

---

## 从零配置免密 git 推送

### 1. 配置 ssh 公钥

打开你需要推送代码的PC或者服务器，创建公钥（如果没有的话）

```bash
ssh-keygen -t rsa
```

先通过你使用的远程仓库的设置内的 ssh 公钥

此时你应该可以推送你本地的代码了，但是需要输入账号和密码。

### 2. 安装 gcm

为了免密，我们需要安装 gcm(git-credential-manager, github 官方推荐的 https 认证账号管理器)

```bash
mkdir -p ~/package/gcm-linux && cd ~/package/gcm-linux
wget -c https://github.com/git-ecosystem/git-credential-manager/releases/download/v2.6.1/gcm-linux_amd64.2.6.1.tar.gz
tar -xvf gcm-linux_amd64.2.6.1.tar.gz
```

让 Git 使用 GCM 管理凭据（全局生效）：

```bash
./git-credential-manager configure
git config --global credential.credentialStore cache
```

此时，你的 ~/.gitconfig 应该如下：

```bash
[credential]
        helper = 
        helper = /home/kirigaya/package/gcm-linux/git-credential-manager
        credentialStore = cache
[credential "https://dev.azure.com"]
        useHttpPath = true
```

### 3. 设置目标仓库网站的登录账号密码

设置一下你之前需要输入的账号密码

```bash
git-credential-manager store <<< "protocol=https
host=目标仓库网站域名，比如 github
username=账号
password=密码"
```

敲入回车，就 ok 了！此时你再次输入 git push origin main 就不会需要你输入账号密码了。

:::info
如果是在 Windows 或者 macOS 上，那么 gcm 会以图形界面的方式出现，配置起来更加方便。
:::
