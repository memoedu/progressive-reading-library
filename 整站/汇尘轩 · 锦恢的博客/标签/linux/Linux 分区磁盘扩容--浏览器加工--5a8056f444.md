## 给服务器加了几块新的硬盘

如你所示，最近我的物理服务器加了几块硬盘来作为我的个人 NAS 使用。不同于一般的 NAS，我的 服务器 不仅需要作为文件服务器和git服务器使用，内部还需要安装一些数据库，所以做成了一个稍微大一点样子。

之前部署的文件服务器左下角的容量太小了，所以我加了几块硬盘。无论是 Windows 还是 Linux，操作系统显示的可用空间都不是你插几块硬盘上去就能自动扩容的。这篇文章简单记录一下如何在你的服务器上插了新的硬盘后，给主分区扩容。Linux 提供了很方便的磁盘扩容工具，让我们不需要重启计算机就能轻松完成扩容。

---

## 调整磁盘大小的基本步骤

我们可以先查看一下当前服务器的磁盘使用情况：

```bash
df -hl
```

输出：

```
Filesystem                         Size  Used Avail Use% Mounted on
tmpfs                              2.8G  1.5M  2.8G   1% /run
/dev/mapper/ubuntu--vg-ubuntu--lv  914G   57G  819G   7% /
tmpfs                               14G     0   14G   0% /dev/shm
tmpfs                              5.0M     0  5.0M   0% /run/lock
/dev/sdd2                          2.0G  448M  1.4G  25% /boot
/dev/sdd1                          1.1G  6.1M  1.1G   1% /boot/efi
tmpfs                              2.8G  8.0K  2.8G   1% /run/user/1000
```

我现在只关心根目录下的空间大小，看到挂载点 `/` 那行的信息，可以看到当前逻辑卷的大小为 914G，属于名为`ubuntu-vg`的卷组（Volume Group），并且卷名为`ubuntu-lv`。为了将当前 `~` 下的空间进行扩容，我们需要把新买的硬盘划进这个卷组中。

在 Linux 中，为了扩大一个分区的大小，一般的步骤为：

```mermaid
graph LR
a(创建物理卷) --> b(使用该物理卷扩展卷组) --> c(100%扩容逻辑卷) --> d(调整逻辑卷)
```

---

## 创建物理卷

为了将磁盘合并入逻辑分区，需要先创建物理卷，我们先查看当前系统的物理磁盘情况：

```bash
lsblk -a
```

输出：

```
NAME                      MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
loop0                       7:0    0  63.9M  1 loop /snap/core20/2318
loop1                       7:1    0  74.2M  1 loop /snap/core22/1380

loop3                       7:3    0 130.1M  1 loop /snap/docker/2915
loop4                       7:4    0    87M  1 loop /snap/lxd/28373
loop5                       7:5    0    87M  1 loop /snap/lxd/29351
loop6                       7:6    0  40.4M  1 loop /snap/snapd/20671
loop7                       7:7    0  38.8M  1 loop /snap/snapd/21759
loop8                       7:8    0     0B  0 loop
sda                         8:0    0 476.9G  0 disk
sdb                         8:16   0 119.2G  0 disk

```

只有满足如下两个条件的磁盘才可以合并进入 `ubuntu--vg` 卷组中：

1. 没有挂载点，也就是 `MOUNTPOINTS` 为空
2. 没有被进行分区，也就它没有子节点

上述满足这两个条件的只有 sda 和 sde 这两个磁盘，它们正好也是我新插上去的两块硬盘。此处我就先以 sde 为例子演示一下，sda 只需要把本文步骤重复一遍即可。

创建物理卷的步骤如下：

```bash
sudo pvcreate /dev/sde
```

输出：

```
  Physical volume "/dev/sde" successfully created.
```

这说明 sde 的物理卷创建完成了。

---

## 扩充卷组 ubuntu-vg

然后我们把抽象好的物理卷合并进入根目录所在的卷组 `ubuntu-vg`：

```bash
sudo vgextend ubuntu-vg /dev/sde
```

输出：

```
  Volume group "ubuntu-vg" successfully extended
```

---

## 扩容逻辑卷

`ubuntu-vg` 得到扩充后，我们把 `ubuntu-vg` 内的 `ubuntu-lv` 逻辑卷直接 100% 扩充即可

```bash
sudo lvextend -l +100%FREE /dev/ubuntu-vg/ubuntu-lv
```

输出：

```
  Size of logical volume ubuntu-vg/ubuntu-lv changed from <928.46 GiB (237685 extents) to 1.37 TiB (359781 extents).
  Logical volume ubuntu-vg/ubuntu-lv successfully resized.
```

这说明 `ubuntu-vg` 中的所有空间都划分给了 `ubuntu-lv`。

---

## 调整逻辑卷

上述的步骤只是在逻辑上把逻辑卷进行了扩充，为了让根目录真的有这么大，我们还需要调整逻辑卷。

```bash
sudo resize2fs /dev/mapper/ubuntu--vg-ubuntu--lv
```

输出：

```
resize2fs 1.46.5 (30-Dec-2021)
Filesystem at /dev/mapper/ubuntu--vg-ubuntu--lv is mounted on /; on-line resizing required
old_desc_blocks = 117, new_desc_blocks = 176
The filesystem on /dev/mapper/ubuntu--vg-ubuntu--lv is now 368415744 (4k) blocks long.
```

最终，我们再查看一下根目录的磁盘空间：

```bash
df -hl
```

输出：

````
Filesystem                         Size  Used Avail Use% Mounted on
tmpfs                              2.8G  1.5M  2.8G   1% /run
/dev/mapper/ubuntu--vg-ubuntu--lv  1.4T   57G  1.3T   5% /
tmpfs                               14G     0   14G   0% /dev/shm
tmpfs                              5.0M     0  5.0M   0% /run/lock
/dev/sdd2                          2.0G  448M  1.4G  25% /boot
/dev/sdd1                          1.1G  6.1M  1.1G   1% /boot/efi
tmpfs                              2.8G  8.0K  2.8G   1% /run/user/1000
````

可以看到，已经涨到 1.4T 了，重复上述的步骤，我们可以把所有的新硬盘都划入到根目录下。
