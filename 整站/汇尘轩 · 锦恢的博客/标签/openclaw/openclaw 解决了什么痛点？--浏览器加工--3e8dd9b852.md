## T1. 产品上的痛点：大模型缺少一个亲民的入口

大模型虽然风风火火地发展了好多年，但是对于大部分的普通老百姓来说，他们一直没有找到日常生活中什么地方能够用到大模型。也正因如此，开发圈和外界对于大模型出现了极大的认知偏差，开发圈都知道如何使用大模型来提高自己的工作和生活效率，但是外界的人更多只是看到大量的资本涌入，知道这个行业现在很火，有些人甚至将大模型称之为泡沫。这也体现出了很多外界的人士，其实对于大模型的具体使用和它的能力并没有一个直观的了解，因为他们生活中根本就用不到这个东西。openclaw 就像一座桥梁，它硬生生地将大模型的服务，和所有人都能使用到的 IM 软件给绑在了一起。两个世界的间隔在逐渐消失，你懂吗？

当然了，这么多天对于 openclaw 的营销，其实也有其他的一些人在背后推波助澜，主要的动力就是芯片厂商和云服务厂商。芯片厂商需要借助 openclaw 所代表的 AI 叙事来提升自己的股价，而云服务厂商则需要通过 openclaw 来清理自己的库存。其实你们可以看到 openclaw 爆火几天之后，阿里云上的低价云服务器，就被一抢而空了，而网络上不少吹捧 openclaw 的写手，其实也是这些厂商雇的枪手。

## T2. 技术上的痛点：IM 机器人缺少一个统一的架构和生态

其实 IM 机器人的开发从很多年前就开始了，因为很多朋友都需要有一个智能助手，我们通过聊天框的形式就可以向他传递一些信息，它也能帮我们处理一些杂活。我们日常能够使用到的这些通信软件本身就是最佳的入口，因为我们习惯通过这些通信软件来表达我们的观点和指令，我们通过这些通信软件来收发消息的交互成本也是最低的。

但是常年以来，各个平台都缺少一个统一的机器人架构，WhatsApp，QQ，Discord，Slack，飞书这些平台真正好用的机器人往往都是针对于平台特性定制化开发的，这些机器人本身不能从一个社交平台迁移到另一个社交平台。导致每一个机器人的生态都是固定在社交平台上的。比如说 QQ 机器人的一些组件就不能移动到飞书机器人上。这种长期的割裂开发，使得整个机器人的生态一直不能很好地兼容开来，并且也使得整个机器人的部署与开发成本居高不下，甚至很多人都不知道，这些社交平台上有对应的一些热门机器人框架和对应的社区。openclaw 是这么多年以来，我第一次见到有人尝试在技术层面将所有这些社区全部统一在一起，从 Agent 层面，只提供最基本的发送消息与接收消息的事件函数，就能让大模型完全接管整个通信软件的基础使用，然后，额外的一些平台相关的特殊功能就通过 skill 的方法来注入，这种方法极大地降低了不同平台之间的迁移成本，使得不同的通信软件平台使用统一的机器人架构成为了可能，就变成了如今你能看到的这副样子，你长期迭代好的 openclaw，只需要配置一下 channel，就可以立刻从 QQ 迁移到飞书，几乎不存在任何迁移成本，这件事情在 openclaw 出来之前是几乎想象不出来的。其背后是大模型能力的增强，和 Anthropic 这家公司所提出来的 skill 与 MCP 这些 Agent 架构技巧所带来的可能性。
