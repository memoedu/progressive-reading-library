## 前言

最近在开发一个新的 MFM 的意图识别工具，从而完成我的助手机器人的拒答流模块的开发。其中我抽象出了一个名为“意图节点”的数据结构，它是一种类似于树节点的数据结构，使用 python 申明 schema 时如下：

```python
@dataclass(frozen=True)
class IntentNode:
    name: str
    children: IntentNode
```

其中 `IntentNode` 做了一次递归申明。然而，我在运行时，解释器居然报错了：

```
NameError: name 'IntentNode' is not defined
```

啊？class 难道不是 runtime 解析吗，怎么现在连编译字节码前处理都没编译通过？

我急忙看了一下 PEP 563 标准中关于延迟解析的说明：

> **Postponed** evaluation of annotations.

对呀，type 的延迟解析不是支持的吗？



## 解决方法 annotations

不解，遂 google 一番，StackOverflow 上有老哥给出了回答：

>  it was announced to be default in 3.10 (when python3.7 was released), but it was now moved to a later release
> 回答链接：[from __future__ import annotations](https://stackoverflow.com/questions/61544854/from-future-import-annotations)

啊？居然到 python 3.10 都不支持延迟解析吗？我刚刚运行的环境就是 python 3.10，然而，老哥给出了解决方法，只需要在开头添加一行：

```python
from __future__ import annotations
```

这样下面的嵌套申明就不会报错了：

```python
class A:
    def f(self) -> A:
        pass
```



## 解释一下

所以为什么上面这样话是有用的呢？ `from __future__ import annotations` 这句话在低版本的 python 中是用于支持类型注释的，比如：

```python
def f(a: int) -> int:
    ...
```

这个代码在低版本的 python 中会报错，此时引入 `annotations` 会让解释器支持类型标注；而在我的问题中，3.10 的 python 类型标注是支持了，看起来可以不用 import annotations 了，但是 3.10 还不支持 类型标注中 postponed annotations feature，也就是说，3.7 到 3.10 这个区间内的 python 对类型标注属于是支持了，但没有完全支持。
