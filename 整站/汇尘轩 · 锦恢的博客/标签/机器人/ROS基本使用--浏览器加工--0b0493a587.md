# 环境安装

我强烈建议你在Ubuntu18.04环境下安装ROS。如果你是Windows用户，那么安装ROS有两个选择：

1. 使用ROS的Windows移植版本，我曾经写过非常详细的系列教程[如何优雅地在windows上玩ROS（一个紧致的解决方案） - 知乎 (zhihu.com)](https://zhuanlan.zhihu.com/p/414874250)。但是这个版本的使用体验不如Ubuntu下的，嗯，各种层面的使用体验。
2. 使用WSL2或者其他的虚拟机软件应用来安装Ubuntu，然后下载ROS。我本人使用的WSL2，体验极佳。

ROS的不同的版本号是对于不同的Ubuntu发行版来说的，比如18.04是对应`ros-melodic-desktop`，而20.04则是对于`ros-noetic-desktop`。除此之外，直接根据网络上的教程添加软件源，然后apt安装即可。基本没有什么坑，记得apt install的时候加上--fix-missing即可。

安装完后每次激活ROS环境需要`source /opt/ros/melodic/setup.bash`，这个地方注意两点：

1. 很多教程会让你将这个命令加入`.bashrc`中，这样下次启动就不需要输入了，这个记得加。
2. 如果你使用了别的shell，请使用其他的setup脚本。比如我用的是ZSH的shell，那么激活环境的脚本就是`setup.zsh`，然后将`source /opt/ros/melodic/setup.zsh`加入`.zshrc`中。

# 项目结构

好久不用真的容易忘记ROS的项目结构，不过也很简单。

## 创建工作环境

一般而言，一堆的包都是针对于某个工作环境而言的。首先，我们需要创建工作环境。

```bash
mkdir ws
cd ws
mkdir src
cd src
```

然后进行初始化：

```bash
catkin_init_workspace
```

然后会生成一个用于编译src下所有功能包的CMakeLists.txt文件，这个文件其实是一个链接文件。然后我们回到根目录，先试着编译一次：

```bash
cd ..
catkin_make
```

这个时候你会发现多了build和devel两个文件夹，看名字基本就知道是干什么的。build用于存储构建好的成本，devel里面存储着一些开发和调试时需要用到的东西。

需要注意，如果你希望你可以在全局都能通过包名来访问其中的软件功能，那么请使用`source devel/setup.bash`（如果是zsh的话，那就是`setup.zsh`）。否则后续的roslaunch, rosrun指令是找不到对应的包的。

可以看到每个文件夹都是一个功能包，那么下载下来后，这些功能包应该放在哪里呢？

**答：放在工作目录的src文件夹下。**

当你把这些文件夹下载下来后，放在src文件夹下后，下一步就是回到上一层目录运行`catkin_make`了。

当你编译别人的包时，很可能会在编译过程中报错，大概率是因为你没有下载别人用的包，请根据报错提示去网上查缺了哪一个包，然后通过`apt`进行安装。比如上面的项目，就需要额外安装一个用于导航的ROS包：

```bash
sudo apt install ros-melodic-navigation
```

然后就可以编译了。

在编译后，不要忘了`source devel/setup.bash`
