## 前言

很多时候，我们希望篡改浏览器的行为，比如修改某个网站对我们的 IP 位置（为了隐私），但是修改前端的内部函数困难重重，因为这些关键函数可能会在启动器里面被展示，但是这不代表它们可以被我们 get 或者 set。这个时候，拦截请求和响应参数并进行修改同样也能达到目的，而且简单得多。

浏览器上目前常见的请求类型一共三种：XHR（也就是 ajax 请求），Fetch API，script 注入请求。针对这些不同类型的网络请求的拦截器方案各不相同。

所有可能的浏览器请求发起方案在 [MDN 文档中](https://developer.mozilla.org/en-US/docs/Web/API/PerformanceResourceTiming/initiatorType) 有所提及。倘若未来有的网站的请求能够逃脱我下文方法的拦截，请前往上述链接查看更多的请求方式。

### 拦截原理

基本原理很简单，前端所有的网络请求底层都是依赖 `window.XMLHttpRequest` 这个类的，我们只需要覆写掉这个类即可。主要实现两个函数：

- `send`：发送请求。
- `open`：接受请求。

使用 `window.prompt` 来展示需要修改的参数并让用户提供修改结果。

需要注意的一点是，在部分浏览器中 `XMLHttpRequest` 用于存储响应数据的属性 `responseText` 是只读的，所以我们需要在继承 `XMLHttpRequest` 的子类中额外创建一个新的可读可写的 `responseText` 来覆盖原本的，并通过修改子类的 `responseText` 的方式让 `open` 方法将修改后的结果返回给其他函数。


```js

    constructor(...args) {
        super(...args);
    }

    send() {
        const body = arguments[0];
        console.log(body);
        if (body) {
            // 询问用户并修改请求
            // const userArgString = window.prompt('修改请求参数', body);
            // if (userArgString) {
            //     return super.send(userArgString);
            // }
        }
        return super.send(...arguments);
    }


    open() {
        const method = arguments[0];
        const url = arguments[1];

        let localOnreadystatechange = this.onreadystatechange;
        Object.defineProperty(this, 'onreadystatechange', {
            set(v) {
                localOnreadystatechange = v;
            }
        });

        super.onreadystatechange = () => {
            if (this.status == 200) {
                const text = super.responseText;
                console.log(super.responseText);
                // 询问用户并修改响应
                // if (text) {
                //     const userResponse = window.prompt('修改返回值', text);
                //     this.responseText = userResponse ? userResponse : super.responseText;
                // } else {
                //     this.responseText = super.responseText;
                // }
            }
            if (localOnreadystatechange) {
                localOnreadystatechange();
            }
        }
        return super.open(...arguments);
    }
}
```

使用时，先在我们有权限的区域注册它，以油猴脚本为例：

```js
(function() {
    'use strict';

    // 注册拦截器
    window.XMLHttpRequest = CustomHttpRequest;
})();
```

然后根据规则，修改注释的两个地方即可。

## Fetch

### 介绍

大部分静态资源的请求都是基于 Fetch 请求发出的，当然，也可以用它去请求业务数据。比如B站上的视频组件，按钮的svg，图标等等都是基于 Fetch 发起的。大部分情况下，拦截这些东西意义不大。

### 介绍


相比于 XHR，Fetch 更加现代，由于是函数，所以可以直接修改，此时使用如下的代码即可拦截：

```js
const { fetch: originalFetch } = window;

window.fetch = async (...args) => {
    let [resource, config ] = args;
    // 拦截请求 -> 修改 resource
    const response = await originalFetch(resource, config);
    // 拦截响应 -> 修改 response
    return response;
};
```

## JSONP

JSONP，也就是 script 注入请求。这类请求非常特殊，开发者通过创建 `script` 标签，把需要 GET 请求的链接放入 script 的 src 中，再将 script 挂载进入 body 来发起请求。这么做的好处就是可以免配置直接发起跨域请求。比如，腾讯文档的打卡定位功能就是基于这个方法获取 script 返回的值：

### 基本原理

当返回结果后，浏览器会自动执行 script 内部的代码。我们需要知道一点，当浏览器获取 script 标签返回的结果后，会将返回结果直接扔给 V8 当成 js 代码运行，所以直接返回 json 数据是不行的。为了将返回的数据赋值给当前引擎的某个变量上，我们一般是实现定义好一个函数，比如叫 `receiveData`，把这个方法挂载到 `window` 对象上，使其可以被全局访问，然后后端返回的数据为：

```js
receiveData({
    code: 200,
    data: {}
})
```

这样，当浏览器获取了 script 的返回值后，就会执行上面这段代码，将真正的结果返回给内部变量。


当用户点击了定位按钮后，前端会将当前经纬度发给后端，后端返回了上图右侧的js代码，这段代码执行了 `jsonCb_1710158180434` 这个函数，将具体的地理位置信息返回给客户端。

当然，你也可以将数据赋值给某个全局变量，比如：

```js
window.scriptData = {
    code: 200,
    data: {}
}
```

这样，后续代码访问 `scriptData` 也行，只不过，通过回调函数的方法更加方便设计后续的响应函数。

基于这种方法的拦截只需要直接在 load 事件触发之前，覆盖这个接受函数或者接受变量的 getter 。注入请求往往是一些重要的服务类型的请求，拦截它们存在一定难度，但是往往值得这么做。
